# 12 反馈任务幂等与逐项执行规格

日期：2026-10-13。状态：**设计提议，待独立 review；未实施、未验收**。上游：11 §2/3.1/7 的 C 阶段、04 S-05～S-12、09 G05。本文只定义反馈闭环，不扩大至自主模型写工具、投诉自动处理或全部 22 工具。

## 1. 现状与目标

`feedbackflow.go` 已通过受信任务执行配置和记忆，支持父 trace 与提交后缓存刷新失败；仍存在每次重试生成新任务、相对减量重算、全局 failed 抹去部分生效事实、扁平动作丢失意图依赖、postpone/boost 绕工具的问题。反馈记录和通知在副作用之后另写 runtime，保存失败可造成实际已生效却显示失败。

Dashboard 已有反馈 Modal、历史和通知；目前无 submission_id、仅展示总状态，HTTP 成功即提示已收到。课堂 REST/WS 已有 event_id/context 防重放，但它们不等于反馈任务幂等；WS feedback_reply 只含 status/reply。`/admin/todos` 已筛选 escalated 历史，并非完全没有升级入口；缺独立持久待办及管理员页面消费，混合失败会使投诉漏出待办。`PostponeLesson` 当前只校验 scheduled，七日范围/冲突需补，不能假定底层已有保障。

目标：一次提交绑定一个冻结任务；各意图独立原子提交；已完成项永不重做；回复、记忆、通知和待办都对应已提交事实；重启后仍可查询、恢复。

## 2. 输入、身份与兼容

- `POST /api/v1/feedbacks` 新增 `submission_id`，保留 `text/channel`。身份仅来自认证；不接受 student/task/owner 任意指定。ID 为 1–128 字节不含控制字符的字符串，现代客户端使用 UUID。文本统一 trim 首尾、CRLF→LF，禁止控制字符，限制 2,000 Unicode 字符；不改内部空白、大小写和标点。禁止静默截断后当成原提交。
- 唯一键 `(student_id, submission_id)`；保存规范化文本及其 SHA-256，冲突检查同时核对文本。channel 不参与身份，同一提交允许 WS→REST 切换。同学生同 ID 异文返回现有响应包装的 `code=409, error_code=submission_conflict`，无副作用；不同学生同 ID 完全隔离。文本/哈希不写日志。
- 增加学生查询 `GET /api/v1/feedbacks/submissions/:submission_id`，仅当前身份空间，未找到返回 404；重复 POST 返回同一 feedback ID/当前结果。处理中返回正常数据 status=processing、retry_after_ms；不能称成功应用。
- 无 ID 的旧请求服务端生成并返回 ID，标记 `idempotency=server_generated`：后续显式携带该 ID 才能幂等。保留 HandleFeedback/HandleFeedbackContext 包装供旧调用，但新 REST/WS 使用返回 error 的提交入口，不能把冲突压成失败反馈并新建记录。
- FeedbackRecord 保留小写 `id/student_id/text/status/intents/reply/created_at`，新增 `submission_id/task_id/results/retryable/updated_at`。旧记录 results 缺失时展示原 reply，不伪造逐项成功。迁移不重新执行历史任务。

## 3. 冻结计划、并发和恢复

持久层新增任务及意图凭证（可独立表；禁止继续整份 feedbackRecs JSON 覆盖）：任务唯一键如上，含稳定 task_id、schema_version、规范化输入、冻结解析/计划、初始时间、version；意图唯一 `(task_id,intent_index)`，保存 kind、依赖动作、冻结目标、结果、attempt_count、完成时间。结果不得只靠内存标志。原始输入用于用户历史及管理员授权查看，不进入审计参数。

1. 短事务创建/读取任务并校验输入；失败时没有业务变更。同一 ID 的并发创建由数据库唯一约束兜底。
2. 事务外 ParseContext(parent, text)，沿用本机模型配置/规则降级；父取消直接返回，不降级后继续写。解析可因竞争重复执行，但不得产生业务副作用，也不得持有 DB 事务或 App/Room 锁等待模型。
3. 短写事务 CAS 安装第一个计划；失败竞争者丢弃自己的解析，读取胜出计划。计划按原意图顺序分组，Agent 输出必须携带 intent_index（不能靠动作类型猜分组）。调用数/参数/未知动作预检先于任何业务写入。
4. 安装计划时读取数据库配置和资源，把相对词量冻结为绝对值（±10，50～100），把相对日期冻结为具体日期/时区，把改期课 ID、难词匹配资源冻结。无资源是一项明确结果，不改找别课/别词。重试不得重新解析、重新选课或再次减量。
5. 每意图一个写事务：重新读完成凭证→校验资源及版本→执行 tx Registry 工具→保存意图实际结果、相关通知/待办、审计及任务汇总→commit。已完成直接返回凭证。并发事务必须先获得 SQLite 写入序列或 CAS 锁定版本，再读写；处理 SQLITE_BUSY 为可重试错误，不能把 DB 读取失败当不存在。进程 mutex 只是优化，不作为重启/多 App 实例保证。
6. 同一学生不同 submission 的相对调整，按计划冻结事务顺序取基线。保存配置基线版本/预期值，执行时已被独立提交修改则该项返回 stale_target，不覆盖新值；要求用户确认当前状态后新提交。一个提交重复修改同一资源应由 Agent 明确顺序与依赖，计划器按虚拟前序结果冻结；含互相矛盾目标则 need_confirm，不任意取最后一项。

正常重复 POST 只查询，不自动再次执行失败项。新增 `POST /api/v1/feedbacks/submissions/:id/retry` 无新文本，只恢复未提交且 retryable 的项；processing 可查询，浏览器不并发重试。网络中断、重启留下 pending 项可以由此恢复，committed 项始终跳过。非法日期/未选词库/越权/stale_target 为终止失败，存储暂不可用/超时为可重试；取消不抹去已提交项。新提交为新的用户意图，不能复用旧 ID 修改文字。

**预算澄清提议，需 review 确认**：冻结计划最多 8 个逻辑工具调用（包含 get/recall/reply），超限整条不写业务；每次执行/恢复 attempt 共用一个最多 8 次的 Registry context，不按意图重建预算。已完成项不再调用工具，重试沿用同 taskID、另有 attemptID，只执行原计划未完成槽位，禁止加动作。失败尝试保留审计但不永久耗尽任务的恢复资格；此处明确区分逻辑任务预算与一次运行 guard，不通过拆子任务放大额度。

SQLite 为持久恢复保证。内存模式用同样状态机、锁和完成凭证；本段涉及的内存工具必须使用任务私有工作副本并在意图成功后一起发布，不能先改真实服务再以失败记录掩盖部分写入；不承诺内存进程重启恢复。无法提供工作副本时该模式不得宣称逐意图原子验收通过。

## 4. 工具、依赖与真实结果

| 意图 | 同一意图事务内动作 | 结果与失败边界 |
|---|---|---|
| A/B 词量、C 频率 | config.set_student → feedback.reply | 返回持久层实际值；刷新应用缓存在 commit 后，失败仍为已应用 refresh_pending，仅重试刷新 |
| D 请假改期 | scheduler.postpone_lesson → memory.append → feedback.reply | 课、占位卡、请假记忆、通知/结果/审计同事务；任一步失败均回滚此意图 |
| E 难词 | scheduler.boost_word → feedback.reply | 已选且发布词库中全部确定匹配项同事务；返回实际 book/word IDs 与数量；任何保存错误不得部分标记成功 |
| F 投诉 | feedback.escalate → feedback.reply | 创建真实管理员待办和通知后才返回 escalated |
| G 不明确/需确认 | feedback.reply | clarify/need_confirm 不执行学习修改；后续用户确认是新提交，不自动执行旧提案 |

新增 postpone/boost/escalate/reply 均 system/mid，仅 feedback_submitted 受信任务；严格 schema、非空 reason，资源从任务冻结计划派生，兼容 ID 必须完全匹配。注册工厂与持久 tx 服务绑定相同定义，禁止私下直写 App 服务或在 handler 中另开事务。reply 消费执行器的受信结果，不接受模型提交 status=success；确定性话术生成在 Agent/模板层，平台只传事实。未知 action 明确失败，不能 switch 静默遗漏。

改期选择初始最近 scheduled 课，OpenAt 相同按 ID 升序；冻结原时区和同一时段，执行时仍需 scheduled、归属匹配、目标晚于原时刻、目标不超过原提交时刻后七个本地日；重试时目标已过期则失败，不能顺延。与该学生其他有效课程时间冲突明确拒绝（至少 OpenAt 相同；如上游定义时间窗应同步采用同规则）。底层课程写入及 reserveCards 错误传播，查询错误不当无课；取消/禁用/删除后的资源不再操作。

难词沿用 normWord 统一查找，明确传播选库/词条/卡片读取错误；查无记录与存储失败不同。多库命中在一个意图事务执行，不按库独立提交。学过、未学、已 mastered 的标记是否参与后续排课沿用 scheduler 语义，回复只称“已标记加强”，不承诺立即插入当前课堂。

## 5. 逐项状态、通知与管理员待办

results 每项包含 index/kind/status、稳定 result_code、实际值或资源、reply、retryable、refresh_pending；状态为 pending/applied/failed/need_confirm/clarify/escalated。动作成功后派生记忆和成功文案只属于本意图，不能被另一项失败跳过；同意图依赖失败则整组不提交。

总状态为展示投影：有 pending→processing；全部失败→failed；有失败且其他项成功/待确认→partial；无失败但有需确认/澄清→need_confirm/clarify；其余有升级→escalated；全部应用且有缓存待刷新→applied_refresh_pending；否则 applied。**results 是事实源，不能用总状态判断待办是否存在。** reply 按原意图顺序列实际结果，不以统一“未保存”覆盖已经提交的项。

管理员待办独立记录 `task_id/intent_index/student_id/status=open/created_at`，唯一 task+intent。`feedback.escalate` 在同一事务建立待办及面向当前有效管理员的通知；无管理员时失败明确 admin_unavailable，不假称已转交。通知唯一 `(task_id,intent_index,recipient,kind)`，重试不重复。管理员原文阅读需要 admin 鉴权，学生仅见自己的反馈；新增管理员通知只读入口及 Admin 页面待办列表/详情。本轮不加入自动关闭/处理工作流，不宣称投诉已解决。

保留 `/admin/todos` 旧列表基本字段，数据改从独立待办关联任务读取；历史 escalated 记录幂等迁移为待办，标记 legacy，不重新发旧通知。学生反馈处理通知可采用每任务一条、内容随结果版本更新，通知 ID 不变、已读状态不因技术重试复位。所有通知持久失败都参与所属意图事务回滚，不能继续用无错误返回的 Notify 假报完成。

## 6. 前端与课堂双通道

Dashboard 第一次点击发送前冻结 text+UUID，失败/断网保留；编辑已发出的草稿需要生成新 ID。按钮 busy 只改善体验，服务端仍处理并发。按实际 status 显示成功/部分完成/失败，逐项显示实际值、失败原因和“重试未完成项”；processing 有查询，不能永远转圈或盲目重复新提交。当前待恢复 ID 按登录用户隔离保存，退出清理草稿，不把原文长期放 localStorage；再次登录从历史恢复可重试条目。

WS voice_text 和课堂 REST voice 新增 submission_id，保留必需 event_id/context。同一语音事件 WS 失败转 REST 保留两种 ID；新事件仍须校验 turn/epoch。语音反馈正文提取只做一次并回传规范化正文/记录，不能重试时换成包含口令的另一段文本。被 ingress 判为重复/过期时不绕过课堂校验重新跑语音业务，客户端用已知 submission_id 查询反馈；已登记但未完成用 retry 入口恢复。尚未登记时明确“反馈未送达”，经学生确认后通过普通反馈入口提交冻结正文，不能悄悄吞失。

WS feedback_reply 保留 status/reply，增加完整 feedback 记录及 submission_id；REST voice 保留 data.frames/data.feedback。Classroom 共用帧处理器展示逐项摘要，并可跳转历史；event_processed 仅表示课堂路由结束，不能当反馈应用确认。语音 mock E2E 明确标注，不冒充真实 ASR 质量验收。

## 7. 日志、验证矩阵与发布门

日志必须含 request trace_id、稳定 task_id、attempt_id、student_id、intent_index、action/tool、result_code、duration、transaction_outcome；新事件：feedback_task_created/plan_frozen/replayed/conflict、feedback_intent_committed/rolled_back、feedback_retry、feedback_admin_escalated、feedback_refresh_pending。参数仅长度/资源 ID/数值结果；不记原文、模型提示、记忆内容或底层 raw error。审计与副作用同事务；失败尝试事务外摘要落库再次失败须有 audit_persist_failed，不能伪称审计已保存。

| 用例 | Go 单元/真实 SQLite/REST/WS | Playwright 无头真实交互 |
|---|---|---|
| C01 幂等 | 同ID同文串行/并发/跨App仅一副作用；异文409；A/B学生同ID隔离 | 双击提交、拦截响应丢失后恢复查询、刷新/重新登录历史只有一条；双学生互不影响 |
| C02 冻结恢复 | 相对减量保存计划后重启；重复不二次减量；同资源新任务版本冲突不覆盖 | 减量后断网重试，显示同实际值；用户另提交修改后旧失败任务不得回退配置 |
| C03 逐项事务 | 两独立意图一成一败；失败项无记忆/通知；反转顺序仍各自正确 | “减量+不存在难词”显示已改词量及难词失败，不能统一成功/统一未应用 |
| C04 改期 | 七日/过期/冲突/归属；保存课、reserve卡、记忆、审计分别注入失败整项回滚 | 学生通过反馈请假，课表实际日期一致；无课/冲突正确提示；其他学生课表不变 |
| C05 难词 | 多库匹配、非选库、DB读/写失败无部分标记 | 选库→难词反馈→后续课程/报告可见加强结果；不存在词明确失败 |
| C06 投诉 | 混合任务升级仍留待办；待办/通知写失败回滚；幂等重启不双发 | 学生投诉+另一项失败，独立管理员登录在真实页面见一条待办及通知，其他学生看不到 |
| C07 预算/取消 | 未知动作、超8调用预检无业务写入；各意图共享context；解析取消/执行取消/commit后取消 | 多意图超预算展示可操作提示，取消或断线恢复后保留已提交事实 |
| C08 通道兼容 | WS/REST同submission、event重放与feedback结果独立；旧无ID/旧历史 | mock语音反馈→WS断线→REST/历史恢复，收到完整逐项结果而非仅event_processed |
| C09 数据故障 | 提交凭证/汇总/通知/审计失败注入；commit后Cfg.Reload失败显示已保存 | 错误显示与数据库事实一致，刷新恢复不重复调用；真实页面重试未完成项 |

故障 E2E 使用仅测试服务端启用的故障 fixture 或代理丢响应；不得在产品页面增加任意注入接口。Go 覆盖并发/事务语义，浏览器覆盖可见交互，两者不互代。测试子代理后台运行全量 Go（跨包实际profile统计）及 Playwright；核心≥80%、调度/判分/状态机/反馈≥90%。本地无 gcc 时 -race 待 CI，不当已测。
