# 12 反馈任务幂等与逐项执行规格

日期：2026-10-13；验收更新：2026-10-14。状态：**按第8节设计实施，独立代码评审与C阶段专项验收通过，证据见第9节及10当前进度**。上游：11 §2/3.1/7 的 C 阶段、04 S-05～S-12、09 G05。本文只定义反馈闭环，不扩大至自主模型写工具、投诉自动处理或全部 22 工具；真实语音及全项目总验收仍未完成。

## 1. 实施前现状与目标

`feedbackflow.go` 已通过受信任务执行配置和记忆，支持父 trace 与提交后缓存刷新失败；仍存在每次重试生成新任务、相对减量重算、全局 failed 抹去部分生效事实、扁平动作丢失意图依赖、postpone/boost 绕工具的问题。反馈记录和通知在副作用之后另写 runtime，保存失败可造成实际已生效却显示失败。

Dashboard 已有反馈 Modal、历史和通知；目前无 submission_id、仅展示总状态，HTTP 成功即提示已收到。课堂 REST/WS 已有 event_id/context 防重放，但它们不等于反馈任务幂等；WS feedback_reply 只含 status/reply。`/admin/todos` 已筛选 escalated 历史，并非完全没有升级入口；缺独立持久待办及管理员页面消费，混合失败会使投诉漏出待办。`PostponeLesson` 当前只校验 scheduled，七日范围/冲突需补，不能假定底层已有保障。

目标：一次提交绑定一个冻结任务；各意图独立原子提交；已完成项永不重做；回复、记忆、通知和待办都对应已提交事实；重启后仍可查询、恢复。

## 2. 输入、身份与兼容

- `POST /api/v1/feedbacks` 新增 `submission_id`，保留 `text/channel`。身份仅来自认证；不接受 student/task/owner 任意指定。ID 为 1–128 字节不含控制字符的字符串，现代客户端使用 UUID。文本统一 trim 首尾、CRLF→LF，禁止控制字符，限制 2,000 Unicode 字符；不改内部空白、大小写和标点。禁止静默截断后当成原提交。
- 唯一键 `(student_id, submission_id)`；保存规范化文本及其 SHA-256，冲突检查同时核对文本。channel 不参与身份，同一提交允许 WS→REST 切换。同学生同 ID 异文返回现有响应包装的 `code=409, error_code=submission_conflict`，无副作用；不同学生同 ID 完全隔离。文本/哈希不写日志。
- 增加学生查询 `GET /api/v1/feedbacks/submissions/:submission_id`，仅当前身份空间，未找到返回 404；重复 POST 返回同一 feedback ID/当前结果。处理中返回正常数据 status=processing、retry_after_ms；不能称成功应用。
- 无 ID 的旧请求服务端生成并返回 ID，标记 `idempotency=server_generated`：后续显式携带该 ID 才能幂等。保留 HandleFeedback/HandleFeedbackContext 包装供旧调用，但新 REST/WS 使用返回 error 的提交入口，不能把冲突压成失败反馈并新建记录。
- FeedbackRecord 保留小写 `id/student_id/text/status/intents/reply/created_at`，新增 `submission_id/task_id/results/retryable/updated_at`。旧记录 results 缺失时展示原 reply，不伪造逐项成功。迁移不重新执行历史任务。

## 3. 冻结计划、并发和恢复

持久层新增任务及意图凭证（可独立表；禁止继续整份 feedbackRecs JSON 覆盖）：任务唯一键如上，含稳定 task_id、schema_version、规范化输入、冻结解析/计划、初始时间、version；意图唯一 `(task_id,intent_index)`，保存 kind、依赖动作、冻结目标、结果、attempt_count、完成时间。结果不得只靠内存标志。原始输入用于用户历史及管理员授权查看，不进入审计参数。

1. 短事务创建/读取任务并校验输入；失败时没有业务变更。同一 ID 的并发创建由数据库唯一约束兜底。
2. 事务外 ParseContext(parent, text)，沿用本机模型配置/规则降级；父取消直接返回，不降级后继续写。解析可因竞争重复执行，但不得产生业务副作用，也不得持有 DB 事务或 App/Room 锁等待模型。
3. 短写事务 CAS 安装第一个计划；失败竞争者丢弃自己的解析，读取胜出计划。计划按原意图顺序分组，Agent 输出必须携带 intent_index（不能靠动作类型猜分组）。调用数/参数/未知动作预检先于任何业务写入。
4. 安装计划时读取数据库配置和资源，把相对词量冻结为绝对值（±10，50～100），把相对日期冻结为具体日期/时区，把改期课 ID、难词匹配资源冻结。无资源是一项明确结果，不改找别课/别词。重试不得重新解析、重新选课或再次减量。
5. 每意图一个写事务：重新读完成凭证→校验资源及版本→执行 tx Registry 工具→保存意图实际结果、相关通知/待办、审计及任务汇总→commit。已完成直接返回凭证。并发事务必须先获得 SQLite 写入序列或 CAS 锁定版本，再读写；处理 SQLITE_BUSY 为可重试错误，不能把 DB 读取失败当不存在。进程 mutex 只是优化，不作为重启/多 App 实例保证。
6. 同一学生不同 submission 的相对调整，按计划冻结事务顺序取基线。保存配置基线版本/预期值，执行时已被独立提交修改则该项返回 stale_target，不覆盖新值；要求用户确认当前状态后新提交。一个提交重复修改同一资源应由 Agent 明确顺序与依赖，计划器按虚拟前序结果冻结；含互相矛盾目标则 need_confirm，不任意取最后一项。

正常重复 POST 只查询，不自动再次执行失败项。新增 `POST /api/v1/feedbacks/submissions/:id/retry` 无新文本，只恢复未提交且 retryable 的项；processing 可查询，浏览器不并发重试。网络中断、重启留下 pending 项可以由此恢复，committed 项始终跳过。非法日期/未选词库/越权/stale_target 为终止失败，存储暂不可用/超时为可重试；取消不抹去已提交项。新提交为新的用户意图，不能复用旧 ID 修改文字。

**预算澄清提议，需 review 确认**：冻结计划最多 8 个逻辑工具调用（包含 get/recall/reply），超限整条不写业务；每次执行/恢复 attempt 共用一个最多 8 次的 Registry context，不按意图重建预算。已完成项不再调用工具，重试沿用同 taskID、另有 attemptID，只执行原计划未完成槽位，禁止加动作。失败尝试保留审计但不永久耗尽任务的恢复资格；此处明确区分逻辑任务预算与一次运行 guard，不通过拆子任务放大额度。

SQLite 为持久恢复保证。内存模式用同样状态机、锁和完成凭证；本段涉及的内存工具必须使用任务私有工作副本并在意图成功后一起发布，不能先改真实服务再以失败记录掩盖部分写入；不承诺内存进程重启恢复。无法提供工作副本时该模式不得宣称逐意图原子验收通过。

新增 postpone/boost/escalate/reply 均 system/mid，仅 feedback_submitted 受信任务；严格 schema、非空 reason，资源从任务冻结计划派生，兼容 ID 必须完全匹配。注册工厂与持久 tx 服务绑定相同定义，禁止私下直写 App 服务或在 handler 中另开事务。reply 消费执行器的受信结果，不接受模型提交 status=success；确定性话术生成在 Agent/模板层，平台只传事实。未知 action 明确失败，不能 switch 静默遗漏。

改期选择初始最近 scheduled 课，OpenAt 相同按 ID 升序；冻结原时区和同一时段，执行时仍需 scheduled、归属匹配、目标晚于原时刻、目标不超过原提交时刻后七个本地日；重试时目标已过期则失败，不能顺延。与该学生其他有效课程时间冲突明确拒绝（至少 OpenAt 相同；如上游定义时间窗应同步采用同规则）。底层课程写入及 reserveCards 错误传播，查询错误不当无课；取消/禁用/删除后的资源不再操作。

难词沿用 normWord 统一查找，明确传播选库/词条/卡片读取错误；查无记录与存储失败不同。多库命中在一个意图事务执行，不按库独立提交。学过、未学、已 mastered 的标记是否参与后续排课沿用 scheduler 语义，回复只称“已标记加强”，不承诺立即插入当前课堂。

## 5. 逐项状态、通知与管理员待办

results 每项包含 index/kind/status、稳定 result_code、实际值或资源、reply、retryable、refresh_pending；状态为 pending/applied/failed/need_confirm/clarify/escalated。动作成功后派生记忆和成功文案只属于本意图，不能被另一项失败跳过；同意图依赖失败则整组不提交。

总状态为展示投影：有 pending→processing；全部失败→failed；有失败且其他项成功/待确认→partial；无失败但有需确认/澄清→need_confirm/clarify；其余有升级→escalated；全部应用且有缓存待刷新→applied_refresh_pending；否则 applied。**results 是事实源，不能用总状态判断待办是否存在。** reply 按原意图顺序列实际结果，不以统一“未保存”覆盖已经提交的项。

管理员待办独立记录 `task_id/intent_index/student_id/status=open/created_at`，唯一 task+intent。`feedback.escalate` 在同一事务建立待办及面向当前有效管理员的通知；无管理员时失败明确 admin_unavailable，不假称已转交。通知唯一 `(task_id,intent_index,recipient,kind)`，重试不重复。管理员原文阅读需要 admin 鉴权，学生仅见自己的反馈；新增管理员通知只读入口及 Admin 页面待办列表/详情。本轮不加入自动关闭/处理工作流，不宣称投诉已解决。

保留 `/admin/todos` 旧列表基本字段，数据改从独立待办关联任务读取；历史 escalated 记录幂等迁移为待办，标记 legacy，不重新发旧通知。学生反馈处理通知可采用每任务一条、内容随结果版本更新，通知 ID 不变、已读状态不因技术重试复位。所有通知持久失败都参与所属意图事务回滚，不能继续用无错误返回的 Notify 假报完成。

## 6. 前端与课堂双通道

Dashboard 第一次点击发送前冻结 text+UUID，失败/断网保留；编辑已发出的草稿需要生成新 ID。按钮 busy 只改善体验，服务端仍处理并发。按实际 status 显示成功/部分完成/失败，逐项显示实际值、失败原因和“重试未完成项”；processing 有查询，不能永远转圈或盲目重复新提交。当前待恢复 ID 按登录用户隔离保存，退出清理草稿，不把原文长期放 localStorage；再次登录从历史恢复可重试条目。

WS voice_text 和课堂 REST voice 新增 submission_id，保留必需 event_id/context。同一语音事件 WS 失败转 REST 保留两种 ID；新事件仍须校验 turn/epoch。语音反馈正文提取只做一次并回传规范化正文/记录，不能重试时换成包含口令的另一段文本。被 ingress 判为重复/过期时不绕过课堂校验重新跑语音业务，客户端用已知 submission_id 查询反馈；已登记但未完成用 retry 入口恢复。尚未登记时明确“反馈未送达”，经学生确认后通过普通反馈入口提交冻结正文，不能悄悄吞失。

WS feedback_reply 保留 status/reply，增加完整 feedback 记录及 submission_id；REST voice 保留 data.frames/data.feedback。Classroom 共用帧处理器展示逐项摘要，并可跳转历史；event_processed 仅表示课堂路由结束，不能当反馈应用确认。语音 mock E2E 明确标注，不冒充真实 ASR 质量验收。

## 7. 日志、验证矩阵与发布门

日志必须含 request trace_id、稳定 task_id、attempt_id、student_id、intent_index、action/tool、result_code、duration、transaction_outcome；新事件：feedback_task_created/plan_frozen/replayed/conflict、feedback_intent_committed/rolled_back、feedback_retry、feedback_admin_escalated、feedback_refresh_pending。参数仅长度/资源 ID/数值结果；不记原文、模型提示、记忆内容或底层 raw error。审计与副作用同事务；失败尝试事务外摘要落库再次失败须有 audit_persist_failed，不能伪称审计已保存。

故障 E2E 使用仅测试服务端启用的故障 fixture 或代理丢响应；不得在产品页面增加任意注入接口。Go 覆盖并发/事务语义，浏览器覆盖可见交互，两者不互代。测试子代理后台运行全量 Go（跨包实际profile统计）及 Playwright；核心≥80%、调度/判分/状态机/反馈≥90%。本地无 gcc 时 -race 待 CI，不当已测。

## 8. 实施前复核决议（2026-10-13）

基线为本地提交 `fcf5cc8`。主代理根据agent_gap_design架构复核、design_arch_review前端/协议复核及baseline_tests测试/安全交叉复核批准下列实施合同；本节覆盖前文存在歧义的约定。测试复核者曾参与初稿，明确不冒称独立作者外审。问题须由新增回归锁定后才能验收。

### 8.1 输入与结果合同

- submission_id收窄为 `[A-Za-z0-9_-]{1,128}`，UUID兼容，拒绝路径分隔符/百分号/控制字符。无ID旧提交生成唯一的 `tr-*` ID并返回server_generated。channel支持page/voice，缺省page；不参与输入身份。
- JSON请求最大16KiB，正文必须合法UTF-8，CRLF转LF、trim边界、内部空白/标点不变，最多2000 Unicode字符；保留LF和TAB，拒绝其他控制字符。不再使用200字节sanitizeText处理反馈。反馈口令仅剥离原文前缀，不对正文做语音指令归一化。
- Go接口冻结为SubmitFeedback(ctx,sid,FeedbackSubmission)、FeedbackSubmissionByID(ctx,sid,id)、RetryFeedbackSubmission(ctx,sid,id)，均返回(*FeedbackRecord,error)；FeedbacksContext用于能传播错误的历史查询。保留旧包装但不再执行旧旁路流程。
- FeedbackRecord增加version、submission_id、task_id、results、retryable、refresh_pending、updated_at、idempotency、retry_after_ms和error_code。results为空也返回[]；每项index/kind/status/result_code/reply/retryable/refresh_pending/actual（实际配置数值或资源对象）。前端按submission_id+version合并，不让迟到低版本结果覆盖新值。
- FeedbackSubmissionError包含Code/ErrorCode/Retryable/SubmissionID；HTTP保留现有code/data/message包装，增加error_code及可用submission_id，不能把冲突包装成新反馈。404/409/400有稳定分类，存储故障503。普通重复POST只查询；未安装计划的取消/中断任务可显式retry首次安装，不能永久processing。
- 管理待办列表采用id/task_id/intent_index/student_id/status/text/reply/created_at/legacy；id为独立待办ID，reply为任务实际结果摘要，不能当作“投诉已解决”。新增GET /admin/todos/:id详情和GET /admin/notifications。原文只向本人及管理员提供。

### 8.2 冻结计划与事务

Parser新增ParseContextAt(ctx,text,createdAt)，取消返回错误且不降级继续写；规则/模型/边界Plan均使用同一CreatedAt日期锚。同类型不同目标意图不得合并；仅语义等价意图去重。Agent动作携带IntentIndex，平台不靠动作kind反推分组；矛盾配置意图返回need_confirm，同资源顺序依赖显式记录。

持久任务、意图凭证、待办和通知分表。每个SQLite写工作单元第一条SQL取得任务写锁（更新version），再读取完成凭证和资源；不得只用进程mutex作为跨App幂等保障。解析在事务和业务锁之外，安装计划采用CAS。失败结果另事务写入前再次检查已有成功凭证，记录失败本身失败则返回storage_unavailable并保留可恢复pending事实。

配置全局/个人写入及删除均推进持久单调revision；冻结值同时冻结相关revision，防止60→70→60的ABA覆盖。全局默认与学生覆盖的版本均校验，已独立修改则stale_target，不重算相对目标。每attempt共用8调用，冻结逻辑计划也最多8调用；重试仅执行原未完成槽位，多库boost是单工具原子处理冻结集合。

显式依赖项继承前置项的恢复能力：前置pending或暂时失败且retryable时，后项为可恢复dependency_failed；前置stale_target等终止失败、need_confirm或clarify时，后项终止失败并保存完成凭证，不展示永久无效的恢复入口。已applied前置项不阻止后项执行。持久计划依赖索引必须指向此前项，schema版本或索引损坏须在整条任务业务执行前拒绝。

投诉意图事务成功提交后，额外记录 `feedback_admin_escalated`，含父trace、task/attempt/intent、学生ID、工具摘要与committed结果；回滚不得产生该成功事件，重复提交及已完成项恢复不得重复发出。日志不含原文或管理员个人信息。

内存模式采用持锁私有副本，固定顺序agentWriteMu→App.mu→Config原锁→Scheduler原MemRepo锁→Memory原MemRepo锁。克隆、回调与发布全程持有原底层锁，阻止其他入口并发写入后被旧副本覆盖；私有scheduler只绑定私有config，禁用或缓冲外部回调。深复制slice/map/时间指针；所有可能失败工作在最内层完成，返回路径仅执行不失败赋值并发布任务/通知。非原生内存repo或带自定义persister且不能保证原子性的组合，写前明确拒绝，不虚称事务支持。此保证不承诺跨多次独立GET的一致读快照。

每个意图事务前重新验证学生仍有效、资源仍归属并可用；已禁用账户的旧JWT不能提交/查询/重试。管理员收件人只取当前有效管理员。commit后刷新失败仍保留applied；query/retry可尝试恢复缓存，禁止再执行已提交工具。

### 8.3 语音双通道与前端恢复

REST/WS处理语音时直接取得本事件冻结的反馈正文，不在释放Room锁后从共享FeedbackCh取另一事件数据。event_rejected回显event_id/submission_id；有效反馈响应携带submission_id和完整FeedbackRecord，独立于课堂帧seq/turn显示。event_processed只表示课堂路由完成，不代表反馈已应用。

Dashboard保留UUID直到明确收到任务结果，响应丢失后优先query；编辑为新提交时换UUID。只缓存按登录身份隔离的pending ID，不持久保存原文；历史/刷新/重登可恢复。processing查询有60秒上限及手动查询入口，绝不自动POST重跑；仅明确retryable项提供恢复按钮。Classroom反馈消息同样按submission/version处理，迟到反馈不得驱动课堂相位或播放。

### 8.4 必测缺陷矩阵

跨两个SQLite连接/App的重复并发与异文409；create后/parse取消/plan安装前后/第一意图提交后重启；各存储写点及审计故障整意图回滚；ABA与同资源依赖；禁用旧token；日期锚、七日/冲突/过期；跨库难词第二写失败；两语音并发不串单及超过200字节正文；partial含投诉仍有唯一管理员待办；旧记录迁移不重新发通知；超预算/未知schema写前拒绝；内存并发设置/结课不被副本覆盖；真实trace及日志不含原文。Go事务证据和浏览器用户路径分别记录，不能相互替代。

### 实施复核补充：身份、日期与恢复展示

- 频率按完整数量解析，支持每天/一天/一日加显式次数；一/二/两及阿拉伯1/2可进入既有配置边界，其余数量须确认，缺失或不能可靠解释则澄清，禁止默认成1。数字12不能因含2而变成2，三遍不能漏掉超界。模型候选同样对照原文：明确超界、矛盾或与原文明示次数不符时要求确认，不因模型把4解释成1而执行。单位限次/遍/节，分钟不视作课程次数。

- 持久模式鉴权以当前DB身份为准，已删除/停用账号不可凭缓存与旧token继续访问。首次启动在事务写锁内加载账户、补齐缺失Agent服务账号并持久化，重启与双App启动保持服务账号ID稳定；加载失败中止启动，不能当成空库。
- 非法月日不使用time.Date的自动进位；明确给出无效/多义日期的请假必须确认，不能降级为默认明天。字面“投诉”优先识别为转交，不擅自把投诉正文中的“词太多”变成调量。
- Dashboard已选择词库的课表在反馈版本/状态变化后自动刷新，包含提交、查询和显式恢复；旧选择或旧登录会话的异步响应不可覆盖当前页。
- 前端正在处理状态的查询遇临时网络失败仍可在60秒窗口继续；超时转人工查询。确定未受理的400清理pending提示，409查询原任务并保留冲突提示。页面不把内部枚举作为主要用户解释。

### 可复用实现准则

1. GORM复合主键允许0索引时，显式按完整键UPSERT，避免Save把合法零值判断为新纪录；必须以第一项index=0的真实SQLite回归锁定。
2. 版本与逐项结果必须在同一读事务取得；否则旧版本可能携带新结果，使客户端乱序保护失效。
3. 异步任务上下文绑定真正生命周期：WS升级请求结束不等于连接任务取消；用户取消解析又不能变成规则兜底写入。
4. 确认提交、业务成功、缓存刷新是不同事实；提交后刷新失败只恢复缓存，不能重做学习调整。
5. 故障注入必须落在待验证层：鉴权已经拒绝的请求，不能拿来声称测试了业务存储故障日志。
6. 会话切换同时清页面状态和拒绝旧响应：路由重建负责草稿/详情，API在异步解码后再次比较token；静态弹窗须另行清理，旧401不能清掉新登录。
7. 数量解析先取得完整表达再判断边界，禁止用包含某个数字来推断次数；原文安全校验同时作用于规则和模型候选。补负向歧义测试时保留独立词量/时长的正向用例，避免过度拦截。
8. 并发正确性测试保留真实竞争；需要稳定覆盖克隆/回滚时，另以预置记录断言副本指针、集合和序列不污染原状态，不靠重复运行等待某种调度顺序。

### 8.5 浏览器恢复矩阵与边界

专项入口为 `web/playwright.feedback.config.ts`，独立临时 SQLite 与无头 Chromium，覆盖 Dashboard、Classroom、Admin 及两个学生隔离。`feedback-regression.spec.js` 包含：长语音原文及丢失 WS 回复查询恢复；未送达确认重提与旧版本拒绝；processing 查询首次网络失败后继续轮询；POST 响应丢失及双击幂等、重登历史；partial 已完成项及学生隔离；投诉待办与通知唯一；数据库意图故障后的未完成项重试；400 清理待确认标记及 failed 空回复文案；409 展示原任务；非法明确日期需确认且课表不变。

浏览器语音识别和朗读为确定性 mock，课堂 WS 与持久 API 为真实服务。未送达/迟到版本及 HTTP 丢包、400/409、processing 中间态使用显式协议故障夹具，不作为真实模型质量证据。数据库故障由测试进程直接在隔离 SQLite 建立并清理 trigger，产品无故障注入接口。后台查询只 GET，最多 60 秒；短暂失败会继续排程，超时保留手动入口。异步响应以会话 generation 守卫，退出或换账号后不得继续发送旧正文。

补充三项：已选词库在普通提交、查询恢复、显式重试后自动刷新实际日期，另一学生课表不变；五个不同难词意图超过共享预算时以中文提示拆开提交且卡片/配置不变；跨标签页切换账号清理原课堂连接、朗读/识别、未送达草稿，旧回执不能写入新身份。日期用例同时覆盖不存在的日期和多个备选日期。

会话复核增补：Dashboard旧通知/选课/草稿及静态确认清理；Settings切换学生重读；同账号新token拒绝迟到旧401但当前401仍退出；管理员新会话关闭旧详情。持久计划依赖夹具覆盖前项stale_target导致后项dependency_failed终止、无永久恢复按钮。原文“每天一次”必须识别为频率1；“每天4次/10次/12次/三遍”必须确认且学习资源不变，不能截取数字中的1或静默降为1。专项共18条，Go与浏览器断言映射见03 §9 FB-C11～C14。

会话隔离以 userId+token 为边界。课堂连接回调验证创建连接时的身份与实时 token；换身份关闭旧连接并重新执行归属校验，旧 ASR 回调不再转交正文。反馈状态和查询生命周期亦随 token 更新失效。

会话同类复核补充：路由子树在 userId 或 token 变化时重建，统一清理 Dashboard、Admin、Settings 的草稿、选中项及异步生命周期；React key 仅为内部身份标识，不输出到 DOM 或日志。REST 客户端在解析回复后核对请求时 token 与当前 token，旧会话回复（含401）不应用、不清理新登录；当前会话401仍正常退出。正常登录先收到响应再保存新token，不受此守卫影响。已发出的写请求可能已在旧身份下提交，本措施只隔离前端结果，不声称撤销后端事实。静态确认弹窗的迟到操作须另校验页面生命周期。

测试结果须以本轮生成的 JSON 报告登记，本节用例清单本身不代表已通过。既有 closure、firstuse 默认朗读与 playback 自定义朗读三组继续纳入回归，反馈结果帧不得改变课堂相位、seq 或播放队列。正式配置可用 `E2E_SERVER_BINARY` 指定预先构建的服务二进制（默认仍 `go run ./cmd/server`）；前端始终由配置执行构建后 preview，不提交本机路径 runner。
