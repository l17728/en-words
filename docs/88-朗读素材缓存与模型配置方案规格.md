# 朗读素材缓存与模型配置方案

## 目标

课程中的同一词条在不同学生、不同课次重复使用时，复用已经验收过的音频，降低首音延迟和模型并发压力。模型服务的选择由管理员配置，不再由业务代码固定模型名称。

## 设计

- `speech_assets` 以语言、朗读文本、服务 ID、模型名、规则版本计算缓存键；音频原子写入 `server/data/cache/tts/`，SQLite 保存文件路径、内容哈希、大小、状态和最后使用时间。
- 课程合成命中数据库和文件即直接返回；同一缓存键使用进程内互斥锁合并并发生成。模型或朗读规则变更会自然产生新键；管理员可按词条和语言强制刷新。
- `model_profiles` 保存文本、ASR、中文 TTS、英文 TTS 四个角色的服务 ID。首次启用本地模型时幂等创建并应用 `default`（`vl/asr/tts/tts-en`），重启后从 SQLite 恢复。
- 管理员 API：`GET /admin/model-services`、`GET/POST /admin/model-profiles`、`POST /admin/model-profiles/:id/apply`、`GET /admin/wordbooks/:id/words/search`、`POST /admin/speech/refresh`。

## 约束与降级

服务 ID 必须在模型管理器发现结果中具备对应能力；切换失败不改变当前配置。缓存写入失败不阻断本次合成，只记录 `speech_cache_miss` 和失败原因。缓存目录不进入 Git。

## 验收

Go 单测覆盖自定义服务路由和默认回退；存储启动矩阵覆盖新增表；前端构建覆盖管理员查询、缓存状态和配置应用。真实课堂仍需在模型管理器和浏览器环境中验证首音延迟及并发长尾。
