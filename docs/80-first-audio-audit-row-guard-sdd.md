# First-Audio Journey Audit Row Guard SDD

Date: 2026-10-28
Status: design and test-only implementation approved by architecture, backend/testability, and security reviewers. Focused and full `TestFirstAudio*` regressions pass. Windows race/vet and the later App/E2E gates remain unverified.

## Scope

Implement only the fixed SQLite row triggers and typed guard for the three successful Agent audit writes permitted by docs/74 section 3 and docs/77 sections 2-3: `classroom.say`, `classroom.show_word`, and `classroom.play_tts`. This test-binary-only slice proves the write boundary against real mattn SQLite. A standalone audit-guard probe uses a private one-use permit bound to one test connection, active transaction, context version, and expected invocation row. It is not a production JOURNEY permit and is never exposed to api.App or the control protocol. The slice does not add SQL permits to application call sites, publish the controller's JOURNEY, create a listener, or claim an api.App/browser journey. The harness remains fail-closed.

## Row contract

The frozen AuditLog column order is `id, ts, actor_type, actor_id, actor_role, tool, risk, ok, result, args, duration_ms, trace_id`. A validating AFTER INSERT trigger observes the generated NEW.id and calls `first_audio_row_guard` with exactly 24 arguments: for each column in that order, `typeof(NEW.column)` and `CASE WHEN typeof(NEW.column)='text' THEN CAST(NEW.column AS TEXT) ELSE NEW.column END`. Expected storage classes are integer for ID/DurationMs, text for TS and string fields, and integer 0/1 for OK. Schema or storage-class drift fails validation. Build/runtime must provide SQLITE_MAX_FUNCTION_ARG >= 24.

The immutable expected invocation row includes the exact generated ID, canonical timestamp bytes, exact DurationMs and Args bytes, current `lesson-<id>` trace, and exactly one expected tool name. Before SQL begins, the coordinator validates the whole expected row against the fixed actor/result/risk/trace contract, tool allowlist, canonical Args encoding, positive measured duration, and inclusive frozen timestamp bounds. Timestamps may use the caller's local offset; validation compares the instant to the frozen bounds, while SQLite bytes preserve the pinned mattn `SQLiteTimestampFormats[0]` representation of the invocation time. Args are exact ASCII bytes emitted by the registered tool (`{"bytes":N}`, 1<=N<=512); the UDF checks byte equality and does not parse JSON. The full NEW row must match: empty ActorType, ActorID=teacher_agent, ActorRole=teacher_agent, the exact expected tool, low risk, OK=true, Result=ok, and all exact invocation values. Comparison preserves SQLite storage class and exact TEXT bytes. The callback does not query SQLite or acquire the lifecycle lock.

The transaction-scoped probe lease owns one registered physical connection and a `database/sql` transaction from ID derivation through final COMMIT or ROLLBACK. Its epoch advances only after `Begin` succeeds; non-BEGIN permits and row callbacks require the active transaction flag, registered connection, current epoch, and immutable context version. A one-use ledger consumes each permit per epoch before its fixed private operation runs. Permits bind the physical connection ID/raw pointer and the expected row where relevant. The row-callback permit is consumed before validating the first UDF callback attempt; a mismatch, repeated attempt, or missing callback fails closed and terminalizes the candidate. A confirmed rollback uses a separate one-use cleanup permit that cannot authorize SELECT, INSERT, or COMMIT. Rollback failure retires the connection and fails the test.

Before INSERT, the test transaction derives the next generated ID on that same connection using `SELECT max(COALESCE((SELECT seq FROM sqlite_sequence WHERE name='audit_logs'),0), COALESCE((SELECT MAX(id) FROM audit_logs),0))+1`. The fixture pool is fixed at one physical connection, and its transaction-scoped lease serializes this read, INSERT, and readback. No browser, protocol input, or SQL parameter selects the ID. The AFTER trigger compares NEW.id with the frozen value and raises ABORT on mismatch. Before commit, the coordinator requires exactly one guard callback, a consumed row permit, GORM's returned ID equal to the frozen ID, and an exact same-connection row readback under its separate permit. Tests cover empty table/absent sequence, sequence greater than max ID, and ordinary increment. Any failed check rolls back; uncertain rollback terminalizes the candidate.

Fixed BEFORE UPDATE and BEFORE DELETE audit triggers always deny with RAISE(ABORT,...); the guarded authorizer also denies top-level UPDATE/DELETE at prepare time. The independent `fa_audit_no_replace` BEFORE INSERT trigger rejects duplicate IDs and INSERT OR REPLACE before replacement; no trigger execution order is assumed. The validating trigger is `fa_audit_guard_insert`. Exact audit guard trigger DDL is stored in `server/internal/api/testdata/first_audio_matrix_journey_trigger_manifest.json`. The existing base schema object inventory remains pinned in `server/internal/api/testdata/first_audio_matrix_schema_manifest.json`; its validator accepts this extension only when the actual schema minus the exact lesson/audit guard trigger namespaces equals that base inventory and both dedicated trigger manifests match their complete DDL and digests. Thus the `fa_audit_no_replace` trigger is in the base inventory and the three new guard triggers are represented only by the extension manifest. Exact observed authorizer tuples are separately frozen in `server/internal/api/testdata/first_audio_matrix_journey_authorizer_manifest.json` as `(phase, source, action, database, table/column/function, permit)`.

The manifest maps the exact GORM startup `FUNCTION(sqlite_version)` probe to `AUDIT_BOOTSTRAP`, `TRANSACTION(BEGIN)` to `AUDIT_BEGIN`; top-level `SELECT`, `READ(sqlite_sequence.seq,name)`, `READ(audit_logs.id)`, and the exact `FUNCTION(max)`/`FUNCTION(coalesce)` callbacks from ID derivation to `AUDIT_ID_DERIVE`; top-level INSERT plus `fa_audit_no_replace` SELECT/READ and `fa_audit_guard_insert` SELECT, exact NEW-row READs, `FUNCTION(typeof)`, and `FUNCTION(first_audio_row_guard)` prepare-time tuples to `AUDIT_INSERT`; post-insert SELECT/READ(audit_logs columns) to `AUDIT_READBACK`; and `TRANSACTION(COMMIT)` or `TRANSACTION(ROLLBACK)` to their distinct `AUDIT_COMMIT` and `AUDIT_CLEANUP` permits. Only tuples actually observed in the pinned mattn/SQLite capture are checked in; the capture test rejects unreviewed extra or missing tuples. The UDF's execution-time row callback is governed by the separate consumed row permit and is not a SQLite authorizer tuple. A capture-only test compares callbacks with the checked-in manifest; runtime observations never grant permissions. Every tuple is additionally bound to the same physical connection, active transaction, and context version. These permits exist only in the standalone AUDIT_GUARD_PROBE test policy, not in a controller phase, and cannot authorize JOURNEY. Unknown callbacks terminalize the candidate and increment monotonic denial evidence.

## Required tests and gates

Real SQLite tests accept all three exact tool rows, local-offset timestamps, and long measured durations; they reject an unlisted tool, invalid expected contracts, wrong tool/actor/trace, timestamp, args, duration, SQL storage classes, duplicate callback, UPDATE, DELETE, duplicate ID, and REPLACE. A wrong-row-then-correct-row case proves the first mismatch consumes the permit and terminalizes the candidate. The AFTER trigger observes SQLite's generated ID; tests cover empty table/sequence, sequence greater than max ID, ordinary increment, and predicted/generated ID mismatch. Every rejected candidate asserts rollback and independent row count or unchanged full snapshot. Tuple tests compare a fresh live callback set for exact equality with the independent manifest and restrict permit names to the finite policy. Tests separately assert prepare-time authorizer UPDATE/DELETE denials and trigger-time unconditional aborts. Strict journey schema validation requires both lesson and audit trigger extensions before opening the guarded pool. This slice does not authorize production `persistToolAudits` or create a reusable permit.
