# 课堂双工确认与原子决策评审记录

## 开发前结论
架构评审通过：先接通 WS 真实旅程，再迁移课堂状态转换到 SQLite 事务。确认前不判分，REST 文字路径保留，默认关闭双工影子能力。

## 风险与约束
当前 Room 内存状态与收据仍分离；在原子提交改造完成前，不宣称事务级幂等。测试必须区分协议可用、课堂推进和持久化恢复三层证据。

## 实现后复核
- Playwright 已覆盖本机真实服务 WS 旅程：启动、PCM 分片 ACK、ASR final、确认 hash、课堂确认收据。
- 修复两个状态机缺陷：End 后首次 Preview 必须允许；Preview 后不得再次修改；确认身份保留服务端初始 revision，最终 revision 单独传递。
- 平台 harness 增加确定性 ASR 响应和空请求保护。

## 持久化提交复核（2026-11-13）
- DuplexRepo.CommitSnapshot 已将 snapshot/<lesson> 与 receipt 状态更新放入同一 SQLite 事务；WS 确认路径使用该提交点。
- 进程重启以该事务中的课堂快照恢复；事务失败返回 commit_pending_recovery。
- Agent/TTS 等外部副作用仍在事务提交后执行，不能在事务回调内重入 Room。

- WS 确认帧现改为事务成功后发送；事务失败恢复内存快照并不发送课堂推进帧。
