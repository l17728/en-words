# Pilot Control Ledger Schema Unification and Test Harness SDD

**Status:** Draft for architecture, backend, test, and security review. This document authorizes no production behavior, route, identity service, ledger write, VFS promotion, or classroom use.

## 1. Problem and scope

The current schema gate has two incompatible inventories. The reviewed DDL draft and its generated inventory contain 103 explicit SQLite objects. `server/internal/pilotcontrol/schema_inventory_v3.json`, embedded by the current Go loader and bound by the schema-fault manifest, contains 95. The nine draft-only objects are `intent_binding`, its three immutability triggers, `pilot_initialization_state`, its three immutability triggers, and `run_root_ledger_meta_update_guard`; the compiled-only object is the obsolete `run_root_ledger_meta_no_update` trigger. The 48 schema-fault cases are all blocked and are not mapped to executable Go tests.

This is a design and test-preparation stage only. It establishes one reviewed schema source, regenerates derived inventories and manifests, maps all 48 cases to discoverable Go subtests, and specifies tests of the actual Go/CGO SQLite path. It does not change product semantics or enable any Pilot entry point.

## 2. Source of truth and digest chain

After domain review, canonical inputs are `review/pilot-control-ledger-v3-literal-ddl-draft-20261021.sql`, `review/pilot-control-ledger-v3-bootstrap-seed-draft-20261021.sql`, `review/pilot-control-ledger-v3-invariant-queries-draft-20261021.sql`, and `review/pilot-control-ledger-v3-initialization-seeds-draft-20261022.json`. The deterministic generator derives ordered statement lists and inventory; hand-maintained object lists are prohibited. It must be a pure read/compute step until all outputs validate: it never edits schema-fault or product manifests and fails on stale source hashes. Each output is written with atomic replacement; the DDL manifest is committed last, and any mixed bundle fails `--check`. Both `--check` and `--write` require `--approved-inputs-sha256`, an out-of-worktree pin over canonical JSON entries `{path, sha256}` sorted by relative POSIX path for docs/50–54, docs/62–63, this SDD, the canonical DDL/bootstrap/invariant/seed/review files, authz vectors, write-capability manifest, schema/product fault manifests, and execution policy. The generator compares this pin before constructing outputs and never creates or stores the approved pin. Do not derive the explicit inventory by running SQLite from the host Python runtime. Parse the canonical DDL into a normalized ordered statement stream and derive explicit object names/table names/types/digests from those statements; the pinned Go/CGO harness validates actual SQLite catalog output and implicit indexes. If duplicated SQL remains inside the manifest, compare its normalized stream byte-for-byte with the canonical input and reject drift. Generate the 48-case execution map by joining the fault manifest with `review/pilot-control-ledger-v3-schema-execution-policy-draft-20261022.json`, the reviewed canonical policy source for execution class, blocked status, Go subtest path, wrapper commands, prerequisites, and evidence path. The policy pins `source_fault_manifest_sha256`; validation must require an exact match and the generated map must retain both fault-manifest and policy SHA-256 values. Validate a bijection, unique Go test paths/result paths, current source hashes, and blocked dependency classes. The generated map is an output, not a second policy source. Generation rejects duplicate/reserved names, unsupported statements, missing target tables, stale source hashes, and any unapproved input change. The external input pin binds the reviewed DDL bytes and prevents an old approval from silently accepting statement/object count drift; a changed DDL requires a newly reviewed pin.

The 103-object inventory remains a candidate, not an accepted baseline. Reviewers must resolve every difference against docs/51–53 and docs/54 before updating compiled artifacts.

Digests are distinct and non-interchangeable: `ddl_sql_sha256` hashes the canonical ordered normalized SQL stream; `inventory_bytes_sha256` hashes the exact canonical inventory JSON embedded by Go; the docs/62 initialization marker stores `inventory_bytes_sha256` and the exact seed-manifest byte digest. The review/source manifest separately hashes every source and generated file; it is never embedded in SQLite or compared as a DDL digest. Generation order is SQL inputs → normalized SQL digest → inventory JSON → inventory-byte digest → review manifest and Go constants. Rename or remove ambiguous `ddl_manifest_sha256` when it currently means normalized SQL. Negative tests must swap digest types and prove rejection; there is no self-referential hash.

## 3. Permitted implementation boundary

The existing path-based `Open` remains a prototype and is not authoritative storage or VFS evidence. The first implementation may change only the deterministic DDL/map generators, generated inventory/manifests, schema digest constants, pure schema-verification functions in `server/internal/pilotcontrol/sqlite.go`, test-only fixtures/harnesses in that package, and the evidence tools `review/run_pilot_schema_gate.py` and `review/aggregate_pilot_schema_gate.py`. The current generator is read-only by default and requires the external canonical-input pin for either `--check` or `--write`; its regression suite locks these guarantees. The original legacy behavior was replaced after Gate D and is no longer used. It may not add initialization/write APIs, publish services, connect to A0, access configured authoritative paths, or change routes. Harness databases must be fresh disposable temp fixtures with synthetic data. A stricter prototype verifier is not production ledger readiness and cannot satisfy the later VFS gate.

## 4. Runtime schema verification

The loader and harness validate through the same pinned CGO driver and connection configuration:

- SQLite version string and number exactly `3.45.1` / `3045001` from the pinned bundled amalgamation; `user_version`, metadata, seed, and immutable initialization marker. `application_id` remains read-only/observable only: docs/51–54 and docs/62 assign no value, so do not set or require a nonzero value absent a reviewed SDD amendment defining its value and atomic write point.
- Explicit object names and normalized SQL digests, plus implicit objects via `table_list`, `table_xinfo`, `index_list`, `index_xinfo`, and `foreign_key_list`.
- Foreign-key/integrity checks, fixed PRAGMAs, and per-physical-connection authorizer restrictions, including denial of DDL, attach/detach, writable-schema, replacement, and unapproved PRAGMAs.
- Atomic test-fixture initialization, marker/seed digest binding, failed-transaction rollback, reopen verification, and no partial state.

Inventories distinguish approved SQLite implicit objects from application objects and reject all other extras. Verification failures are fail-closed with stable error classes; diagnostics identify phase and trace ID without SQL payloads, seed content, keys, or signatures.

## 5. Forty-eight-case execution and evidence contract

`review/pilot-control-ledger-v3-schema-execution-map-draft-20261022.json` is a generated traceability draft. The 47 non-performance cases map to `TestPilotSchemaFaultManifest/<case_id>`; `PERF-01` maps to `TestPilotSchemaPerf/PERF-01` and its separate reference-host command. Each generated row carries its verbatim initial state, action, named barrier, and oracle from the fault manifest. `execution_class` identifies the gating class. Where required, explicit `harness_layer` names the execution target and `platform_requirement` states its platform profile; `runner_command` and `wrapper_invocation` encode build tags; `prerequisites` and `result_path` specify setup and evidence location. This preserves the PERF-01 distinction between `DEFERRED_REFERENCE_HOST` (gate state) and `PERFORMANCE_REFERENCE_HOST` (execution target). The map pins both input SHA-256 values. Discovery asserts 47 unique non-performance subtests plus one unique performance subtest, collectively bijective with the 48 source IDs. The normal Linux matrix reports PERF-01 as `DEFERRED_REFERENCE_HOST`, never as skipped/passed; the schema gate remains incomplete until its independent result is accepted. The map is not execution evidence. Cases with unbuilt dependencies remain `BLOCKED_DEPENDENCY`; wrappers must not run a SQL approximation and mark them passed. Cases may share setup helpers but retain distinct discoverable subtests and result artifacts.

The runner `review/run_pilot_schema_gate.py` must precreate every expected case result as `NOT_STARTED`, capture child output only through pipes, parse Go JSON events, and atomically finalize each result even when a test fails or panics. Persist only allowlisted event fields (`Action`, `Test`, `Package`, `Elapsed`, `Time`) and harness-generated stable error classes; discard the arbitrary Go `Output` field. Raw stdout/stderr may exist only in process memory and must never be written to disk, surfaced in a command transcript, or hashed. If a test attempts to emit an unapproved event or structured field, discard it, record `REDACTION_FAILED`, and fail closed. After the child exits, it marks untouched records `MISSING_RESULT` (and PERF-01 `DEFERRED_REFERENCE_HOST` during the normal matrix); missing/invalid results, nonzero exit, or hash mismatch fails the runner. Only explicit test success plus matching input hashes becomes `PASS`. Each run summary binds a `gate_id` and `gate_contract_sha256`, computed from canonical JSON over docs/65, other reviewed docs/manifests/maps, and runner/aggregator hashes, plus a `source_snapshot_sha256` computed from sorted relative paths and hashes of every compiled source/module/driver input. Results include `runner_sha256` and `aggregator_sha256`; the independently invoked `review/aggregate_pilot_schema_gate.py` verifies them against an approved contract hash supplied out-of-band from a protected CI variable or administrator-owned read-only file outside the worktree. The runner cannot create or override this pin; missing or mismatched pin fails closed. Independent schema and PERF runs can be aggregated only when all bindings match. The aggregate report requires all 47 non-performance cases PASS on every required native matrix cell and a separate PERF-01 PASS; it may not promote `DEFERRED_REFERENCE_HOST`, `BLOCKED_DEPENDENCY`, `MISSING_RESULT`, `REDACTION_FAILED`, or `NOT_STARTED`. Thus partial runs cannot claim overall PASS or combine evidence from different snapshots.

Each machine-readable result under `review/artifacts/pilot-schema-gate/<gate_id>/<run_id>/<case_id>.json` binds case ID; source/generated/test SHA-256 values; runner and aggregator SHA-256 values; Go toolchain; go-sqlite3 module and local replacement hashes; SQLite version, numeric version and source ID; OS/architecture/kernel/filesystem/mount options; build tags, CGO/compiler/linker identity; exact command/exit code; duration; coverage digest; and a digest of the allowlisted structured test-event records. Persist no stdout/stderr bytes and compute no digest over them. Never include SQL bind values, seed payloads, keys, signatures, or raw receipts. A case remains blocked until its bound result exists.

Pin Go to 1.27.3 and its exact reviewed toolchain bundle; pin the module to `github.com/mattn/go-sqlite3 v1.14.22` plus the exact local replacement source hash; pin SQLite to version `3.45.1`, number `3045001`, and source ID `2024-01-30 16:01:20 e876e51a0ed5c5b3126f52e532044363a014bc594cfefa87ffb5b82257cc467a`, all checked at runner startup against the compiled library. Invoke the schema runner as `python review/run_pilot_schema_gate.py --suite schema --coverage --matrix-cell <linux-amd64-ext4|linux-amd64-xfs|linux-arm64-ext4|linux-arm64-xfs> --approved-contract-sha256 <out-of-band-approved-hash> --server-root server --artifact-root review/artifacts/pilot-schema-gate`; it runs `CGO_ENABLED=1 go test -json -race -count=1 -covermode=atomic -coverprofile=<artifact>/coverage.out -tags=pilot_schema_gate -run '^TestPilotSchemaFaultManifest$' ./internal/pilotcontrol`, then `go tool cover -func=<artifact>/coverage.out`. PERF-01 uses `python review/run_pilot_schema_gate.py --suite perf --matrix-cell linux-amd64-reference --approved-contract-sha256 <same-out-of-band-approved-hash> --server-root server --artifact-root review/artifacts/pilot-schema-gate` and runs `CGO_ENABLED=1 go test -json -count=1 -tags=pilot_schema_gate,pilot_schema_perf -run '^TestPilotSchemaPerf$' ./internal/pilotcontrol`. Aggregate with `python review/aggregate_pilot_schema_gate.py --approved-contract-sha256 <same-out-of-band-approved-hash> --run-root review/artifacts/pilot-schema-gate/<gate_id>`. The normal matrix reports PERF-01 deferred and cannot report the complete gate as passed. Capture literal commands and environment; no skip counts as pass. Coverage is evaluated per native schema-matrix run against non-test package code only (Go excludes `_test.go`); the runner checks `loadApprovedSchemaInventory`, `preflightSchema`, `validateSchemaConnection`, `querySingleValue`, `hashNormalizedSQL`, `normalizeSchemaSQL`, `sqliteConnector.Connect`, and `(*Store).configureConnection` at ≥90% statement coverage by parsing `go tool cover -func` output. Missing functions, uninstrumented matrix rows, or any function below threshold fail the aggregate gate. Playwright E2E is not applicable to this isolated database harness and cannot substitute for Go/CGO tests; later user-facing routes require separate multi-user Playwright E2E.

The fixture `TestOpenAcceptsExactPinnedSchemaFixture` must build from canonical inputs and pass `Open` against the generated inventory; missing, extra, altered, and wrong-digest negative controls must fail closed. The map marks cases requiring Stage B transactions, production capacity helpers, Reaper startup, paired cross-store recovery, or signed IPC as `BLOCKED_DEPENDENCY`; the first isolated harness may only report them blocked. SCHEMA-33 uses synthetic marker material and a test-only trust anchor and does not validate production restore authority. Python DDL probes are supplementary and cannot satisfy CGO authorizer, crash, concurrency, signature, or performance cases.

## 6. Review order and regression cases

Review is split into two enforceable gates to avoid requiring hashes for files that do not exist yet. **Design freeze gate (before implementation):** architecture, backend, test, and security reviewers approve this document and exact hashes for existing design inputs only: docs/50–54 and docs/62–63; canonical DDL/bootstrap/invariant/seed inputs; authz vectors and write-capability manifest; current DDL/schema-fault/product manifests, execution-policy input, and draft inventory/map; the existing generator and Python DDL test; `server/go.mod`, `server/go.sum`, the complete `server/third_party/go-sqlite3` replacement tree; `server/internal/pilotcontrol/sqlite.go`, its embedded inventory, and current package tests. Record the reviewed Go toolchain/compiler bundle hash when available. Gate D hashes capture exact inputs; they do not certify implementation behavior. The hash-bound implementation review in §6 authorizes acceptance of the new generator outputs. No new harness execution or generated acceptance evidence is valid before the implementation hash gate. **Implementation hash gate (before running or accepting the new harness):** repeat all four domain reviews against final hashes of every changed/generated source, including the generator, runner, aggregator, Python tests, Go verifier and test files, embedded inventory, and result contract. The approved contract hash is produced from those final reviewed hashes and provisioned out-of-band; it cannot be generated by the runner. Any source, toolchain, or contract change invalidates the relevant review and evidence. Resolve findings and repeat review at final hashes.

After approval, implement only the permitted schema generator/verifier and test harness. Regression must prove repeatable generation; consistent manifest binding; digest-type separation; one-to-one case discovery across both test entry points; exact fixture acceptance; each schema-drift class rejection; authorizer enforcement on every pooled and replacement connection; capability cleanup after success/error/panic/cancel; atomic init rollback; altered seed/schema marker rejection; crash/reopen and commit-unknown distinction; unsupported environments fail the gate; and sensitive values never enter logs. All 47 non-performance results and the separate PERF-01 result are mandatory before the complete schema-fault gate can pass. Production schema authority, A0, VFS, A1/A2, Stage B, routes, and classroom use remain behind independent docs/50 and docs/54 gates.
