# Pilot Quota Durable Append Coordinator SDD

## Status and scope

This is an interface-level design delta for the next slice in `docs/64` and implements ordering already fixed by `docs/63`. It authorizes only an in-memory coordinator that accepts injected journal and anchor interfaces for deterministic tests. It does not authorize a filesystem adapter, privileged service, production route, nonce reservation, encryption, or quota minting. All production gates remain closed.

## Contract

`JournalAppender.AppendAndSync(frame)` returns a typed result with outcome and offset. `NotWritten` is valid only when journal bytes and length are unchanged and offset is absent; `Durable` requires the exact end offset (`old_length + frame_length`) and successful sync; `Uncertain` means any partial write, sync uncertainty, malformed result, or unknown outcome. Any inconsistent outcome/error/offset combination is treated as `Uncertain`. Adapter panics are recovered at the coordinator boundary and treated as uncertain; adapters must not panic as normal control flow. The coordinator never exposes raw adapter errors.

`MonotonicAnchor.Read()` returns the full exact tuple from docs/63 §49: `(sequence,digest,restore_generation,trusted_time_high_water_ns,boot_id,boottime_ns)`. Initial and read tuples require nonzero restore generation and boot ID, and signed-range time fields. Equality compares every field. `CompareAndAdvance(expected, next)` returns `Advanced`, `Conflict`, `Unavailable`, or `Ambiguous`, with the semantics in docs/63 §49; `next` must preserve nonzero restore generation, increment sequence without wrap, bind the synced frame digest, and use one nondecreasing time/boot sample.

`JournalKeyProvider.KeyFor(keyID)` supplies a copy of the selected journal MAC key for encoding. Missing/invalid keys fail before append. The coordinator must not retain the returned key after encoding; a production keyring/provider is outside this slice.

The coordinator starts its fixed 10-second transaction deadline before waiting for its serialization lock, then permits one transaction at a time. Before mutation it reads the anchor and requires full tuple equality with its in-memory anchor. A transient `Read` unavailable result returns unavailable without append/CAS and may be retried by a new operation. A malformed tuple, full-tuple mismatch, restore-generation mismatch, or sequence/time regression permanently trips the process-lifetime breaker and quarantines the coordinator, even if a later read appears healthy. Sequence overflow and any unexpected append offset also fail closed. Record validation, expected sequence/head/digest checks, and encoding all happen before append; the record timestamp must equal the single trusted-time sample supplied for this operation. Failure there returns a bounded error and leaves bytes, anchor, and in-memory state unchanged. It durably appends, then compare-and-advances the anchor. The proposed next tuple preserves the nonzero restore generation, advances sequence exactly once without wrap, uses the synced frame digest, and carries the same sampled boot/time tuple that does not regress. Only after `Advanced` may it publish the new in-memory head and return success. Any uncertain journal result, any non-`Advanced` result after durable append (including conflict or unavailable), or deadline expiry trips a process-lifetime breaker; the coordinator returns no success and accepts no further operation. A proven `NotWritten` result or transient preflight unavailability may fail without advancing state. The coordinator never retries writes or guesses anchor outcome.

The injected clock models the fixed 10-second `CLOCK_BOOTTIME` transaction deadline from docs/63 §59; construction requires the caller to supply a CLOCK_BOOTTIME-backed clock and timer. This slice provides no production/system clock adapter. The first journal mutation requires a one-time write authorization under the same arbiter used by deadline transitions and the global breaker. If timeout/breaker wins first, the journal adapter is never called; if authorization wins first, a later timeout treats the operation as potentially mutating and permanently trips the breaker. The adapter itself never runs while holding the arbiter. `DURABLE_ACKABLE` publication and in-memory head update are atomic with respect to breaker trips. While an adapter call blocks, a deadline monitor can atomically win the same terminal arbiter; the coordinator retains serialization ownership until the call returns, and no later completion can publish state or ACK. Only `DURABLE_ACKABLE` strictly before the exclusive deadline can succeed; `DURABLE_UNCERTAIN` wins at or after it. ACKABLE won before deadline remains success even if response delivery completes later. Tests cover both race orderings and lock-wait expiry; the cross-transaction interleaving test injects an expired waiter's terminal transition while a real `Append` is paused before ACK publication. This slice does not prove process termination. Restart reconciliation, OS locking, trusted time, log emission, and real durability remain outside this slice.

## Required tests

Use deterministic fakes with an ordered operation trace. Constructor rejection for zero restore generation/boot ID and out-of-range tuple fields must have zero adapter calls. Missing/invalid key, key-provider panic, invalid record, wrong sequence/head/digest, and encode failure must prove zero append/CAS and unchanged state; no key bytes or provider error may escape. Assert preflight full-tuple anchor read before append; append-before-anchor-CAS; publication-after-anchor; no duplicate retry; and permanent breaker behavior for uncertain append and every non-`Advanced` post-append anchor outcome. For `NotWritten`, capture journal bytes and length before/after and assert they are identical and offset absent. For `Durable`, reject the starting offset and accept only the exact end offset. Test each anchor field mismatch, sequence overflow, invalid offset/outcome combinations, and that proposed `next` preserves generation, increments once, binds the synced frame digest, samples boot/time once, and does not regress. Inject panic independently in append, key lookup, anchor read, and anchor CAS and assert no panic/raw adapter error escapes; every panic also permanently quarantines the coordinator. Test transient preflight unavailability (no append/CAS, retry allowed), and mismatch/generation/regression quarantine (subsequent retry rejected despite a healthy fake anchor). While an adapter is blocked, prove a second transaction cannot enter; test deadline expiry before the first mutation, while waiting for the lock, or blocked in the adapter, and prove a pre-deadline `DURABLE_ACKABLE` remains successful after delayed response delivery. Force a waiting transaction to trip the global breaker before an active transaction's final ACK and assert no success/head publication. Exercise both terminal-arbiter race orderings. Independently assert returned status, in-memory head, append count, anchor tuple, journal bytes, and subsequent-call behavior. Tests must not claim crash consistency or Linux filesystem durability.

## Acceptance boundary

Before implementation, architecture, backend, security, and test-design reviewers must approve this document at its exact SHA-256. Implementation review and package tests must bind exact code hashes. Native Linux crash/restart and rollback tests, service identity, installer-pinned anchor, telemetry, IPC, and product E2E remain explicit later gates.
