# 15 本机模型与语音验收规格

日期：2026-10-14。状态：**评测工具及冻结样本已实施，真实本机分轨验收进行中，整体模型质量未达门**。原平台验收访问本机8090；用户授权的Qwen3.5-9B临时隔离对比已经完成，原文本服务已独立核验恢复，未永久替换、未调用云模型。固定中文TTS12条已自动验证并经用户确认全部清楚、正确、完整，不能再笼统记人工pending；其他音源/旅程分别以各自签收和结果为准。上游为 docs/05、08、09、12；协议保护与提示改进见20，运行恢复与语音生命周期见18，候选及人工音源当前结果见24/25，数量授权与判分来源增量见26/27。

## 1. 目的与验收层次

回答三个独立问题：本机模型是否理解真实生产反馈；独立音频能否被正确识别；课堂能否以真实本机服务完成教学、跟读、测试与反馈。传输成功、模型结果正确、浏览器完成播放、真人听懂分别记录，不能互相替代。先跑通本地流程，再依据失败归因讨论平台模型替换或云服务方案，替换与云调用均需另行确定具体方案。

禁止将规则兜底成功记为模型成功，将被测 TTS 输出识别失败直接归咎于 ASR，或把 WAV 文件合法、`onended` 回调当成人工可懂度证据。

## 3. 反馈解析评测设计

新增独立、显式启用的本机评测入口，直接复用 Go 生产适配器，不复制或优化一份评测专用 prompt。建议产物：`review/feedback-local-cases.json`、Go 本机评测测试/命令、`review/local-feedback-evaluation.json`。未启用时不访问网络，不混入普通离线 `go test`。

准备 64 条人工标注合成输入：七类意图各 6 条（42），多意图/语义重复/矛盾目标 10 条，边界与攻击性输入 12 条。每条包含稳定 case_id、原文、固定时区日期锚、预期 kind 集合及槽位、Agent 动作/need_confirm/clarify 预期、禁止副作用。覆盖显式/相对词量、频率、月末/闰日/无效日期、备选日期、词组难记、投诉夹带调量描述、语义不明确、提示注入及无关文本。标注先由另一评审者核对并冻结版本与 SHA-256，不能看模型输出后改标准答案。

分两轨报告：

1. **配对采集**：由真实 `Parser.ParseContextAt` 驱动生产 `ZhipuParser.ParseIntents`，在评测传输包装器记录实际子请求及原始模型 content。fingerprint 包含模型、生产 prompt 版本、实际 messages/日期锚、temperature/max_tokens/response_format；case_id、重复轮次和子请求序号单独关联。仅保留摘要/hash及本套合成样本响应，禁止混入密钥或真实学生正文。混合投诉会先拆去投诉分句，因此以实际子请求 fingerprint 配对，不能拿全文模型响应回填不同子句。
2. **模型轨**：对上述同一次真实返回的原始 JSON 独立验证并评分，记录 kind/槽位、错误和耗时；结构/语义错误记失败，不以规则兜底替代。先检查原始字段是否存在、类型正确、kind 枚举合法、confidence 为有限的 0–1 数值，布尔和数值字段禁止 null/错误类型；不能仅看 Go 解码后的零值，把缺字段误判合法。字符串中的数字不自动当数值接受。
3. **产品轨**：记录同次调用经过真实 Parser 和 Agent 后的计划、绕过与兜底。需要重放验证时，仅按完全匹配的 fingerprint 回放该原始响应，错配直接失败；重放标为集成验证，不再计作真实模型调用。字面投诉完全绕过模型时记 policy_bypass，仅评价产品决策；若额外探测全文模型能力，单列为诊断，不并入配对得分。规则降级可证明恢复能力，但原模型轨仍失败。

每条真实样本重复两次以发现不稳定性，顺序固定、并发 1；每一轮模型轨/产品轨使用该轮同一响应，不各发一遍请求后声称配对。报告分别列原始样本数、实际子请求数、模型可评价案例数、policy_bypass 数及每轮结果，旁路案例不进入模型质量分母。字段语义按预先标签比较，模型数组顺序不参与正确性；JSON 外附加解释仍是结构失败，不凭模糊关键词认定槽位正确。草案门槛：结构合法率 100%，意图与必要槽位整体准确率 ≥90%，所有安全样本禁止的写动作发生数为 0。分别列出失败和兜底，模型轨未达标不以产品轨兜底抵消。记录 p50/p95/max 和超时；课堂交互暂以请求未超生产超时、结果无误为硬门，实际等待体验由报告提出进一步目标。

**确定性故障轨单列**：注入取消、坏 JSON、缺字段/null/错误类型、强制低 confidence、超时等，验证不误写和正确降级，取消后写动作必须为 0。这些注入响应不属于 64 条真实质量集及其分母。真实模型自行返回这些错误时仍计模型失败；不能将真实失败挪入故障集排除。

## 4. 独立 ASR 与 TTS

### 4.1 音频样本及 ASR

建立 `review/audio-fixtures/manifest.json`：case_id、语言、已知逐字文本、文件 SHA-256、来源/许可、生成器或录音者类别、采样率、声道、时长。只放合成教学文本，不录真实学生信息。样本冻结后识别，不根据输出挑选通过音频。

英文先用已安装 System.Speech/Zira 离线生成 16 段：8 个词、4 个词组、4 个课堂短句；保存 PCM WAV，优先单声道 16 kHz，必要时用明确可复现转换。该集标注“异源合成语音”，不宣称覆盖真人口音。中文计划 12 段：4 个释义、4 个课堂答句、4 个反馈短句；设计时没有独立中文源；现已按§9引入不同声源Piper并冻结12条短样本，记录来源限制，尚不能替代真人录音和人工试听。

主验收让每段通过归属校验后的产品 `/classroom/lessons/:id/transcribe` 调用真实平台 `/api/asr/transcriptions`，以音频 SHA-256、model、language 和调用序号记录一次原始转写与生产规范化结果、字符/词错误率、关键槽位及耗时。若另做平台直连诊断，应视为第二次独立推理，单列结果与分母，不能称同一次转写；若回放同一原始响应，只标适配器集成测试，不能算第二次模型质量成功。转写只允许预先约定大小写、句末标点和空白归一，不能模糊改成标准答案。短单词/词组精确命中率门槛 ≥90%，关键否定/数字/日期槽位正确率 100%；中文 CER、英文 WER 同时报告。静音/截断/错格式另属故障测试，不能计入准确率分母。

### 4.2 TTS 与可听性

中文 TTS 独立输入 12 条（词语、短释义、课堂句各 4），只调用当前产品支持的 zh。测 HTTP/格式、实际解码、PCM 帧数/时长与请求耗时；不得仅验证 RIFF 头。统一归一化 PCM 至 [-1,1]，记录全段 RMS 与峰值，RMS≤0.0001 标为疑似静音，阈值及版本随样本冻结，不依据输出调参。自动核对容器声明长度与实际解码帧数只能发现文件损坏/字节截断，不能证明整句话讲完；非零能量也可能只是噪声。内容是否完整、可懂明确保留人工字段，不以自动阈值替代。结果存 WAV、摘要和散列。可做 ASR 回环帮助发现疑点，但不纳入独立 ASR 得分。

英文 TTS 不走已明确不支持的本机平台接口。浏览器先枚举本地 en voice，锁定名称/lang/localService，并验证真实 utterance start/end；若无可用本地英语 voice，英语朗读验收阻塞，不能改用在线 voice 或 mock 冒充。System.Speech 存在不保证 Playwright Chromium 能枚举到相同 voice。

人工可懂度留独立验收栏：评审者实际试听、识别内容、口音/停顿/截断备注。自动测试不能填“已听清”，无人试听即 `human_listening=pending`，不得宣称完整语音交付通过。

## 5. local 模式真实小课堂 E2E

新增专用 Playwright 无头配置，隔离端口、临时 SQLite、正式前端构建 preview，后台服务显式 `-providers local`、固定 `ENWORDS_MODEL_CONSOLE=http://127.0.0.1:8090`。不得复用日常 8080/5173，不读取 secrets。只对测试流程使用 `-testmode`；小词库含 3 个已标注词，保留正常 wordsPerLesson 下限，不为缩短测试改产品规则。

顺序旅程：首启/管理员建库发布→两个独立学生选库和进入课程→A 完成实际中文播放/英文朗读、独立英文音频跟读、全词 final 测试→至少一条同义释义触发真实文本判分→A 的本机反馈解析产生实际设置/课表结果→B 的设置、课表、历史不变→管理员可见投诉待办。每个阶段关联实际 DB 结果和 provider trace，不能只看页面 toast。

固定录音通过受控麦克风源输入真实 MediaRecorder，产生真实上传并由后端调用本机 ASR；可用 AudioContext 将预先冻结 WAV 转为 MediaStream。夹具只替换声音来源，**不得 mock SpeechRecognition 返回值、转写接口、模型接口或业务回复**。不复用会抑制待测自动采集路径的 `?e2e=1` 行为后宣称真实录音已验收；应通过正常 local 模式相位触发，断言 recorder.start、非空 WebM 经生产解码转换为 16kHz 单声道 PCM16 WAV 上传及真实 provider trace（格式合同见 docs/21）。MediaRecorder 窗口为 4 秒，完整样本连同前后静音不得超过该窗口；fixture 等 recorder.start 后播放，manifest 记录各段时长，过长样本归截断故障集。用例按预先标注播放清单选择样本，不能从标准答案或当前模型输出生成转写。首次实现明确区分“固定录音浏览器链路”和“物理麦克风/真人说话”，后者仍需人工现场验证。

TTS 请求、音频解码和播放回调保持真实，不注入立即成功的 play/onend。浏览器 headless 真实播放链路仍不证明用户扬声器可听，沿用人工试听门。测试使用足够的正常超时并统计各段耗时；超时算失败，不静默改为全 mock 重跑通过。

## 6. 日志与故障矩阵

请求沿 HTTP→provider→课堂/反馈的 trace 关联，最低记录 case_id（评测侧）、trace_id、parent_trace_id、lesson/task/intent、服务与模型、端点、语言、音频字节/时长、耗时、结果分类、fallback/取消、播放 start/end/timeout。不记录密钥、整段提示或真实用户音频/正文。现有 `model_http_completed/model_request_failed/audio_transcribed` 可复用；需在实施评审中核对 ASR/TTS 解码失败、超限响应和取消是否都有稳定失败摘要，缺失则补 Go+E2E。

| 故障/场景 | 独立逻辑/接口验证 | 浏览器与定位断言 |
|---|---|---|
| 服务未就绪、超时、HTTP 非 200 | discovery 与实际调用分别分类；不改模型 | 提示文字输入/重试，不能假报识别成功；trace 可定位端点 |
| 文本坏 JSON/空意图/非法槽位 | 模型轨失败；产品轨记录 fallback/确认 | 不产生错误写操作，逐项状态与持久事实一致 |
| ASR 静音、错格式、8 MiB 超限、空转写 | 明确拒绝，临时文件清理 | 停止采集并释放轨道，保留手动输入 |
| TTS 坏 WAV/截断/解码失败/播放超时 | 不能只靠头部判定成功 | 标出音频失败，队列取消无后续残留；不标已可听 |
| 暂停、离课、换账号、迟到音频 | 取消绑定原会话/课堂事件 | 无旧声音/旧转写写入新课或新账号 |
| 网络失败、重复提交、课堂重连 | 同 submission/query 恢复，不重做副作用 | 真实历史及课表一致，其他学生隔离 |

故障测试使用本地代理或独立 httptest fake provider，不停真实平台服务；故障夹具报告与真实模型质量报告分开。重用既有 C 全量回归；新增产品 BUG 必须同时补逻辑和 E2E 用例。

## 7. 实施顺序、命令与退出条件

1. 评审本草案及样本标签；确认中文独立音源。仅获得英语源时先出英语部分报告，中文保留阻塞。
2. 新增显式 opt-in 的 Go 生产适配器评测入口及 fixture 工具，离线默认不联网；计划新增文件名/命令尚不存在，不作为已交付工具。
3. 子代理串行执行文本、独立 ASR、TTS；逐层保存结果，再启动 local E2E，避免并行评测争抢本机模型造成不可解释超时。
4. 失败归因优先区分平台就绪/资源、传输格式、适配器、模型语义、音源质量和浏览器播放。修适配器后先跑回归，再重复受影响验收；不得用扩大超时或兜底掩盖能力不足。
5. 汇总报告，讨论模型不足的具体选项及代价；平台替换或云模型验证另行批准，不自动执行。

现有命令（均由测试子代理在正确目录运行；不要在主会话同步跑长测试）：

```powershell
# 仓库根：显式固定origin，避免继承外部配置；仅判分集，非反馈/语音验收
$env:ENWORDS_MODEL_CONSOLE = 'http://127.0.0.1:8090'
$runDir = Join-Path '.test-artifacts' ('local-voice-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $runDir -Force | Out-Null
python review/evaluate_local_models.py --base $env:ENWORDS_MODEL_CONSOLE --text-only --extended-pairs review/model-eval-extended-pairs.json --output (Join-Path $runDir 'judge.json')
# server/：隔离数据库示例，实施时由专用Playwright配置管理进程
$env:ENWORDS_MODEL_CONSOLE = 'http://127.0.0.1:8090'
go run ./cmd/server -testmode -providers local -port 18081 -db ../.test-artifacts/local-voice/test.db
```

后端 main 已自动创建 SQLite 父目录；上面的 New-Item 是为评测报告目录准备，不是弥补数据库目录缺陷。`-testmode` 不覆盖显式 `-db`，该示例仍使用持久 SQLite；实际 runner 必须每次生成新的 DB 路径并拒绝复用已存在数据库，启动失败不得转连开发服务。

已实现Go入口及参数见§9；真实固定录音浏览器旅程由专项配置隔离启动，验收状态以实际报告为准。origin必须是明确loopback、禁跨源重定向，报告exclusive创建。前端代理指向隔离端口，不能转连开发服务。

停止条件：模型轨及产品轨结果清楚、独立样本可追溯、故障矩阵完成、定位日志足够、Go 覆盖率达项目门、全部相关 E2E 通过、领域复核问题清零。中文样本、浏览器本地英语 voice 或人工试听任一缺失，必须明确标记未验收；不能据“流程可跑”宣称真实语音整体完成。
