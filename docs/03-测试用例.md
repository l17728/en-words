## 1. 测试策略总览

| 层 | 工具 | 范围 | 准入 |
|---|---|---|---|
| 单元测试 | Go `testing` / 前端 vitest | 状态机、调度器、判分器、配置边界、意图解析、VAD 算法（纯函数抽取）、WS seq 去重 | 提交必绿 |
| 集成测试 | Go httptest + 内存 SQLite | REST/WS/工具管线/审计/事务 | 提交必绿 |
| 多用户 E2E（服务级） | Go 并发测试：多学生 WS 客户端池 + Agent(Mock) + 管理员 REST | 全链路拟真 | 发布必绿 |
| 浏览器 E2E | Playwright | 关键 UI 流：摸底/课堂/反馈/管理后台 | 发布必绿 |
| 专项 | 覆盖率脚本 / 日志断言 / 恢复演练 | 见 §5 | 发布必绿 |

**Mock 原则**：LLM/TTS/ASR 全走 Provider 接口的确定性 Mock（见 05 文档），每条 E2E 用例声明所需 Mock 脚本号，保证可复现。

## 4. 多用户拟真 E2E 用例（质量铁律 5）

> **并发在场**：学生×3 + 管理员 + 老师 Agent + 系统 Agent 同时活动，按拟真时序编排，非单接口冒烟。服务级用 Go 并发驱动，浏览器级用 Playwright 多 context。

### E2E-01「三学生并发完整学习日」

```
配置: 学生 S1/S2/S3，各自词库(初一/初三/高三)，Mock LLM/TTS/ASR 脚本集
时序(T+相对分钟):
 0   admin 登录，批量导入 3 个词库（各200词，含格式脏数据），发布
 5   S1/S2/S3 并行登录，各自选库、摸底（勾选率分别 10%/30%/5%）
 8   三人同时进入各自首课（Mock Agent 驱动）
     - S1 正常跟读作答（脚本A：全对）
     - S2 慢速+2次超时兜底触发（脚本B）
     - S3 中途断网30s重连续课（脚本C）
 30  三人课中同时提交反馈：S1"太多" S2"周三有事" S3"abandon难记"
     → SystemAgent 并发处理3条：S1 调参、S2 排课、S3 Boost
 45  三人下课；SystemAgent 并发排3套下一课（间隔阶梯正确）
 46  admin 查审计：本轮所有 Agent 调用/配置变更/判分记录完整可查
断言:
 ① 三学生 memory_cards/lessons 互不串库（数据隔离）
 ② 三条反馈状态机各自正确收敛 applied
 ③ S2 课程改期成功且与 S2 其他计划无冲突
 ④ S3 abandon 下次课在批次头部
 ⑤ 全程 trace_id 无断裂；课堂事件可完整回放
 ⑥ 无死锁/竞态（-race 通过）
```

### E2E-02「课堂协同拟真：老师 Agent 与学生实时互动」

```
Playwright 双视角（同课堂）:
  - 学生视角: 点击单词→听朗读(Mock TTS 图标动画)→跟读(REST /voice 提交读词转写→老师听读判读)
    →教完全部词→final 完整测试语音作答(转写→判分)
  - 服务端视角(断言): ui_action 序列 = 设计稿顺序；每个学生事件→决策延迟<1s(Mock)
  - 干扰注入: 学生在判分前狂点按钮(seq 去重)；朗读中点下一词(播放队列不被打断)
断言: 教学期零 quiz；教完最后一词触发 start_quiz(kind=final, total=全部词)；
      打✗词进入轻量回顾面板（E2E 定案锁定用例：bugs-regression.spec.ts）
```

```

断言: classroom_events 无断档；lesson_state 与事件流一致
```
