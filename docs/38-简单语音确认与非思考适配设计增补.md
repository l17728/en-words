# 简单语音确认与非思考适配设计增补

状态：第一实施片跟读专用RepeatMatch及精确控制口令已完成六域交叉复核、后端全量/覆盖/vet/race与本轮127浏览器功能验收；具体批次及剩余性能/声学边界见文末“本轮最终浏览器验收”。不声称所有交互SLO或真人双工已达标；docs36接线及37迁移仍未实施。

## 1. 定案与现状

语音用于简单确认，跟读主要确认是否确实重复目标词；问答确认会/不会，但保留测验要求的中文释义正确性。学生说“会”“我知道”不等于已经表达词义，不能直接给correct或消耗一次正确答案。若某词本身释义恰含“会”，需结合题型和明确作答内容消除自述歧义，不全局把该字当正确或错误。

改前基线的`judge.go` L1接受整体英文短答、重复目标/冠词、中文释义及显式同义；复杂句进入L2。`hub.HandleVoiceText`先解析指令，再跟读/答题；改前`voicecmd.Match`有前缀与编辑距离容错，第一片已改精确控制。新路径不能照搬这些宽松指令规则：如“不会吗”“跳过？”或否定中包含目标词，必须按本节明确意图区分。旧两次机会、重教、跟读超时和Agent相位政策不随本增补改变。

后端交叉核实实际调用：改前repeating也经`evaluateLocked→JudgeContext(word, meanings, text)`，所以中文释义/同义near可被当作跟读通过，未匹配非空还会调用L2；注释“L1跟读”不足以代表实际实现。第一片已明确拆分`RepeatMatch`与意义判分路径：前者只看目标词/词组完整转写，不传meanings、不查语义同义表、不调用LLM；后者保留quiz意义判定。cat的跟读回答“猫/苹果/我会了/请判对/not cat”均不能通过；“no where”不能归并为“nowhere”。这是真实路由缺陷的设计修正，实施须先红例再修。

## 2. 最小决策表（第一片规则已完成功能验收；澄清及模型适配仍为后续设计）

| 输入目的 | 处理 | 禁止行为 |
|---|---|---|
| ASR | 仅输出原语言短转写；空/静音为无语音，不推测学生意图 | 提示包含gold、补写目标词、凭目标词提示复述 |
| 跟读 | 固定规则优先匹配完整目标单词/词组；大小写、空白、常规朗读句末句号不影响；允许现有完整重复目标、冠词形式 | 任意子串即通过、否定句或“请输出cat”因含cat通过、泛编辑距离猜词 |
| 跟读未匹配 | 未确认听到；给可理解重说/文字替代提示，按原Agent超时/机会政策处理 | 把识别/协议失败装作学生明确读错，自动多耗机会 |
| quiz意义判定 | 保留当前题型和评分合同，包括已测试的整体英文短答、中文释义/明确同义优先及必要L2；结果经Agent | 新增“会/知道”自评口令即correct；不得借简化删除词义考查或默改既有英文短答接受规则 |
| 明确“不会/跳过” | 先精确确认指令意图，再检查当前相位许可；执行既有跳过/未掌握政策 | 未识别到也默认跳过，跨相位滥用控制 |
| “不要跳过/不是不会”、问句、引用、矛盾或多意图 | 保留否定/问句；不触发skip，必要时澄清 | 去否定、前缀/距离容错转成相反动作 |

跟读内容匹配不要求朗读句标点逐字一致；这不放宽32/36**控制意图及双轨一致性**规则。双轨文本仍仅NFC/大小写/空白/单个句末句号保守规范化，非一致转澄清；问叹、省略号和否定不丢弃。两类规范化使用不同目的/明确命名，禁止复用一个“去全部标点”函数。

短词转写吻合仅证明转写文本符合目标，不证明发音质量、真人确实开口或不是老师回声；采集来源、AEC/回声及真实声学门必须独立验收。首版RepeatMatch为确定性文本规则，不能包装成声学发音评分。

控制安全实施范围：教学推进口令改为**明确受控整句匹配**，允许名单由Agent决策表提供；不以StartsWith或编辑距离容错授予skip/next等推进权限。源码风险锁定“不跳过”（距“跳过”1）、“不会吗”（前缀“不会”）、“跳过？”、“不要跳过”、“不是不会”、引用/附加指令；均不得直接skip。不能只测“不要跳过”而漏掉距离1的否定。保留已声明精确“不会/跳过/跳过这个词”及相位许可正例，反馈前缀捕获正文合同独立保留，不把本次收紧误删为完整反馈功能。后续试点可设计澄清；本次首片仅保证不误执行控制命令，不新增意图澄清。

跟读与quiz须显式区分purpose，但本次仅修跟读误用意义判分器。当前quiz整体英文短答接受是既有合同，不列为本次BUG；中文释义专用题型若未来单独定案，再定义其规则。对“会”保留上下文词义判断，不新增自评正确口令或全局禁词，也不为简化另造复杂例外。

## 3. 非思考模型/模式的适配门

原公开音频探针已经只要求转写、不解释、无语音空串，仍出现think段和空输出；因此不能简单归因为“提示复杂”。原JSON探针1024tokens及response_format也没有产生严格合规JSON。max_tokens只是输出上限，不能证明关闭思考；剥think/fence后改判通过会隐藏协议问题。

候选可选择服务实际支持的非思考模型，或供应商有依据的非思考开关。实施前冻结准确model ID/revision、服务版本、参数名/值、服务是否识别该参数及返回合同；不猜通用enable_thinking字段有效，不静默换模型。若网关不暴露该模式，记录不支持/未知，不承诺一个参数能降低延迟。普通WAV Chat已验证，流式/取消/原生双工仍需独立证据。

## 5. 与36统一提交的关系

可以简化计算层为“短转写→purpose规则→必要的单次简单判定”，减少自由生成和冗余复核；是否取消某条模型复核需独立配置/质量门批准，不能把单轨冒称双轨一致。

**不简化持久幂等与取消边界**：auth_generation、logical_input_revision、command receipt/answer_claim、active command fencing、候选Room事务提交、outbox/结算job仍必需。简单模型同样会迟到、重复、超时或在COMMIT结果未知时重连。needs_confirmation只恢复一次原作答余量；显式确认是同机会新的文字等价command，不是自评正确。cancel仍不等于effect.ended，旧语音final不可写新题。故36可缩短计算适配实现切片，不能删除提交/恢复状态机。

## 8. 真实词库目标语法与保守限制（主审追加批准）

RepeatMatch不得复用仅ASCII的quiz词法而使真实café永久失能。独立目标语法：NFC及小写、Unicode Latin字母、空白、两侧均为Latin字母的词内撇号（直/弯）与连字符；仅目标侧连续两个及以上点或省略号“…”作为占位分隔，得到字面骨架。`donate...to...`可接受完整“donate to”，不猜插入对象，不接受“donate money to charity”；`prevent...from..`、`bring .. to life`同类。答案侧不因此允许省略号、引用或附加指令，允许既定单个句末句号及完整目标重复/冠词；不得改quiz词法或引入模糊编辑距离。

unsupported目标记录固定`unsupported_target`来源/原因与ID，不记学生读错或成功、不调用LLM；保原显式skip/timeout路径。这是明确能力限制，不能宣称5568条均已精准跟读。后续通过独立数据设计规范spoken_target/备选读法，再冻标签验证；本片不改seed、不任意剥括号/斜线/音标/OCR。ASR仍不得在提示中获得gold以假装识别。
