# RunRoot Deterministic Writer-Wait Test SDD

## Status and scope

This SDD closes two test-quality gaps recorded in `review/pilot-bootstrap-control-ledger-acceptance-20261021.md`: the stale-generation concurrency test and the WAL-transition cancellation test infer SQLite lock contention from elapsed sleeps. It changes no production lock policy, transaction order, timeout, or cancellation semantics. The new hook is a test-only observation installed on the pinned test connection.

## Design

Extend the local `go-sqlite3` fork with `SQLiteConn.RegisterBusyHandler(func(retryCount int) bool)`. The C callback trampoline looks up a connection-owned Go callback, reports SQLite's retry count, and returns the callback's retry decision. A nil callback explicitly clears the custom handler via `sqlite3_busy_handler(db, NULL, NULL)`; SQLite then returns BUSY without delay. It does not restore a previous timeout handler. Tests that need the normal timeout must reapply it with `PRAGMA busy_timeout=<ms>` and assert the observed pragma value. Production connections never install this test callback, so their configured 5000 ms timeout is unchanged. Callback panic is recovered and fails closed by returning false. Registration/removal and `SQLiteConn.Close` serialize on the same connection lifecycle mutex; registration on a closed connection returns an error. Close holds that mutex across the native close and callback-handle removal, and leaves the connection open if native close fails. No package-global observer is allowed.

Tests install a buffered, nonblocking first-entry signal and a test-owned release channel. The callback signals that SQLite itself invoked its busy handler, waits only on the explicit test gate, then returns the requested retry decision. The test cancels the operation context or commits the lock holder only after receiving that signal, and releases the callback in a deferred cleanup path. Register the release-and-join defer after connection-close defers so Go LIFO ordering releases a blocked callback and joins the worker before any connection is closed, including on test failure. No sleep establishes that a lock wait or retry began.

The stale-generation case holds `BEGIN IMMEDIATE`, inserts a newer generation, starts the older consumer with the custom handler installed on its pinned `sql.Conn`, waits for the first busy-handler signal, commits the newer generation, then releases the handler with `retry=true`. The retried `BEGIN IMMEDIATE` must succeed; the consumer rereads the durable high-water mark and returns unconsumed without inserting. The WAL cancellation case starts from DELETE journal mode, holds a read transaction after reading a row (preventing the exclusive journal-mode transition), and runs `PRAGMA journal_mode=WAL` through `enableRunRootLedgerWAL`. The native busy callback signals entry and waits at the gate. The test cancels the parent context, releases the callback with `retry=false`, and expects `context.Canceled`; it then verifies the journal mode remains DELETE and no Pilot ledger schema was published. `enableRunRootLedgerWAL` borrows but does not own or dispose its SQL connection; `NewRunRootLedgerWithLogger` owns connection disposal on initialization failure, so the helper barrier does not claim disposal. Add a separate cgo-only constructor failure test with a tracked SQLite connection: hold the DELETE-mode reader lock so the WAL transition fails with SQLITE_BUSY, then assert NewRunRootLedgerWithLogger returns failure and the driver connection is closed. If the pinned SQLite version bypasses the busy handler for this conflict, the barrier times out and the case fails; it is never reclassified as reached. Existing timeout tests remain outcome tests and are not relabeled as barrier evidence.

## Required tests and logs

Add driver tests for callback counts/retry values, replacement/removal after a completed operation, nil clearing plus explicit timeout reapplication, panic behavior followed by successful connection reuse, and registration-versus-close serialization (either registration wins and its handle is released on close, or close wins and registration is rejected). Count connection-owned cgo handles before/after under the handle registry lock. Add RunRoot tests for signal-before-cancel/commit ordering, exact final ledger rows, preserved DELETE mode/no schema on WAL cancellation, and cleanup on every failure path. Every gated test defers gate release and waits for the operation goroutine to join even when an assertion fails. Move both barrier tests into a dedicated //go:build cgo && pilot_e2e file so non-cgo pilot tests do not try to use a driver whose Open is a runtime stub. The constructor-disposal test and sqlite3_busy_test.go are also cgo-only. Keep RegisterBusyHandler in the !cgo stub as an error-returning method so the driver API surface remains consistent, but do not claim that stub-backed tests run successfully. Structured test diagnostics record test ID, retry count, gate reached, action released, outcome class, and ledger row counts; they must not log request identity secrets. Run focused tests, package and full-suite tests, `-race` where supported, vet, and driver/package coverage. Linux acceptance remains separate.

## Exit criteria

Architecture/backend/test-design review approves this exact SDD and failure matrix before implementation. Passing these deterministic tests improves only the RunRoot ledger component evidence; it does not satisfy A0/A1/A2 integration, VFS, package coverage, product API/E2E, native Linux, or classroom gates.

## Cross-platform fixture correction (2026-10-22)

The first native Linux run found that the WAL cancellation and constructor-disposal tests did not explicitly establish their stated DELETE-mode precondition. Their implicit `modernc.org/sqlite` default allowed the WAL transition to succeed without invoking the registered busy handler. The required fixture correction and Linux/Windows regression oracles are specified in [docs/60](60-pilot-runroot-wal-test-fixture-sdd.md); this is test-fixture work only and does not alter runtime policy.
