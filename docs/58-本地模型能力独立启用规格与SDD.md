# 本地模型能力独立启用规格与 SDD

## 问题与目标

8090 管理平台分别启停文本、ASR、TTS。2026-11-12 真实媒体 E2E 发现：ASR 和 TTS 已就绪、文本模型停机时，`-providers local` 因强制文本探针收到 502 而退出，课堂无法使用本地语音。目标是让语音能力独立可用，同时保留文本模型可用时的 L2 判分与反馈解析。

## 行为规格

1. 启动时必须成功发现 8090；注册表无任何受支持能力时启动失败。只要至少注册一项，即使全部模型停机，仍以规则判分和文字输入启动；服务状态另行报告，不能把“已注册”当成“已就绪”。
2. 文本模型通过结构化探针后才注入 `Judge.LLM` 和反馈 LLM。探针失败时继续启动，保留规则判分和规则反馈，记录 `local_text_degraded`，仅写状态与错误类别，不写学生内容或密钥。文本模型恢复后的 L2 注入需重启应用；语音恢复不需要重启。
3. `/providers` 返回本次状态快照：`local` 表示本地模式已装配，`asr/tts_zh` 仅在对应服务为 `ready` 时为真。状态接口超时或失败时语音能力均报不可用，课堂明确提示使用文字跟读或作答。转写失败保留文字输入，不推进课堂。
4. 课堂挂载时、此后每 10 秒及 WebSocket 重连后刷新能力；请求串行且忽略过期结果。服务恢复最长约 12 秒可见（10 秒轮询加 2 秒后端上限）；能力变化不得让已取消的录音提交旧结果，不改变课堂状态、判分幂等键或播放代次。首次能力未知或查询失败时，禁止调用浏览器自带云语音识别，保留文字输入。

## 实现设计

`localmodel.Discover` 只解析固定的 `vl/asr/tts` 注册信息，至少一项能力存在即可通过。`EnableLocalProviders` 先装配客户端，再对已注册文本能力做一次结构化探针；失败时不注入文本 LLM。`/providers` 从 8090 `/api/status` 读取 `ready`；后端调用上限 2 秒、成功快照缓存 2 秒并合并并发读取，失败快照不超过 2 秒。8090 状态实测约 0.4 秒；超时按不可用处理。请求级语音失败继续走现有 503 与文字输入降级。日志沿用 trace ID、module、event、duration_ms，并新增能力状态摘要。

## 用例与验收

- Go：ASR/TTS 已注册、文本 502 时启动成功，`Judge.LLM` 保持 nil；文本 200 时原有注入不变；仅文本 502 时文字规则模式启动；空注册表和坏注册表仍失败。
- Go：`/providers` 对 ready、stopped、状态接口故障分别准确返回；ASR 503 不推进课堂；并发状态读取合并、超时不超过 2 秒。
- Playwright 无头：真实 8090 ASR/TTS、文本停机时，浏览器完成英文跟读与中文答题；隔离模拟服务停机/恢复时切换文字输入和恢复语音，不重复提交；首次状态未知时不启动浏览器云识别。故障用例仅加速页面轮询定时器以避开课堂答题超时，12 秒上界由真实定时常量与后端状态超时共同核对。模拟故障套件不得启停共享 8090。
- 整体：Go 全量、vet、前端构建、相关 E2E 与日志审查通过后收尾；合成音频质量与真人课堂试点另行记录，不以传输成功代替准确率。
