# 首词展示与自动开播间隔设置 SDD

## 状态与依据

设计已完成架构、课堂状态、前端和测试审查；实现正在进行回归验收。2026-11-01 的隔离 SQLite + `api.App` + Playwright 矩阵完成 30 次冷样本和 100 次热样本，130 次全成功，但首播放帧 p95 未达 2 秒门槛。基线分位数和复测状态见 [首音矩阵报告](76-first-audio-matrix-result-20261101.md)。

## 目标与行为

将 `show_word` 发送到自动 `play_tts` 之间的固定 800 ms 改为用户可调的最短等待，默认 250 ms。该值作用于每个新词，包括首词和后续词；服务端现有 1 秒 tick 仍会带来不足 1 秒的轮询超调，调度误差另计。界面不得宣称精确开播时刻。手动点击和语音口令继续立即开播，不等待该定时器。

设置仅在课堂首次进入时冻结到 `EffectiveSnapshot`。排课后、首次进入前保存的新值适用于该课；首次进入后修改只影响尚未进入的新课；重连使用原课堂快照。课堂词序、重复次数、TTS 供应商和判读规则不变。

## 配置与兼容性

- 新增整数 `showWordLeadMs`，范围 100–2000 ms，默认 250 ms。最小值为 100 ms，以便浏览器更新字幕并完成呈现；0 ms 不接受。
- 新设置 API 接受完整六字段 camelCase 对象。缺字段、`null`、未知字段、重复键、非整数或越界值一律拒绝。设置与审计记录在同一事务提交。
- 旧五字段客户端继续有效：仅更新和审计原五键，不创建、覆盖或删除学生的 `showWordLeadMs` 值；响应返回六字段有效配置。
- 新快照写 `snapshotVersion=1` 并显式写入新键。版本 0 快照恢复为历史 800 ms；版本 1 缺少该键或值越界视为损坏并拒绝恢复，不用零值猜测。
- 设置页以秒显示，步长 0.05 秒；保存时转换为毫秒。字幕在对应 `play_tts` 播放期间可见，现有播放队列负责隐藏和切换。

## 日志与隐私

沿用配置 mutation 审计和课堂 `classroom.delivery_ready`、`classroom.tts_segment_scheduled` 日志。记录设置值、学生/全局作用域和 trace；不记录学生音频或回答。矩阵原始样本只写入本地忽略的私有 `.test-artifacts/`。

## 验收用例

1. Go 配置与 API 测试覆盖默认值、100/2000 边界、越界、全局/个人覆盖、持久化、旧五字段兼容、审计原子性及事务失败回滚。
2. FakeClock 测试确认阈值前不推进、到期后由 tick 推进；覆盖首词和后续词、快照迁移、版本 1 缺键拒绝及 Machine 创建后的配置冻结。
3. Playwright 从设置页保存 0.1、2、0.25 秒，断言毫秒请求值、刷新回显、字幕可见和播放词与字幕一致。播放帧及 mock `onstart` 不代表声学起音。
4. 当前未有专门 Playwright 用例覆盖“课堂进入后从 2 秒改成 0.25 秒、当前课保持旧值且下一课采用新值”的跨课旅程。后端冻结语义已有单测；该跨层旅程仍需单独验收，不得据此宣称设置特性 E2E 全覆盖。
5. 设置完成后重跑 30 冷 + 100 热隔离矩阵。所有尝试必须成功，冷/热首播放帧及字幕呈现 p95 ≤ 2000 ms，最大值 < 10000 ms；真实课堂声学验收单独进行。
