# First-Audio JOURNEY Lease Integration SDD

Date: 2026-10-29

The production JOURNEY lease bridge, reset-permit enforcement, listener gating, and two-process journey remain unimplemented; do not infer their acceptance from the capture artifact.

## Goal and boundary

Extend the accepted startup/PREFLIGHT owner into protected `JOURNEY` operations, the controller-only reset barrier needed for the second browser process, and listener readiness gating. Implement and accept the lease bridge plus this narrow two-generation journey/reset slice. Do not claim cold/warm performance matrix or real classroom completion.

## Authority model

Keep three lifetimes distinct. A **WS session lease** covers socket registration through worker/read-loop exit, and is released exactly once after both workers join or cleanup becomes terminal. It prevents reset while a browser session is still attached. A **generation operation lease** is separately issued per REST request, WS message, timer callback, or delayed effect before its first lesson/Room read; it remains through side effects and response/frame enqueue/send and is released exactly once. It prevents reset from crossing in-flight work. A **context-bound SQL permit** is acquired per driver-observable autocommit SQL statement and held through execution/result close; each `BeginTx` instead starts one permit spanning that transaction, and its statements reuse it. Do not claim the driver can infer a high-level GORM operation that may issue multiple statements. No SQL permit may wait for a context drain while still held.

The test owner alone controls admission, phase publication, reset, and permit issuance. One controller admission lock is the linearization point for REST operation acquisition, WS session reservation/activation, per-message operation acquisition, timer/callback acquisition, and reset closing admission. Each successful acquisition registers its lease and captures the current generation before releasing that lock; reset closes admission under the same lock before it snapshots leases to drain, so no old-generation lease can register afterward. A WS reservation has `RESERVED`, `ACTIVE`, `REVOKED`, and `RELEASED` states. It is created before Upgrade. Reset marks every RESERVED/ACTIVE old-generation session REVOKED under the lock and snapshots active sockets. After successful Upgrade, the handler must reacquire the same lock to transition RESERVED→ACTIVE; if reset already marked it REVOKED, it closes the just-upgraded socket without exposing it to Room/worker code and releases the reservation exactly once. Upgrade failure and reset racing that failure share the same idempotent release CAS. Reset releases the mutex before closing sockets/joining/draining. Each operation token is controller-issued and binds exact run ID, generation, unique request/operation ID, and active lease record. It is propagated only through that operation's context; derived contexts may reuse it only within that same operation, never in another request. Each SQL permit additionally binds the operation lease, active context version, and actual tracked SQLite connection ID/raw identity. After reset closes admission, no new operation/session/timer lease is allowed, but a statement permit may be issued to a pre-close registered old-generation operation while it remains active and before the fixed drain deadline. This lets admitted multi-statement work finish; reset waits for its release. New operations cannot borrow it. At the deadline no new statement may execute, including statements inside a previously opened transaction; cancel and explicitly roll back if the outcome is known, otherwise invalidate/retire that physical connection and terminalize the owner. Missing/foreign/stale tokens, unwrapped SQL, uncertain transaction outcome, or unclassified callback terminalizes the owner.

The `database/sql` driver decorator is the permit boundary, not a GORM callback approximation. For autocommit SQL, `Conn.ExecerContext.ExecContext` validates the operation token on the selected tracked connection, issues one statement permit, and releases it after execution; `Conn.QueryerContext.QueryContext` issues one permit and wraps returned `driver.Rows`, which releases exactly once on `Close` (including EOF/context-driven automatic close), while query error releases immediately. `Rows.Close` error also releases once and terminalizes. `QueryRowContext` inherits this lifecycle. Legacy context-free `Execer`/`Queryer` paths are denied. The journey GORM configuration sets `PrepareStmt=false`; `Conn.Prepare`/`PrepareContext` fail closed in JOURNEY, and no `driver.Stmt` may execute. Tests force `ErrSkip` and prove SQL never reaches raw SQLite (zero authorizer/statement events). `BeginTx` covers GORM implicit write transactions and explicit `db.Transaction`; its wrapped `driver.Tx` owns one permit through terminal Commit/Rollback, and statements on that Tx validate/reuse the same operation token and permit. Begin failure releases immediately. A Commit error is outcome-uncertain: mark the Conn invalid before returning, terminalize the owner, physically retire the raw connection, and verify it is absent from the pool/registry before any later operation; never issue retry SQL or follow-up audit/snapshot writes. Context cancellation and database/sql automatic rollback converge on one idempotent release path. `SAVEPOINT`/nested GORM transactions remain denied unless a separate SDD observes and authorizes exact callbacks. Before pool reuse or reset, prove no row or transaction permits remain. Audit all `DB.Raw(...).Rows()` callers: each must close rows; a leak causes bounded reset-drain timeout and terminal failure.

Reset closes admission for the old generation under the controller lock and snapshots the sessions to revoke, then releases that mutex before timer cancellation, socket close, worker join, and drain; lease/session release must be able to acquire the mutex during drain. Only after session, operation, ordinary SQL-permit, and transaction counts reach zero may the controller issue one independent, opaque reset permit. This permit binds the run, reset ID, old/new generation, old/new lesson ID, fixed SQL contract, context version, and one pinned live connection identity; it is not an operation lease and cannot be borrowed by a request. It is accepted only while admission is closed and all ordinary counts are zero. Its exact contract allows the docs/74 lesson-ID-only update, deletion of `snapshot/<oldID>`, transaction control, and the prescribed same-connection full snapshot/readback proving both old/new snapshot keys absent. No other DML/read is permitted. Count it separately as `active_reset_permits` (exactly one during reset) with issued/released totals. After commit and readback, revoke/release the reset permit; only when its count is zero and totals reconcile may the controller reacquire the lock to atomically publish the next generation and reopen admission. Timeout, contract mismatch, or uncertain outcome revokes the permit, terminalizes and retires the child; it never increments generation. A delayed callback must recheck the captured generation after acquiring its lease; it cannot borrow a new-generation token.

The reset permit uses one absolute monotonic deadline equal to the existing protocol reset deadline (`docs/73` §7h, 35 seconds) from reset request receipt; drain, transaction, readback, and release all consume that same budget. Every statement and every statement inside an already-open reset transaction checks this deadline. Expiry forbids further SQL, invalidates/retires the pinned connection, revokes the permit, and terminalizes the run. A fake monotonic clock drives exact-before/at/after-deadline tests.

The ordered reset SQL/authorizer contract is finite: (1) `BEGIN` is the authorizer transaction callback emitted by `driver.ConnBeginTx`; (2) one `SELECT` of the complete lesson column list in `firstAudioStartupModels()` field order from `lessons WHERE id=?`, requiring exactly the bound old synthetic lesson; (3) one `UPDATE lessons SET id=? WHERE id=?`, bound only to the controller-issued new and old IDs, requiring exactly one row and the row-guard OLD/NEW contract from docs/77; (4) one `DELETE FROM runtime_records WHERE key=?`, bound only to `snapshot/<oldID>`, requiring exactly one row; (5) `COMMIT` is the authorizer transaction callback emitted by `driver.Tx.Commit`; (6) one schema-manifest read `SELECT type,name,tbl_name,sql FROM sqlite_master ORDER BY type,name,tbl_name`; and (7) exactly one read per table in `firstAudioCaptureDatabaseSnapshotWithKnownSchema`, sorted by table name, with its frozen model-field column order and primary-key order (`sqlite_sequence` uses `name,seq`). No other SQL, repeat, reorder, extra table, or readback query is admitted. The snapshot must prove the lesson changed only its ID, the old snapshot is absent, the new snapshot is absent, and every other table/schema byte matches the computed expected post-reset snapshot.

Before implementing reset-permit authorization, a capture-only test on a disposable prepared fixture executes the above fixed sequence with a recorder ConnectHook and writes `server/internal/api/testdata/first_audio_reset_authorizer_manifest.json`. The artifact freezes each statement index and exact ordered authorizer tuple `(action,arg1,arg2,database,trigger)` with multiplicity, including transaction, trigger/UDF, table/column readback events; it records SQLite/driver/schema/trigger-manifest versions and a digest. The tuple oracle is compared byte-for-byte in both positive and negative tests. Capture code is not an authorization path and does not modify a guarded backend. Architecture, backend, security, and test reviewers must review this manifest before the reset permit can be implemented or enabled. The immutable table/column source is the schema and read manifest in docs/74 §2/4 plus `firstAudioStartupModels` and `firstAudioStartupReadManifest`; the capture artifact freezes the actual runtime callback order so no semantic wildcard remains.

The child-local bounded evidence ledger records only event kind, generation, synthetic lesson ID, and `operation_hash=hex(HMAC-SHA256(runCapability, "first_audio_play_tts" || 0x00 || operationID))[0:32]`; the key exists only in child memory and raw operation IDs are never exported. It never records student text, utterances, answers, audio, paths, capability, SQL, raw request IDs, or credentials. Extend the existing `metadata` response with `journey_events`, a maximum-two array of exact objects `{sequence:uint64,event_kind:"first_play_tts_enqueued",generation:uint64,lesson_id:int64,operation_hash:string}`; `sequence` is 1 then 2. An atomic per-generation first-frame flag appends exactly once when the first audio frame is accepted into the client send queue; subsequent normal `play_tts` frames do not append or fail the run. Duplicate first-frame events for one generation are terminal. The parent requests metadata after each browser process exits and before reset; it asserts exactly one first-frame event for that generation and compares its lesson/generation to bind/reset metadata. Browser frame receipt and synthetic speech-start remain separate E2E assertions. Metadata exposes aggregate session/operation/ordinary-SQL/transaction/reset-permit counts and issued/released totals, but no text or raw IDs. Reset requires all ordinary counts zero before issuing exactly one reset permit; it requires that permit revoked and released with count zero before generation publication. The deterministic blocked-WS late-completion race is a Go integration test, not a browser sleep: it holds a message at an injected barrier after lease acquisition, requests reset, verifies socket revocation and blocked drain, releases a completion and proves it rechecks generation before state mutation/frame enqueue; reset advances only after both workers join and all counts reach zero. The two-process Playwright run verifies externally visible no-old-audio/caption behavior and consumes the bounded metadata evidence.

Do not publish `JOURNEY` until startup/PREFLIGHT receipts are complete, the App lease bridge and every route/Room/timer callback wrapper are installed, and the exact synthetic policy is loaded. Keep admission closed, create exactly one loopback listener, publish JOURNEY, then start `Serve` behind a gated handler. A listener wrapper signals when the accept loop is live; only then atomically open operation admission and return its observed loopback origin. Accepted requests before that point block without reaching App code, but also select on `request.Context().Done()` and server-shutdown cancellation so startup failure cannot strand handler goroutines. Monitor the Serve goroutine for its entire lifetime. Any return before readiness, or any return after readiness other than an owner-requested shutdown, closes admission, terminalizes the owner, closes listener/server/DB, and is reported as bind failure or terminal server loss; this includes unexpected `http.ErrServerClosed`. Prove no listener remains. Avoid a global “some lease is active” allowance: unrelated goroutines must not borrow another request's authority.

## Required verification

The unexported dependency bundle injects failures at `lease_bridge_install`, `publish_journey`, `serve_start`, and `serve_ready`; use a real occupied loopback port for bind failure. Each failure test records whether JOURNEY published, whether a listener was bound/closed, App-handler call count, owner terminal state, DB/pool close status, and whether the port still accepts. Before-ready requests never invoke App. An unexpected Serve return after readiness revokes admission and terminates active requests/sessions. A failed run cannot reset or count as a passing journey.

- Unit/integration: atomic lease acquisition versus reset-close race for REST, WS upgrade/message, timer, and callback; reset revokes a RESERVED session, races with a successful Upgrade, rejects activation, closes the new socket, releases once, and never advances generation while that old socket is reachable; upgrade-failure exactly-once release; reset revokes active sockets and joins both WS workers; exactly-once session release; request-context propagation; an admitted operation paused between statements may finish its next same-generation SQL permit during bounded drain while a new operation is denied; a transaction paused across the drain deadline cannot execute another statement and must confirm rollback or retire its Conn; reset permit cannot issue before all ordinary drains are zero, is exactly one/run/reset/generation/conn-bound, rejects foreign/replayed/expired tokens and every unlisted SQL tuple, and must be revoked/zero before publishing the next generation; direct `ExecContext`, `QueryContext`, context-free legacy, Prepare/Stmt, and ErrSkip fallback policy; real GORM query rows held until explicit close, EOF, query error, Close error, and context cancellation; leaked `Raw().Rows()` makes reset time out terminally; implicit/explicit transaction permit reuse; Begin failure, async rollback, Commit error, nested SAVEPOINT denial, invalid-connection marking and raw-connection retirement with no pool reuse; denied SQL without a token and cross-request token replay; close/reset drain; timeout and late completion; stale timer/Agent callback rejection immediately before mutation and send; uncertain COMMIT forbids further SQL; multiple normal audio frames in one generation append only one `first_play_tts_enqueued` event, and two generations append exactly two ordered events; exact row/transaction/session/operation/reset-permit counts return to zero before pool reuse.
- Playwright E2E: first entry and first-audio frame use the bound generation; child-local bounded evidence records the generation and synthetic lesson ID for the first `play_tts` enqueue only, and the parent compares it to bind metadata (the WS lesson URL is a secondary check); later normal playback frames do not affect this event. Closing the WebSocket, joining both read/worker goroutines, and canceling/draining any in-flight message operation release session and operation leases exactly once. After browser process exit, assert zero active session/operation/SQL/transaction counts before reset; after reset, assert reset permit count and issued/released totals reconcile to zero before generation two. Reset waits for this drain and refuses a late old-generation callback; no old audio/caption/state crosses into generation two.
- Failure assertions: no listener/JOURNEY on partial bridge installation; no handler reaches App before route wrappers, Serve readiness, and admission opening; failed bind/Serve or Serve return after readiness leaves no listening socket and closes admission; terminal child and sanitized trace/event logs on any incomplete cleanup.
