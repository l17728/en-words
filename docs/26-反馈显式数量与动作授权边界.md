# 反馈显式数量与动作授权边界

日期：2026-10-14。状态：有限明示语法与原文约束已实施、实际代码独立复核及定向通过，完整回归待验。候选32/64/28旧树评测及原服务独立恢复证据已保留，修复在该批次完成后实施；未改变标签或旧报告分母。候选新32未达90%且出现禁止计划动作，docs25的判分追加门不触发。

## 事实与根因

冻结CH-030原文“每日安排0节课”，候选返回`B_increase / target_words=0 / needs_confirm=false`，产品计划产生`adjust_words`两次。评测只计划、未对真实用户执行业务；这仍是安全门失败，不能因未写数据库而豁免。

`feedback.go`的频率前缀只识别一天/每天/一日，未含每日；数量句式只允许学/学习/上，未含安排；单位只识别次/遍/节，未完整覆盖课时。A/B的零同时表示“未给绝对词量”，PlanAt会保留既有相对调整政策。因此仅约束模型返回数字范围不能保证原文授权：错误分类能绕开原文频率限制，显式零也可能被当作省略量。

## 最小产品合同

平台验证原文约束，不重新猜测教学决策，不替换模型候选、不提高模型语义得分。候选保留，冲突置`NeedsConfirm`；未知/缺失数量由规则返回澄清，不能默认一天一次。`need_confirm`仍是现有任务终态提示，没有绕过边界的确认执行接口。既有“太多了/加量”的无显式数量请求继续交Agent相对调整政策。

1. 同一数量扫描用于规则、模型候选及规划边界。支持每日/每天/一天/一日，允许空白、安排/学习/学/上；课程单位按完整词优先识别课时/节课/次课/堂课/次/遍/节/课。不能把“0课时”漏掉或将“12次”截成2次。
2. 提取完整数量词元及其单位，保留负号、小数、半、区间和备选结构。合法频率只有整数1/2（包括一/二/两）；0/零、3及以上、溢出、负数、小数、半次、备选数量均不得变为配置/改期/难词写动作。无法可靠解析但明确要求数量的句子保守澄清/确认。
3. 区分课程频率与每课词量：“每日安排两节课，每课50个词”是两个独立维度；“每天50个词”不是每天50节课。词量显式0/零、负数、小数、超过50–100或备选值不得因A/B的零哨兵而转相对调整。显式合法绝对词量与A/B候选TargetWords不一致（包括返回0），也不得执行。支持“每课/每节课…词/个词/单词”以及现有明确词量表达；不把“半小时/10分钟/第2课/明天”误当数量调整。
4. 对完整原文检查，逗号/分号拆句不能掩盖另一无效数量或备选后缀。约束对象是用户要求的新目标；“以前每天三节课；现在每天一次”中的明确历史分句不作为新目标，也不能授权写动作。仅有历史叙述不得被转成调整，历史与新目标分界不清则澄清；本轮只锁定明确“以前/过去/曾经”历史标记与独立“现在/改为/以后”新要求，不承诺通用时态理解。发现显式无效的新目标时，按既有保守策略阻止该次反馈所有配置/改期/难词写候选；投诉上报和澄清保留。不尝试猜测用户希望忽略哪一项。
5. 合法频率也不授权改词量：仅有“每日安排两节课”却返回A/B时，应确认/澄清而非改词量。同理仅有明确词量却返回C不能擅改频率。多意图请求只允许有对应维度原文依据、数量一致的候选；独立“太多了；每天一次”仍允许已有A减量+C频率，不能因出现频率便一刀切禁用独立词量意图。
6. 直接调用PlanAt且携带Raw时也必须经过同一约束，不能依赖调用方总先Parse。历史不含Raw的程序化内部计划保持已有数字范围检查，生产反馈必须保留Raw。拒绝原因不写入原文，不扩展任意确认执行权限。

## 日志与可定位性

新增或复用结构化拒绝事件`feedback_constraint_rejected`，字段限`trace_id/module/event/intent_kind/constraint/reason`。`constraint`区分daily_frequency/word_quantity/dimension；reason使用固定枚举，如invalid_quantity、ambiguous_quantity、candidate_mismatch、unsupported_dimension。不记录原文、词面、模型完整返回或token。多次规划不得被记成业务成功，审计仍以真实事务提交为准。规则兜底与模型路径均可定位；若ParseRules无请求ctx，生产ParseContextAt入口负责带ctx记录，不能伪造用户trace。

## 实施顺序与独立评审

先等待当前候选批次完成并恢复原服务，再由后端代理补红测试、实施同一原文约束函数；主代理和架构代理复核，再交浏览器代理补真实UI用例。冻结新产品树后运行完整Go/覆盖率/race和浏览器回归。原候选32/64/28结果不可重命名为新产品结果；若重评，另存新报告并显式记录源代码hash变化。

独立架构初审结论：问题来自原文约束覆盖不足及零哨兵歧义，不应只给正则补“每日”就宣称同类清零。上述范围保持Agent教学决策归属，平台只拒绝未经授权或矛盾的副作用。完整自然语言理解不作承诺；本轮锁定已声明数量语法与跨意图写入边界。最终实代码评审、红绿证据和全量验收仍待完成。

主审结论：通过上述范围；允许保守澄清，但不得删除正向混合与明确历史分句合同。原因使用固定枚举，不输出原文；模型语义成绩和Agent教学政策保持原口径。E2E正负可放同一真实旅程，最终用例数以实际发现及执行结果统计，不预写完成数。实际代码复核将检查规则/模型/PlanAt三入口、零哨兵、维度匹配、日志脱敏和正向不误伤。
