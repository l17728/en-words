# First-Audio Guarded App Preparation SDD

Date: 2026-10-29
Status: design reviewed; implementation not started.

## Purpose and boundary

Compose the reviewed fixture, tracked SQLite connection, immutable guard controller, real `api.NewApp`, and per-connection PREFLIGHT checks under one test-only owner, implementing the startup/PREFLIGHT slice of docs/74. This is not protocol `bind`: it cannot return an API origin, create a listener, publish JOURNEY, or claim browser/classroom acceptance. All code stays in CGO-tagged `_test.go` files; no production route, flag, or binary dependency is added.

## API and ownership

Add `Prepare(ctx, runRoot, dbPath, runID, capability)` and idempotent `Close()` on one test-only owner. Independently compare the supplied capability to the child’s sanitized-environment capability with constant-time comparison; validate run-ID syntax and its exact run-directory binding. Require a private canonical run root with no symlink/reparse traversal, `dbPath == <runRoot>/matrix.db`, and no DB/WAL/SHM/journal sidecars before SQLite opens. Reserve the DB using exclusive create/no-follow semantics, verify it is a regular file below the same canonical root, and never overwrite or delete an existing path. Invalid/mismatched capability, root, or DB path must prove the injected SQLite-open function was not called.

A setup owner opens `store.Open`, seeds exactly the synthetic student, book, words, scheduled lesson, teacher-agent and system-agent identities via the existing fixture helper, installs the reviewed startup and lesson-probe triggers, validates schema/read manifests, and captures the full canonical baseline. Pre-seeding both agents is required so real `NewApp` has no missing-user writes. Close the setup pool and verify it unusable before constructing the guarded pool.

The guarded owner uses a unique tracked mattn driver. Its ConnectHook registers raw physical identity and installs the UDF/immutable authorizer. Open only the guarded GORM pool under DRIVER_PROBE; when `gorm.Open` returns, immediately close/drain driver-probe admission and publish STARTUP_PROBE before any `NewApp` call or SQL. Assert no `NewApp` statement runs in DRIVER_PROBE. Run the real synchronous `NewApp` only under STARTUP_PROBE; reject a nil App or non-nil `app.StartupError`, verify the startup transaction is back in autocommit, assert no startup row-guard callback or unexpected write occurred, and verify the full snapshot equals baseline before publishing PREFLIGHT monotonically. The `newApp` dependency adapter returns `*App`; tests inject both a normal App with `StartupError` and a panic. Fix pool capacity at three. Pin all three `*sql.Conn`s simultaneously before probing, prove they map to three distinct live registry identities, then consume exactly one context-bound one-use challenge and complete one rollback/readback receipt per identity. The success invariant is three hooks, three distinct receipts, three registry registrations, zero unexpected denials, exact baseline equality, and active phase PREFLIGHT. Do not return DB or setup handles. Metadata is bounded IDs, phase/generation, digest, counts, elapsed time and status only.

## Test seams and listener boundary

Use an unexported dependency bundle with production defaults for exclusive file reservation, setup open, fixture/trigger installation, guarded driver/pool open, `NewApp`, phase publish/drain, per-connection probe/rollback/readback, snapshot, registry reconciliation, listener factory, and cleanup. Tests inject one failure at a time. Recover `NewApp` panics at the owner boundary, map them to a sanitized category, and run the same cleanup path. The owner listener factory is the sole listener creation seam for later bind; this preparation path must not call it. `NewApp` itself receives only a DB and has no network listener dependency. Assert listener-call count zero and no JOURNEY phase on success and every failure.

## Failure semantics and cleanup

All invalid input fails before SQLite open. Setup/fixture/manifest/setup-close failures never create the guarded pool. ConnectHook/identity/count mismatch, NewApp nil result, non-nil `StartupError`, or panic terminalizes and does not retry. For a NewApp failure in STARTUP_PROBE, inspect the exact tracked driver connection's autocommit state without SQL first. Only if it is confirmed true may the owner perform the bounded startup-manifest snapshot comparison, then close. If autocommit is false or unknown, issue no further SQL (including snapshot reads); terminalize and physically retire that exact raw connection so SQLite rolls back on close, verify underlying `Close()` and registry removal, and require parent kill/reap if retirement is uncertain. Never use the PREFLIGHT-only cleanup permit in STARTUP_PROBE. For later PREFLIGHT probe failures, permit only the existing authorized PREFLIGHT rollback; never grant broader cleanup SQL. Close pins and pool, then prove each uncertain raw driver connection’s underlying `Close()` succeeded and its exact registry identity was removed. `pool.Close()` or `*sql.Conn.Close()` alone is insufficient. If physical retirement is uncertain, terminalize and require the isolated-run parent to kill/reap the child before any retry or artifact cleanup. Confirmed cleanup and uncertain cleanup are separate result categories.

## Required tests and review

Success test: actual migrated schema and `NewApp`, exact three live identities/probes/receipts, setup pool closed before guarded pool open, no unexpected writes, unchanged full snapshot, PREFLIGHT only, listener calls zero. Negative tests: malformed/mismatched capability; existing/symlinked/out-of-root DB and each sidecar before open; fixture/trigger/setup-close failure; hook missing/duplicate; fewer/more/reused physical connections; NewApp nil result, `StartupError`, and panic (including verification of STARTUP_PROBE autocommit/rollback without using the PREFLIGHT cleanup permit); phase/drain timeout; missing/duplicate/stale receipt; probe/rollback/readback/snapshot/registry fault; close failure; idempotent close. Assert sanitized category, terminal phase, rollback/retirement evidence, no listener/JOURNEY, and parent kill/reap requirement on uncertain close. Logs include trace/run ID, module/event, phase/version, bounded counts/digest, error category, elapsed time and cleanup outcome; never capability, password, filesystem path, SQL, or row contents. Obtain architecture, security, backend and test-quality review before implementation and again after code.
