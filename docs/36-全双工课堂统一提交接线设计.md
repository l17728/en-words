# 全双工课堂统一提交接线设计

状态：2026-10-15已完成架构/AI-Agent、后端/安全、前端/测试交叉评审，主审批准隔离SQLite与mock协调层按片开发；不是已交付说明。G1验收期间保持产品代码冻结，保存该阶段证据后再开始接线。本文落实33§6的下一阶段协调层；已验证普通WAV输入，不等同原生双工协议可用。

## 1. 范围和实施切片

下一阶段可使用确定性转写/Judge/媒体替身，完成真实HTTP/WS、SQLite和浏览器的完整课堂提交/恢复。保留D-20两次机会、D-21教学/跟读/最终测试、现有Teacher/System决策及配置。不新增模型自主工具，不把预览当最终输入。

按以下顺序审查和实施，每片有单测/集成红绿及相应E2E后才合并：

1. 持久试点课模式、逻辑身份及所有入口分流，先无网络模型。
2. 独立状态机候选、冻结Teacher计划和tx-bound工具执行器；禁止活动Room提前变化。
3. checkpoint/兼容snapshot/审计/receipt/outbox单事务，发布失败可恢复。
4. completion job与既有结算衔接、重启/重连/模式排空。
5. 同课旧文字和模拟双路确认完整旅程、多学生故障矩阵。真实音频另过34质量门。

首版只允许显式迁移的隔离SQLite试点；不把无DB旧内存模式当持久exactly-once实现。非试点课仍走原handler。不能在单课中部分启用新提交又保留旧写入口。

## 3. 快照字段核查与独立候选

`classroom.State`（classroom.go:169）已包含且Snapshot深复制：

| 字段组 | 候选与恢复要求 |
|---|---|
| Config、LessonID/BookID/StudentID | 冻结课次配置及owner，不能恢复时读当前配置悄悄改变本课 |
| Phase、GroupIdx兼容字段、WordIdx、TtsSegIdx、RepeatCount/RepeatNudged | 保留段位置和跟读事实；废弃兼容字段不新增教学用途 |
| QuizQueue/QuizIdx/QuizSeq/AnswerStage/PendingText、InReteach/ReteachSeg | 精确保留题目及机会；PendingText不代表已提交答题 |
| InReview/ReviewList/ReviewIdx/ReviewSeg | 保留轻量回顾位置 |
| Consec/Judged/Mastered/ReteachN/FirstWrong/FinalWrong/Streak/StreakBest/AnswerMs | 深复制所有map/slice，失败不能泄漏对原统计的修改 |
| StartedAt/Paused/Finished | 保留教学计时和状态；Finished不等价已完成持久结算 |

Machine还有不在State中的words/wordByID、cfg、clock、acts/lastActions、usedWrong。候选必须使用冻结词条及顺序重建；采用生产Snapshot/Restore校验，待发actions单独冻结，不把旧动作再次Drain。当前usedWrong在classroom生产代码仅声明及初始化，不能把它误当已持久化统计来源。

实际核查Restore（classroom.go:309）：校验位置/config、深复制State、兼容修正ReviewSeg及nil集合后直接赋state；不调用RecoverDelivery/RecoverJudgment、不生成恢复动作，但也不清既有acts。因此候选必须由全新Machine构建再Restore，不能在带待发actions的旧Machine上覆盖。Hub.Enter另行RecoverJudgment、Join另行RecoverDelivery并重置phaseSince；这些是恢复策略，不可在每次普通候选复制时执行，否则会重播或刷新超时。须分别测试纯复制无动作、真正重连按一次恢复义务产生动作。

Room（hub.go:35）额外状态不能靠复制mutex/指针解决：

- **持久教学派生事实**：encourageCounter、已决定teacherPending/teacherText、phase计时锚/暂停剩余量、逻辑input_revision、题目机会、checkpoint_version、输入租约是否已用。须纳入带schema版本的协调层checkpoint，或证明可由已提交事实确定重建并测试。
- **输出事实**：seq、lastPhase、lastActions、已生成话术及段义务落outbox/结果；重发不再选择话术或递增鼓励计数。随机话术不得在重放时重新抽取。
- **纯进程态**：mutex/app/clients/currentCli/pendingJudge.cancel/inputContext/FeedbackCh不持久化、不浅复制；创建新的运行容器。words及meaning slices做独立冻结，voiceParser只按受信配置创建。
- **授权生命周期**：epoch/连接代次与retired由当前授权决定，不能从旧checkpoint反向复活；新连接epoch不重置持久题目进度/input_revision。数据库CAS最终仲裁跨进程竞争。

建议新增`DetachedLessonState`而非克隆整个Room；包含Machine.State、必要Room教学事实、词条/config版本和不可变计划。Plan不执行emit、saveRuntime、callAgentTool或配置修改。

## 4. 单提交与工具事务

协调流程：短Room锁捕获已提交版本/当前授权→锁外Judge和Teacher候选→BeginCommit检查共享8秒计算截止→单pinned事务→短Room锁发布。取消有独立signal/lease，不等该长链；事务内没有模型/TTS/WS调用。

`callAgentTool`（agenttransaction.go:27）内部取得agentWriteMu并开Transaction，禁止从CommitDecision调用。新增内部`ExecuteTeacherPlanTx(ctx, tx, trustedTask, frozenPlan)`：

1. 复用teacherEffects的深复制facts、scope/schema、PlanEffects索引匹配以及单次共享工具预算；不接受模型提供工具名/参数计划。
2. registry只装本次允许的Teacher效果与必要受信能力；所需repo全部绑定tx，不调用全局a.DB或重新取池；不再次获取agentWriteMu。
3. AuditEntry先缓冲，再与所有状态一起写；事务失败不得发布成功审计。失败尝试只可固定摘要日志，不混入已提交业务receipt。
4. 现有Teacher话术如需工具/记忆，必须明确列入本次冻结计划并绑定同tx；不能把emitTeacherUtterancesContextLocked留在事务后再自行写入。

事务顺序：取得writer→查询owner/有效课次与持久版本→先查询相同decision receipt（相同fingerprint才重放）→逻辑题目/机会CAS校验→工具/审计→checkpoint与runtime snapshot兼容镜像→receipt/outbox/必要completion job→commit。使用既有atomicConnection失败清理合同；不得任取连接ROLLBACK。

G1现有checkpoint只有State JSON/版本，receipt/outbox也是基础结构；实施必须显式版本化迁移补足schema、逻辑身份、结果摘要、投递字段及completion job，不能宣称已有组件已满足完整字段。receipt唯一lesson+epoch+input_revision只是防同epoch重复；跨重连靠持久逻辑题目/CAS禁止对已完成机会再提交。

同一计算预算8秒涵盖排队/声学复核/Judge；事务耗时另计，不因慢commit回报“没有保存”。未知结果保持committing，查询原decision；只有确定rollback才可结束为未提交。

## 5. 发布、旧文字回退与恢复

发布必须校验Room仍活动、owner一致、版本未倒退；旧epoch输出不重放。不可发布时保留receipt及outbox，返回已保存待同步。客户端按decision_id/effect_index去重，不能把`event_processed`当成绩持久成功；新合同显式decision.committed及结果状态。

outbox按课次版本/效果索引有序，claim/delivery重试有界；delivery确认只说明收到，playback ACK另属段完成。重连加载已提交checkpoint，再为当前授权恢复未完成段的新lease；旧lease失效。物理声音不承诺exactly-once，允许中断段重播，但不重复工具、机会和结算。

试点文字回退使用同coordinator：输入直接标来源typed、无需虚构两路一致；提交与语音争同一逻辑机会。单轨失败只转文字/确认，不静默回旧handler。回退旧模式必须持久关闭新输入、排空或解析所有committing/outbox/job、保存兼容snapshot后原子切换模式版本；活动课不能仅关环境变量就绕过门。

重启：读取模式→严格schema/owner验证checkpoint→未提交输入不自动评分→查询未知decision→恢复outbox/job。破损checkpoint失败可见，不能从陈旧snapshot无声恢复。兼容镜像仅同事务更新，不能成为另一个可独立演进写源。

## 6. 结算job

最后一题事务保存完整答案、最终State/Result指纹和唯一lesson completion job，receipt标答案已存/结算待完成。worker在Room/提交锁之外调用`commitLessonWithAgents`（lessonexecution.go:29），复用settled owner/fingerprint幂等检查。

现有结算锁序completionMu→agentWriteMu→a.mu，不与新提交门嵌套。结算自身仍有旧GORM Transaction；纳入试点前必须补真实COMMIT失败/污染连接恢复验证，必要复用安全pinned原子入口，而不是认为上层job自动修复底层连接问题。

job同时冻结Result/State及System计划版本与fingerprint；重试从job读取，不从当前Room重新计算输入或使用升级后的决策表重规划。现lessonexecution事务内再次检查settled的防重复逻辑保留。job领取使用claim_token+有界claim_until；done与summary outbox唯一写在独立事务完成，并核对当前claim_token，过期worker不能覆盖新worker结果。结算已提交但claim丢失的worker停止标记，后继worker凭settled恢复。不得仅凭进程mutex宣称跨实例结算唯一。

结算成功后独立事务标job done并写summary outbox；结算commit后标记前崩溃重试读取settled，不重做memory/cards/config。job pending失败可重试；没有已提交报告不得发送summary完成。禁用账号时禁止投递/发声，但已有提交事实及必要最终一致处理不能静默删除。

## 9. 交叉评审收敛：控制迁移与答案占用分离

本节替代前文笼统的“所有Transition使用同一个duplex receipt”解释。**G1 `duplex_receipts` 的lesson+epoch+input_revision唯一约束不能用于整课协调层**：同一答题机会内可发生多次暂停/恢复、播放ACK及提示，不能为这些展示/控制事件递增逻辑输入版本。G1组件保留，不原地改变已冻结合同；下一阶段使用显式新表/版本。

### 9.1 可实施schema（新增隔离试点迁移v2）

| 表 | 列与约束 |
|---|---|
| `classroom_pilot_states` | lesson_id PK，student_id/book_id，schema_version=2，mode（pilot/draining/legacy），checkpoint_version uint64，logical_input_revision uint64，question_key string（题目ID/跟读义务及机会编号），phase string，state_json、room_facts_json、config_fingerprint；rev/version不得溢出 |
| `classroom_transition_receipts` | (lesson_id,command_id)复合PK，student_id，request_fingerprint，kind，from_version/to_version，logical_input_revision，decision_id，result_json，committed_at；同command不同fingerprint固定conflict。decision_id服务端生成并唯一，用于outbox关联 |
| `classroom_answer_claims` | (lesson_id,logical_input_revision)复合PK，student_id，question_key，command_id、decision_id唯一引用，answer_kind（quiz/repeat/skip/timeout），result_fingerprint；不含连接epoch，禁止换连接绕过机会占用 |
| `classroom_effect_outbox` | (decision_id,effect_index)复合PK，lesson_id/student_id，schema_version，checkpoint_version，kind，payload_json，delivery_status、attempt_count、next_attempt_at；payload为已确认效果，不含可执行工具参数 |
| `classroom_completion_jobs` | lesson_id PK，student_id/book_id，result_state_json、frozen_plan_json、plan_version、fingerprint，status(pending/running/done)，claim_token、claim_until，attempt_count、next_attempt_at、last_error_code；只在最终教学状态提交事务插入；done和summary outbox同一独立事务唯一写并校验claim_token，详§6 |

沿33要求同事务写runtime兼容snapshot和audit_logs；新表不得与G1 checkpoint各自写同一课。**当前首片以§15为准：显式迁移只创建完整schema和版本标记，不读取旧runtime生成试点基线、不升级任何已有Lesson。**新v2基线只能与新Lesson/pilot reservation同事务生成，checkpoint version从1开始；未开始时logical revision=0、无输入机会，首次实际输入机会分配1，协议输入仍必须正数。旧草案“未启试点且无活动请求即可迁移旧课”已撤销；活动迁移/旧模式排空另作后续设计。已有v2只按明确版本升级，不重置rev。

Transition事务：先按owner查询已存在command receipt并核fingerprint（重放不受当前phase变化影响）；未存在则取得writer并重验owner/课次/mode/version/logicalrev/允许phase→必要claim→tx工具与状态→receipt/outbox/job→commit。receipt重放查询仍必须鉴权，不能因完成或换连接放松owner。

### 9.2 logical revision与claim规则

- 新的实际答题/跟读机会分配持久logical_input_revision；preview、ASR final、judging显示、TTS段、暂停/恢复均不递增。纯控制Transition只递增checkpoint_version，不插answer_claim。
- quiz最终判分（含wrong）消费本机会并插claim。第一次wrong进入重教后，为下一次可作答机会分配新rev；第二次wrong或已确认“不会”等沿旧策略结束本题，下一题使用新rev。不得提前用相位变化创建额外机会。
- ASR分歧、needs_confirmation、模型超时/协议失败不插claim、不消费机会；保留原逻辑rev。学生明确确认所说文字后才生成新的已确认提交请求，仍争该rev，确认不是自评正确。
- 跟读识别失败但原策略允许继续听，不插终态claim；跟读成功/跳过/最终超时推进才占用该跟读义务rev。提示性timeout不占claim；实际推进/判定的timeout必须与学生回答竞争同一claim。
- 教学控制若实际使当前输入义务失效（经批准跳过/换题）必须原子占用或关闭当前义务并分配新rev，不能把所有控制一概当不影响输入。普通暂停/恢复/播放ACK不消费机会。
- 用户撤回未提交草稿仅失效该输入attempt/音频lease，不能自动获得新机会rev或刷新租约。需要重说时沿原rev的有界恢复规则；已committing只能查receipt。

### 9.3 REST/WS与可见状态字段（新试点合同）

新增受ownLesson学生鉴权的接口，旧课堂端点对pilot课只调用同coordinator，不旁路：

- `GET /classroom/lessons/:id/decision-state`：返回schema_version、mode、checkpoint_version、logical_input_revision、question_key、phase、active_input状态以及该逻辑机会已提交receipt（若有）。用于刷新/重连恢复，不要求客户端仍记得command_id。
- `POST /classroom/lessons/:id/transitions`：`{command_id, connection_epoch, expected_auth_generation, expected_checkpoint_version, logical_input_revision, question_key, kind, payload}`。kind精确枚举，payload按kind严格schema；typed提交为`answer.text`及`{text}`。控制仅允许既有控制白名单；统一使用`effect.ended`，payload精确为`{decision_id,effect_index,segment_id,lease_id}`，均引用服务端已签发播放义务；不接受旧`tts.ended`别名。客户端不能指定judge结果、Teacher工具或next_revision。
- `GET /classroom/lessons/:id/decisions/:command_id`：只读返回committed receipt或明确not_found；not_found不自动证明某个仍在执行请求已经rollback，须合并当前active_input状态判断。
- WS试点控制帧使用相同字段及校验；`state.sync`请求返回同decision-state。新增`decision.committed`带command_id/decision_id、from/to checkpoint_version、consumed_input_revision、当前logical_input_revision、question_key、result、settlement_status。`decision.rejected`带固定reason、retryable、已知rollback标志；未知结果使用`decision.pending`，不能伪装rejected。

协议中connection_epoch仅授权/旧帧拒绝，不进入answer_claim唯一键。服务端自动生成timeout等command_id，按课次/逻辑义务/触发序号持久幂等；不能每次timer扫描生成新的有效提交。

### 9.4 前端提交与恢复门

typed/voice共用同步gate，捕获逻辑rev/question及稳定command_id。ASR final、event_processed、同turn重放均不能解锁教学提交；已知rollback或decision-state明确允许重新输入才释放。committing未知保留原稿/ID，禁止编辑造新ID；只查询，不自动重发写操作。查询采用有界退避和明确错误/手动查询/返回入口，不能永久spinner；离开页面不意味着取消数据库提交。

needs_confirmation展示最终候选文字与明确确认/编辑，说明确认的是“我说的内容”，不是“答案正确”。进入此状态即终止原自动语音提交、永久撤销该attempt迟到final权限，并持久恢复一次原作答余量。确认请求绑定原rev和候选指纹；编辑使用新command明确表示文字改写，不能编辑绕过已占机会。人阅读期间沿恢复后的原作答时限，不使用模型8秒计算预算。

state.sync从服务端恢复当前逻辑机会及receipt，不依赖丢失的浏览器内存ID。旧epoch已提交事实可以在新授权下展示，输出必须使用当前新lease，不能把查询receipt等同恢复旧音频。结果展示、outbox接收、实际播放ACK三者分别处理。

### 9.5 增补验收阻断

CD01增加：同rev两次resume/多个ttsACK可各自持久成功却零claim；同rev换epoch答题仅一claim；控制请求复用ID不同payload拒绝。CD03增加：not_found但事务仍执行不得解除gate；断网查询失败可见且无自动重写。CD04增加：浏览器清内存刷新仍按state.sync恢复receipt；旧epoch事实可读、旧lease不可播放。CD08增加：ASR冲突零claim、第一次wrong消耗一次并开启第二机会新rev、跟读未通过继续听不耗终态claim。所有新增REST/WS鉴权、schema/大小限制、日志与取消合同随实现补入03/SDD后再验收。

## 10. 授权接管与独立pilot界面

`classroom_pilot_states`补充持久`auth_generation uint64`、`connection_epoch string`、`retired bool`。新增内部`ClaimPilotConnection(ctx, owner, lesson, expected_generation)`：同一writer事务重新查账号/课次有效性、CAS递增generation并生成新epoch、失效旧输出lease；不递增logical_input_revision、不消费机会。网络连接成功不等于取得授权，返回接管结果后才接收写事件。溢出或竞争失败明确重查。禁用/退休同样持久撤权递增generation，其他App不能凭旧currentCli继续写。

所有新Transition增加`expected_auth_generation`，writer事务同时比较generation/epoch/owner/课次/version。旧连接即使获取最新checkpoint_version仍不能提交。只读receipt重放可在当前owner授权下返回历史事实，但绝不授旧lease。CD01/04必须包含两个独立App：B成功接管后A携最新checkpoint版本+旧generation写入仍被拒绝；A旧receipt可只读核实，不能发声。

前端优先独立`PilotClassroom`路线，不把旧Classroom的AnswerFlight直接改为新语义。旧实现revokeInput会reset AnswerFlight，phase变化/重连会清输入；新界面拆分：

| 状态对象 | 字段 | 生命周期 |
|---|---|---|
| LogicalSubmission | logical_input_revision、question_key、command_id、candidate_fingerprint、frozen_text、status | idle/capturing/needs_confirmation/submitting/committing_unknown/committed/rejected；只有服务端事实解决提交，不能由phase/媒体撤权清空 |
| MediaReadiness | auth_generation、connection_epoch、input_revision、capture_attempt_id | 断线/换号或auth_generation、connection_epoch、input_revision、capture_attempt失效即时撤采集；单纯preview/judging展示turn变化不使逻辑输入失效，真正暂停另撤采集；不能反向改LogicalSubmission已提交状态 |
| OutputObligation | decision_id、effect_index、segment_id、lease_id、auth_generation | received/playing/ended/interrupted/failed；只ended可提交对应教学段完成Transition，其他状态不假ACK |

新增输出帧`effect.ready`携上述完整身份、文本/播放参数及checkpoint_version。客户端`effect.received`仅确认收到；`effect.playing`为实际开始观测；`effect.ended`才请求结束该段，服务端校验当前lease及未完成义务并幂等提交；`effect.interrupted/failed`只撤输出/记录恢复事实，不当tts_finished。ACK使用各自稳定command_id；重复收到effect不得新建第二次播放，实际中断恢复以服务端新lease明确授权。caption局部lease可复用实现，但不是这些服务器身份的替代。

|---|---|
| answer.text / confirmed.voice（quiz） | schema及Judge后争answer_claim；一次最终结果消费本机会 |

## 11. 显式重试的确定方案：固定机会revision、不补发语音时长

选择保持logical_input_revision等于当前教学输入机会的稳定序号；用户重试、撤草稿、断线、换连接均不改变它。answer_claim因此直接以lesson+logical_input_revision防重复，无须另造可漂移机会键。question_key中的题目与attempt只用于交叉校验，不能由客户端填写新值获得机会。

同rev持久保存`voice_lease_used`、`voice_capture_deadline`、`voice_confirmation_deadline`、`original_answer_remaining_ms`及`capture_attempt_generation`。首次有效起音由受信Transition授一次租约；输入最长15秒，第一次endpoint冻结确认截止为其时刻+8秒。后续重试不能重新计算更晚的截止，不能重复冻结原答题剩余时间。无endpoint时输入截止就是原捕获截止；确认故障后不倒退到获得另一完整15秒。

| 当前状态+显式动作 | 受信事务结果 | 可用交互 |
|---|---|---|
| 首次有效起音且lease未用 | 标used，冻结原余量/捕获截止，attempt_generation+1 | 本次采集 |
| 捕获失败、尚未endpoint且原capture deadline仍有剩余；学生点击重试 | 同rev CAS，确认没有committing/claim，attempt_generation+1、撤旧capture，保持原绝对截止 | 仅剩余采集时间；UI明确显示剩余量，不显示“重新获得15秒” |
| 已endpoint、分歧/ASR协议失败或学生明确转文字 | 同rev持久终止自动语音提交，永久撤旧attempt；一次性恢复原作答余量，不重新授捕获窗口 | 首版不再开麦；明确文字确认/编辑，阅读时限为恢复后的原作答余量，不是endpoint+8秒 |
| 捕获或确认预算耗尽 | 标该rev语音租约耗尽，恢复一次原作答余量；重复timer/重试不再次恢复 | 文字作答/原有退出；麦克风按钮禁用并说明本题改用文字 |
| needs_confirmation学生确认/编辑文字 | 新command、同rev及候选指纹CAS；原作答时限内显式提交才授新的Judge计算8秒 | 文字等价输入进入Judge/提交，不等于答对；原语音latefinal永久无权，lease仍used；无终态前不claim |
| committing_unknown时重试/改稿 | 拒写，仅允许state.sync/receipt查询 | 显示待确认结果，不能重说或新建command绕过 |
| 确定rollback后的手动文字再提交 | 同rev、尚无claim且课次/原作答余量有效才准许新command | 不自动重放；语音租约仍used，不复活旧音频 |
| 已有claim或新题/下一次正式机会 | 旧rev仅可读receipt；Teacher产生新机会时原子递增rev并初始化新机会租约 | 新机会才有新语音预算 |

这是一项保守首版易用性边界：失败后“重试”不承诺总能重新录音；UI必须具体区分“剩余时间内重录”和“改用文字”。后续若要求同机会无限或额外完整录音，必须另改策略并评审，不在实现中借重试悄悄增加时间。新增CD03/CD08验证跨连接/重复点击/噪声不能刷新截止，显式剩余内重录可行，耗尽后文字仍走相同claim且仅一次恢复原余量。

### 11.1 主审可用性修正与精确文字确认合同

采纳主审修正：旧草稿把人确认也限制在endpoint+8秒内，会使慢ASR后几乎没有阅读时间，现撤销该限制。8秒只约束每次受信计算，不是人阅读窗口；新的8秒仅由新一次显式用户文字提交触发，不能由噪声、partial、自动重试或迟到final触发。

新增kind `answer.confirm_text`（quiz）及`repeat.confirm_text`（跟读），payload严格为`{text,source_candidate_fingerprint,confirmation_mode}`，confirmation_mode只允许`accept`或`edit`。accept时text须与服务端保存候选一致，edit保存显式改写事实；quiz仍经意义Judge，跟读沿38的EvaluateRepeat（零LLM/不匹配释义），确认本身不代表答案正确。服务端原子校验当前auth、同logicalrev、候选状态needs_confirmation、未claim及恢复后的作答截止。新command进入待计算占位后，旧command重发仍查询原receipt/状态；不得并发启动多个计算。若用户等待超过原作答余量，则沿既有timeout竞争/推进，不能再由确认补回完整作答时间。

持久增加`voice_attempt_terminal`、`answer_budget_restored`及`restored_answer_deadline`：进入needs_confirmation/故障退出自动语音时CAS置terminal；仅answer_budget_restored=false可按冻结余量设一次deadline，重复事件保持原deadline。显式文字提交不重置此deadline；判分超时或rollback后恢复交互仍使用已存在deadline，过期立即依原策略处理，不能反复点击累计延长时间。确认中的8秒计算临界区以与timeout的统一提交门仲裁，已受理在途计算和timeout不能各消费一次机会。

新增回归：ASR用时接近8秒后仍有原作答余量可阅读确认；确认点击才产生新计算deadline；重复needs_confirmation/跨连接重发不延长余量；原语音latefinal在用户文字提交前后都被拒；accept/edit同机会只一个claim；原余量耗尽时确认被明确拒绝或返回已提交timeout结果，无假成功。

## 12. 待计算占位、崩溃与结果未知

新增`classroom_active_commands`：(lesson_id,command_id)复合主键，student_id、request_fingerprint、kind、logical_input_revision、question_key、auth_generation、capture_attempt_generation、status（computing/committing/committed/failed）、claim_token、worker_generation、compute_deadline、claim_until、decision_id、failure_code、created_at/updated_at。`classroom_pilot_states.active_command_id`指向当前唯一在途计算/提交，空值表示无在途；占位与state指针在同writer事务CAS。失败历史保留，不能删行让同command重新Judge。

1. 接受新输入前先查transition receipt及active_commands同ID。receipt存在返回事实；active同ID同指纹返回状态，不第二次调用Judge；不同指纹冲突。只有无active占位、无机会claim且授权/题目/作答期限有效，才原子创建computing行和state指针。同一课首版最多一个计算提交，不按协议/输入通道分别排队。
2. compute_deadline固定为本次受信计算启动+8秒（语音沿既有共享剩余截止），不可续期。claim_until是进程执行所有权期限，固定不超过compute_deadline加一个明确的短提交清理余量（首版5秒）；不是教学作答时限，也不授更多模型计算时间。worker_generation及随机claim_token标识持有者；旧worker不能通过更新期限复活。
3. Judge返回后，BeginCommit所在writer事务核claim_token、worker_generation、auth_generation、active指针、未过compute_deadline及当前逻辑机会，再把状态置committing并写教学结果/receipt/claim/checkpoint/outbox。状态committed及清active指针与结果同事务。慢DB提交不在事后用计算超时伪称未写。
4. 请求取消或网络断开时，客户端显示结果待确认；不能只凭ctx canceled或receipt not_found删除占位。已知事务rollback后，由同owner/token的短writer事务将active行标failed、清state指针；保留原ID终态，不自动再次计算。原作答deadline不重置。
5. 重启/接管回收仅在claim_until已过、成功取得同writer门、重读receipt/answer_claim/state后进行。若receipt存在，同步active committed并返回原事实；若本机会由另一command占用，标当前失败/已被替代并返回对应提交；若均无且active仍是过期token，CAS标failed并清指针。持有SQLite writer意味着其他旧提交不能同时越过这一线性化点；旧worker以后拿到writer必须重核token/status，失败后不得再写或发声。
6. 未过期的孤儿占位保持pending，state.sync返回固定reason和查询建议，不无限spinner；超过上述有界所有权期才可回收。回收不能重新运行同command；用户在当前仍有效机会内明确新command才可再提交。任意DB不可用时不能证明rollback，界面保持可见未知状态并可返回/手动查询，不假解锁。

`decision-state.active_input`精确返回`{command_id,logical_input_revision,question_key,status,compute_deadline,claim_until,result_known,can_submit,failure_code}`，不返回内部claim_token/worker_generation。committed时附receipt；can_submit必须由持久占位/claim/授权/截止共同计算，前端不能从not_found自行推断。新增CD03/04：计算占位后kill、计算完commit前kill、COMMIT成功响应丢失、租约过期旧worker复活、两个App同时回收；均不得二次Judge同command或重复机会。

## 13. kind来源与payload白名单

所有HTTP/WS封套拒unknown/null/重复字段及非法UTF8；command_id、epoch、question_key等标识1–128字符且无空白/control，数字字段为非负整数（revision/generation/version必须正数）。正文≤16KiB，text按Unicode字符1–2048且非空白；不能依靠Go零值补required。enum仅接受本表精确字符串。以下是新试点协议，不改legacy已发布字段合同。

| kind | 来源 | required payload与额外校验 |
|---|---|---|
| answer.text / repeat.text | 学生REST/WS | `{text}`；服务端验证当前quiz/repeating用途；重复请求沿原command |
| answer.confirm_text / repeat.confirm_text | 学生REST/WS | `{text,source_candidate_fingerprint,confirmation_mode}`；fingerprint=64位小写hex，mode=accept/edit；候选必须属于当前学生/机会且needs_confirmation；accept精确匹配服务端候选 |
| control.resume | 学生REST/WS | `{}`；只当前paused课，授权与版本相符 |
| control.next / control.skip | 学生REST/WS | `{}`；沿现有voiceParser/状态机相位许可，不新增quiz跳过权限，不允许调用者携next题号 |
| effect.received / effect.playing / effect.ended / effect.interrupted / effect.failed | 学生REST/WS | `{decision_id,effect_index,segment_id,lease_id}`；effect_index≥0，所有标识受限；failed另required `reason`=playback_error/watchdog/canceled；服务端核owner、当前generation/lease、确切效果索引。received/playing只观测，不能推进；ended仅首次有效完成义务推进 |

### 15.1 由同事务新建事实证明资格

不另设可授予旧课的资格表。`classroom_mode_reservations`增加`creation_nonce`（pilot非空且唯一）、`creation_version`（pilot固定正整数版本）、`creation_fingerprint`（受信创建计划的冻结canonical SHA256），student_id与同事务新Lesson owner一致。**legacy三个创建字段均为SQL NULL，不是空串/0**；creation_nonce采用普通UNIQUE索引，SQLite允许多个NULL。CHECK约束要求legacy三项全NULL、pilot nonce/fingerprint非空且版本为受支持正整数，不能靠Go零值代替。`classroom_mode_metadata`为显式迁移创建的单例表，`id=1`主键、`schema_version`固定正整数，作为全部模式分配入口的writer门。迁移完成时必须有该单例行，缺失或版本不符fail closed。

### 15.2 固定writer门的实际顺序

metadata/reservation及v2表必须由显式迁移先完成；运行请求不能DDL懒创建后绕过模式检查。`atomicConnection`的deferred Begin本身不是取得writer：在同一固定连接事务中，**第一条业务SQL**执行`UPDATE classroom_mode_metadata SET schema_version=schema_version WHERE id=1`，检查SQL成功且单例存在后才读账号/owner/模式/nonce及计划。所有legacy首次Enter与专用pilot创建共用该writer门，不通过原pool在事务内查询；后续读取再核schema_version匹配。原有/普通课首次Enter没有reservation一律插legacy，不需要猜测“是否足够新”。

writer取得失败/取消直接返回固定失败，不退回旧路；版本不符或要求传入已有课次创建pilot均拒。COMMIT错误沿固定连接清理合同，未知结果只能查原nonce/reservation，不发布Room。双独立池测试必须用真实并发证明metadata writer门序列化创建与Enter，不能只检查SQL文本或依赖进程内mutex。

### 15.3 未启试点旧库与试点schema损坏的判别

显式迁移通过固定连接事务创建完整v2表/索引、metadata单例，并在既有`runtime_records`写唯一key=`pilot/schema/version`，值为严格JSON `{schema_version:2,migration_id:<服务端固定标识>}`；同事务提交，任一失败全退。该marker不走课堂snapshot恢复，也不由ENWORDS_DUPLEX_PILOT生成/删除。首片不自动迁移旧库，不在docs37 startupModels中加入这些表。

NewApp在同一一致性读取事务中核marker、所有预声明v2表/索引/约束及metadata版本。精确四种结果：

| 事实 | 启动/入口行为 |
|---|---|
| marker不存在且全部v2表不存在、无G1已提交课堂事实 | 明确`legacy_unmigrated`，允许旧课堂正常启动；不要求用户先迁移才能运行新版 |
| marker合法且完整v2 schema与metadata版本一致 | `pilot_schema_ready`，按每课reservation分流；环境flag仍只控制预检，不授教学权限 |
| marker存在但缺表/缺索引/metadata缺失或版本不符，或marker JSON无效 | 固定`pilot_schema_invalid`导致StartupError；不得fallback旧snapshot或自动补空表 |
| marker不存在但任何v2表已存在（即使空），或G1 checkpoint/receipt已有课堂事实 | 固定`pilot_schema_invalid`，显式修复/迁移后再启动；G1空测试表不等于v2且不能凭存在当可教学 |

读schema/marker失败不是“不存在”，同样fail closed。该检查必须在任何可能自动修补pilot表的迁移之前完成；本轮旧22表正常迁移不得悄悄创建v2或marker。

为避免一个支持版本App启动时缓存legacy、另一进程随后显式迁移导致新pilot课误走旧路，**未迁移分支的首次Enter也不能只信启动缓存**：在既有runtime_records上先执行`UPDATE runtime_records SET key=key WHERE 1=0`取得SQLite writer，再同事务复查marker与v2存在性；仍完全未迁移才允许旧Enter，若已完整迁移则立即在当前已持writer的事务执行§15.2模式校验（不嵌套新事务），不生成旧Room，异常则拒绝。已迁移分支仍直接以metadata单例writer门开始。此兼容检查只用于课次入口；任何旧课永不能转pilot，因此已创建legacy Room不会被另进程换模式。显式迁移推荐停全部App后执行，但安全性不得依赖人肉“没有活动进程”的推断。

新增红例：两个legacy课以NULL nonce正常并存；两个pilot同nonce只一课且跨owner重放被拒；未迁移旧DB正常启动；有marker缺表/无marker残表/坏marker/metadata缺行均拒绝；迁移事务中断无半marker；App A初始legacy，App B完成迁移并创建pilot后A首次Enter只能走新门。上述合同只作用未来docs36实现，不改变当前G1或docs37生产代码。

### 16.1 内部创建计划与初始化基线

`trustedCreationPlan`由受信服务构造而非JSON反序列化公开请求。最小冻结字段：`creation_nonce`、`student_id`、`book_id`、`open_at`、有序且不重复的`word_ids`、有效教学配置快照（包含五项播放配置）、计划版本、创建协议版本。所有数值/枚举沿现有配置Validate；active owner、published词库、词库归属、词条与计划一致性必须在writer事务内再查。逐词教学内容由store在该事务读取并冻结，不接受调用者任意内容；计划fingerprint与实际内容快照fingerprint分列保存，重放返回原冻结内容，不因词条修订重建。授权凭证作为调用上下文传入，不属于客户端可声明的plan字段；nonce不能替代权限。fingerprint对上述规范化冻结字段计算，排除新生成lesson ID/DB时间，但保留词序。caller不能传phase、成绩、attempt、logical revision、checkpoint JSON或任意Lesson ID。

初始化由唯一私有工厂`newPilotBaseline(newLessonID, validatedPlan, now)`产生：checkpoint version=1、auth_generation=0（尚无连接）、active_command_id=NULL、尚无输入机会/answer_claim、无receipt/outbox/completion job。state采用显式pending基线`{schema_version:2,lifecycle:"created",machine:null}`，不是任意State或空对象；受信lesson.start才用冻结内容/config及实际开始时间NewMachine/Start，并将候选结果一起提交。这样不会把创建时刻误当教学StartedAt；不调用Restore/RecoverDelivery/Start来取得初始基线，也不把Machine默认PhaseShowWord误称已经开始。logical revision=0、question_key为空，首次实际输入机会分配1，后续真实新机会才递增。零值仅是未建立机会，不允许客户端以0提交。初始数据库phase取固定`pending`，它不是旧状态机新教学相位，仅created包装层状态。

created不强制授权永远为0：ClaimPilotConnection可以只递增auth_generation/赋新epoch而不Start、不改rev。授权独立约束为gen0时epoch=NULL；gen>0且未退休必须有效epoch；退休gen>0时epoch=NULL，任何旧lease不得复活。所有version/revision/generation使用SQLite有符号整数范围0..MaxInt64，需要正数的字段最小1，增前拒溢出，不使用MaxUint64作为数据库上界。state表mode的draining/legacy仅后继schema预留，首片codec只接受pilot，不能借列枚举提前开放在线切换。

`room_facts_json`必须由typed codec完整生成与校验，首片版本1含下列全部字段，不能用任意`{}`当齐全：encourage_counter=0；teacher_pending=false/teacher_text=NULL；phase_since=NULL、phase_deadline=NULL、paused_remaining_ms=NULL；last_actions=[]、pending_output_effects=[]；`input`初始NULL。未开始无输入租约。进入真实机会时input必须为完整对象：logical_input_revision、question_key、answer_deadline、voice_lease_used=false、voice_capture_deadline=NULL、voice_confirmation_deadline=NULL、original_answer_remaining_ms=NULL、capture_attempt_generation=0、capture_attempt_id=NULL、voice_terminal=false、voice_terminal_reason=NULL、answer_remaining_restored=false、restored_answer_deadline=NULL、confirmation_candidate=NULL。typed定义区分尚未冻结NULL与合法剩余0；首次起音原子冻结remaining并used=true，endpoint冻结确认截止；terminal后永久拒latefinal，恢复余量时同tx置restored=true+绝对deadline，重复事件不重算。confirmation_candidate若非NULL必须有text/purpose/source_attempt_id/fingerprint/current_revision，沿2048文本及指纹codec；不能由客户端直接保存。暂停保存余量、恢复更新绝对deadline遵循现策略，但不重置voice捕获/确认截止。创建与所有后续decode均拒unknown/缺字段/非法枚举/非整数/超界，JSON有效本身不代表这些合同已校验。

### 16.4 schema严格校验与迁移并发

不能只HasTable或AutoMigrate成功即认为schema一致。为版本2固定DDL清单：逐表PRAGMA table_info核列/类型/NOT NULL/默认值/PK序；index_list/index_xinfo核唯一性、列序及partial属性；foreign_key_list核目标/列/动作；sqlite_master核预声明CHECK和索引谓词。固定自建DDL采用明确的空白/标识符规范化后比较，不以substring出现字段名证明约束存在；同版本非标准DDL即fail closed并要求显式迁移核对，不自动重建。仅检查本协议拥有的对象，不能因为业务库多了无关表就拒绝。尤其锁定legacy SQL NULL CHECK、pilot nonce唯一、answer_claim跨epoch唯一、metadata singleton及active指针对应约束。

未迁移跨App顺序严格沿§15.3：runtime_records零行UPDATE取得writer→重读marker与对象→未迁移legacy门或已迁移模式门；显式迁移也先取得同一SQLite writer再复查。表存在查询失败、SQLITE_BUSY、取消均不降级为legacy。已有外层tx路径使用tx-bound内部函数，并对受信调用是否已取得writer做明确控制，不能用裸GORM Begin代表writer已获取。

2026-10-16草稿审查补充（实现阻断待闭合）：启动/显式迁移的完整数据审计与每次writer的当前scope门必须分开。全桥接扫描、逐桥接查scope及foreign_key_check数据扫描不能每卡重复，否则变成卡数×全库规模；热路径只核当前marker/metadata/当前scope，DDL可复用绑定同一outer sql.DB且PRAGMA schema_version相同的已完整验证清单。不得缓存marker值或scope mode；schema epoch不同仍在当前事务重核完整DDL、table_info/index_list/index_xinfo/foreign_key_list。cache仅由明确成功提交后的启动/迁移审计发布，热路径未知epoch可严格重验但不发布，避免未提交DDL回滚后epoch重用误命中。tx绑定必须由所属事务owner证明，不能按数据库文件路径猜测或跨DB共享。缺验证器时完整DDL核验fallback，不跳检查。该优化不省去约束校验，后续需真实卡数/桥接规模的查询计数与双池DDL变化回归。

## 17. 永久scope隔离补充设计（2026-10-16，设计准入）

设计准入记录：架构与后端交叉评审已收敛为0个新增设计阻断，主审批准按本节实施。特别确认配置revision向量、created状态接管、全局梯度变更前置检查，以及禁止REPLACE绕过永久墓碑的三个trigger。此结论仅批准设计，不代表SQL已执行或功能验收完成；双池、失败COMMIT、迁移原子性及真实浏览器用例仍为实施后必过门。当前启动优化验收候选冻结期间，仅在`.test-tools`准备非生产实现草稿，不改变该候选源码。

为封住旧多阶段卡片/草稿/排课写入而不重写成一笔大事务，新增`classroom_scope_reservations`，主键(student_id,book_id)，mode=legacy/pilot、schema_version=2、reserved_at。scope模式不可在线转换，删除选库仍保留永久legacy墓碑。课次reservation新增book_id并外键引用同owner/book/mode的scope。

scope表以固定BEFORE UPDATE及BEFORE DELETE trigger拒绝任何更新/删除（固定scope_immutable），另设BEFORE INSERT WHEN EXISTS同(student_id,book_id)的`classroom_scope_no_reinsert`，重复键直接固定拒绝。原因是SQLite recursive_triggers关闭时INSERT OR REPLACE的隐式删除不一定触发DELETE trigger，仅前两个触发器不足以保护无lesson引用的墓碑。合法入口在同writer先query，已存在只核mode/owner并返回，不存在才普通INSERT；迁移冲突也query校验，不依赖INSERT OR IGNORE/REPLACE或UPSERT重放。metadata writer不能借scope UPDATE取锁，仍更新metadata单例。三个trigger纳完整schema inventory，缺失/修改fail closed；Go真实SQLite负例包括recursive_triggers=OFF且无lesson FK引用的REPLACE、UPSERT、改mode/主键及DELETE均拒绝，原墓碑逐字段不变；正常两次服务预留仍通过。普通课删除只清lesson reservation，不碰scope。

`ReserveLegacyScope(ctx,studentID,bookID)`在任何旧范围副作用前取得writer，核正ID及schema/持久scope，已有pilot固定拒绝，缺失则永久插legacy，COMMIT后才允许原多阶段流程。legacy仓储scope门是隔离纵深，不是新的通用权限层；API/工具保留原身份/授权合同，不给既有停用词库维护或仓储直写单测添加active账号/published书政策。只有专用pilot创建在writer内要求active owner/current published书。后续pilot创建永远拒绝legacy scope，因此释放writer后继续旧事务也不存在中途插入pilot的窗口。内部工具已有tx时调用对应私有tx版本，绝不从tx再取pool；同范围多个legacy操作仍遵循原有并发合同，此门不宣称替它们解决所有并发写冲突。

pilot创建首次只能在**全新scope**：无scope预留、无卡、无摸底草稿、无任何Lesson（包括完成/作废）、无旧范围运行/任务事实。同writer完成这些查询并插pilot scope+新课/reservation/checkpoint；不接受通过删除旧业务行将永久legacy墓碑清掉。旧范围事实的读取失败或无法确认归属fail closed，不把“不认识的旧事实”当不存在。旧runtime的snapshot/report/settled/agent_result按lesson所属范围检查；若相关记录孤立/无法解码不能证明空scope，需显式修复，不自动授pilot。首片隔离测试使用全新学生/词库范围，普通选库会预留legacy，不能随后变pilot。

**未迁移桥接不可省略**：从首个支持版本起，legacy范围入口即使没有v2表，也在runtime_records writer内写固定key=`pilot/legacy_scope/<student_id>/<book_id>`、严格值`{schema_version:1,student_id,book_id,mode:"legacy"}`，然后提交再执行旧流程。同writer重查marker后若已迁移则走scope表。显式迁移在同writer导入并校验全部桥接以及现有卡/草稿/课次范围为legacy，保留桥接原记录，最后写完整v2 marker。这样App A已取得legacy许可但尚无业务行时，App B也不能迁移后抢建pilot。桥接是无v2时允许存在的独立legacy事实，不应误判为§15.3的残留pilot表或v2 marker；坏桥接固定schema错误。旧二进制绕门并写同DB仍明确不支持。

范围门必须位于以下第一副作用之前，而非仅SaveLesson：EnableBook/SeedCards、PlacementSubmit/MarkPlacement/ResetForReplacement、普通PlanNext/AlreadyPlanned与ReserveCards、结算（包括rememberFinished）、overdue重排/作废、取消选库，以及反馈执行将修改的课/卡/范围配置/通知。反馈必须先确定其涉及的已授权范围并全部预留legacy；不能先落一个范围配置再发现另一范围pilot。纯账号设置或只读操作不因本门新增教学权限；新课冻结配置不随账号当前配置变化。后续实现先做准确调用清单，只给涉及持久范围的入口加门，不把无关全局操作强行纳入。

后端调用补查锁定：scheduler公共写入口SeedCard/SeedCards、MarkPlacement(Context)、ResetForReplacement、PlanNextWithPolicy/ReserveCards、SettleLessonFinished/精确lesson settlement、HandleOverdue/Maintenance/Postpone/BoostWord/RemoveBook；TruncateLadderSteps跨scope必须先确定全部范围再逐scope预留，发现pilot时所有业务写拒绝。已成功授予的legacy墓碑可保留，它不是卡/课部分成功。API现有tx-bound SchedulerRepo构造在agenttransaction、feedbackstorage、lessonexecution及overdue：这些路径必须复用已有tx先取得writer，再做scope检查；服务前置门挡住rememberFinished/配置先行副作用，repo底层写门提供纵深，不能只在HTTP外层检查一次。此限制仅涉及对应student/book教学卡/草稿/课/结算及派生通知，不限制学生读取另一book或接收普通管理通知。

特别是全局教学梯度配置变更若将调用TruncateLadderSteps，必须在写全局配置前确定全部影响范围并完成scope检查；不能先更新配置再因pilot卡被拒留下半操作。冻结pilot课堂配置不等于冻结共享cards，此具体调用不能按“无关全局设置”豁免。该门对失败只保留已授legacy墓碑，不产生配置/卡/通知业务变化。

`ListLessons`面向用户可展示pilot事实，但legacy计划执行使用明确的legacy范围查询/返回课mode复核，不把pilot scheduled当ErrAlreadyPlanned的可恢复课程。对pilot范围旧排课/摸底/结算/取消/反馈写操作先固定拒绝，零卡/草稿/缓存完成/通知副作用；禁止通过只过滤pilot课却继续对同范围卡写来绕过scope隔离。删除legacy课时同事务清lesson reservation以满足RESTRICT，scope墓碑和未迁移桥接永不删除。

补双池用例：A永久reserve legacy后屏障暂停于首次写前，B迁移/创建pilot必须拒绝；A随后两个旧事务均可完成。反向B原子创建pilot后，A所有上述入口在首写前拒绝。A已预留后故障退出/取消/删除再选均不能把scope变pilot。迁移期间多范围桥接导入失败全回滚无marker。测试应检查卡/草稿/课/通知和rememberFinished，不只检查返回error。用户旅程仍是学生A普通课与学生B受信隔离课并发、正常用户可见拒绝和恢复，不开放生产测试创建入口。

该方案比独立DB/Router复刻身份和词库更小，也避免全legacy事务重写；它牺牲首片同scope混合legacy/pilot和既有学生范围升级，这是明确隔离范围，不改变旧教学规则。完整DDL非生产草稿见`.test-tools/pilot-v2-schema-draft.sql`，需一次固定所有对象及严格约束再写ready marker，不能只创建mode/state两表就宣称schema完成。

首片UI验收边界：学生B的有效pilot lesson ID只来自受信test harness新scope创建receipt；不提前普通enable，不伪造卡/选库关系或列表，不强点不存在的按钮。B真实课堂与摸底深链显示固定拒绝及返回入口，A普通UI完整旅程不变。旧摸底/删除/排课若尚无可达按钮，则明确记为真实登录浏览器协议测试，不冒称按钮旅程；独立PilotClassroom/试点列表随后另设计。

scope日志在外层操作收口，不能每张卡重复全审计日志。COMMIT成功后才记`legacy_scope_reserved`，同trace固定字段schema_mode、student_id、book_id、outcome=committed、writer_wait_ms、transaction_ms、replayed；writer_wait_ms量测writer取得SQL调用的总等待/执行时长，不冒称精确数据库内核锁时间。事务内最多记prepared事实或缓冲至外层tool audit提交后发布，不提前冒reserved成功。拒绝使用固定reason，包括pilot_scope_protected/schema_invalid/commit_failed，以及operation_failed/unauthorized/plan_stale/creation_conflict/not_ready/cancelled，不把存储或业务失败误报schema损坏；带同trace，不输出SQL、JSON正文、runtime key、连接epoch或数据库路径。迁移审计记schema_version、对象/导入scope数量、固定stage及耗时；冷热检查只记cache_hit、整数schema_cookie及查询数量，与授权connection_epoch严格区分。schema缓存命中不代表scope数据缓存，记录不得暗示已绕过当前模式核验。

### 18.1 只读事实检查与写入预留分开

`.test-tools/pilot-legacy-entry.go.draft`提供两个不同接口：`PilotStore.CheckLegacyLesson(ctx,studentID,lessonID)`在一致只读事务检查当前schema/marker、持久Lesson归属与scope/课次mode；不执行writer UPDATE、不创建bridge/reservation、不更新first_entered_at。`ReserveLegacyLessonExecution`在实际可变课堂执行前取得writer并重查上述事实，预留永久legacy scope及必要lesson reservation，COMMIT后才允许创建/恢复可执行Room。前者不返回可供以后写入的许可，后者也不是身份认证。已存在Lesson不可能转pilot；即使只读检查后别App迁移，该既有Lesson只能被导入legacy，后继写门仍查当前schema。缺表/损坏并非legacy fallback。

已结束课堂重进只返回已有终态/课报、签发或检查内存ticket、发送只读快照时，不得为了防护增加持久reservation写。已有`TestCov_EnterFinishedLesson`仅证明重进保持finished/lesson_end；`TestSessionTimeoutDoesNotRewriteFinishedOrRetiredRoom`证明finished/retired timer零Create，不能合并声称Enter全部DML已被测试。须新增真实SQLite计数覆盖完成课Enter/Join/ticket/report的INSERT/UPDATE/DELETE均0。若实际恢复还要RecoverJudgment/teacherLifecycle/结算重试，则属于可变恢复，走writer门；不能仅凭Lesson状态或phase=lesson_end假定结算已完成。是否已完成需沿持久完成事实及现有Room.finished语义验证，不能借此修改结算决策。
