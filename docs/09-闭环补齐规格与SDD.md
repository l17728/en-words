# 09 闭环补齐规格与 SDD

日期：2026-10-12。状态：初始设计评审已完成，核心补丁已实现，正在运行验证；未关闭项见 10 验收记录。新增设计须另行评审后实施。
上游：01 需求分析、02 SDD、03 测试用例、04 Agent 决策表、08 E2E 测试方案。
本次用户约束优先于旧供应商决策：先经 `http://127.0.0.1:8090` 本机平台跑通，再依据实测决定模型替换。

## 1. 目标与验收范围

管理员初始化、建立学生与词库 → 学生选库、摸底、排课 → 朗读/跟读 → final 测试与两次机会 → 课报、复习排课 → 反馈调节 → 重启后恢复。保留 D-21 教学中零测试、50–100 词配置边界；小词库允许不足 50 词用于快速完整验收。

确定性课堂状态机是事实源，模型不得任意推进相位。先完成这一闭环及其可靠性，观察员 Agent、语法内容插件和声音克隆属于后续产品扩展，不作为当前闭环已经实现的能力。

## 3. 本机模型接入 SDD

### 3.1 已发现协议

`GET /api/models` 返回 `services[]`（id/model/capabilities/proxyRoute）；`GET /api/status` 返回服务状态。调用管理平台代理，不读取平台后端密钥、不改变其他项目服务。

- 文本：`POST /api/vl/chat`，Chat Completions 请求/响应；模型为平台发现的 model，输出须 JSON 校验。
- ASR：`POST /api/asr/transcriptions`，multipart `file,model,language`，响应文本进入已有 voice 管线。
- TTS：`POST /api/tts/speech`，先探测请求/响应契约及中英文可用性，再接入播放器。
- 基址使用 `ENWORDS_MODEL_CONSOLE`，默认 `http://127.0.0.1:8090`；`-providers local` 选择本机，mock 保留用于确定性回归，real 兼容旧模式。

### 3.2 边界与故障

模型 ID 不写死在业务层；发现失败/必需文本模型缺失时启动失败并给出结构化原因。请求须可取消，设置响应大小和耗时上限。无效 JSON、超时、服务错误必须记录并降级到既有规则，不将 fallback 统计成模型通过。模型返回的改期/配置仅为候选，经类型、范围、身份和归属校验后执行。

浏览器仅调用 en-words 同源认证接口；后端代理访问本机平台。录音设置大小/时长限制，禁止任意 URL 代理。ASR 返回后校验仍是同一课堂/题目/相位，过期录音丢弃；课堂离开释放麦克风。播放器使用串行队列，收到 play_tts 才发声，完成后发回执；网络合成失败使用明确降级，不重复播放。

首轮限制：模型发现 5 秒、文本 8 秒、ASR/TTS 20 秒；JSON 响应最大 1 MiB、音频上传/响应最大 8 MiB、录音单段最长 8 秒。暴露 GET `/api/v1/providers` 返回能力（不含密钥）；POST `/api/v1/classroom/lessons/:id/transcribe` 接收音频并仅返回文本，由前端在同一相位/题目标识下提交；POST `/api/v1/speech/synthesize` 接受 text/lang，返回 WAV。接口需登录，课堂接口需学生归属；无能力返回明确不可用响应，禁伪造成功。

英文朗读先保留现有本地浏览器英文 voice。平台当前注册的 TTS 明确为 Chinese，不承诺英语能力；只有通过独立抽测才启用英文平台 TTS。本机 ASR 失败时显示文字输入替代，不能无限重试或静默跳题。媒体 mock 测试明确标记为协议测试，真实音频验收独立留证。

## 4. 数据、调度与工具 SDD

持久化模式由 store 实现 config.Persister 与 memory.Repo；课报、课堂快照、通知和反馈写 SQLite。快照存配置快照与状态，恢复时不采用课中新增配置。`map[QuizItemID]Judgment` 不可直接 JSON 编码，需字符串 key 或显式列表转换，必须 roundtrip 测试。账号修改后同步持久化。

结课顺序：结算当前课 → 系统 Agent 评估 → 执行并核实调整 → 排下一课 → 保存课报、通知。完成状态和结算须幂等，失败可重试，不能先标完成后丢弃失败。

结算实施约束（实现评审后细化）：以 `settled/{lesson_id}` 为唯一键的持久化完成记录；卡片更新、原课程 finished、确定性配置调整、后继课、课报、快照和通知全部处于同一 SQLite 事务。写入完成记录后再次请求跳过整批副作用；模型调用不得在事务内执行。此实现不使用通用 outbox，也不把进程内锁当作持久化幂等保障。失败不得提前设置 Room.finished。必须有事务中途写失败回滚、重启重放和重复结课测试，未验证时 G04 保持未关闭。内存模式只保证同进程重试采用冻结的绝对卡片目标，不能承诺重启恢复。

反馈调整先校验并执行，再生成实际生效值回复；失败记录 failed 并通知用户未生效。工具执行上下文必须绑定受信 student/lesson 标识；模型参数不能覆盖调用者身份。高风险写操作必须 reason，审计记录 trace、角色、工具、结果和耗时。未实现的工具不得注册假成功 handler。

本机模型解析返回必须复用规则边界：词量 50–100、频率 1–2、改期未来 7 天内；未知意图/非法日期/低置信度不执行。增加确认不能突破硬边界。课程归属在 REST/WS/Hub 和新音频接口统一检查。所有修改昵称/密码/状态的路径必须持久化，避免重启回退。

首启 UI 状态为 loading/needs_setup/ready/error；仅 needs_setup 展示创建管理员。管理员专属页面支持创建学生、词库、结构化词条导入和发布。Dashboard 使用后端 snake_case 通知/反馈字段，反馈发送期间防重复提交，显示真实 status/reply；已完成课程可打开持久化课报。统计趋势页属于后续功能，不能列为已完成功能。

本轮工具目标清单：`config.set/get`（system/admin，学生覆盖须绑定任务学生）、`memory.append/recall`（teacher/system，各自 owner）、`scheduler.plan_next_lesson/postpone_lesson/boost_word`（system，绑定任务学生）、`classroom.say`（teacher，绑定课堂）。外部 Agent 工具接口当前无任务凭据，禁止扩展为可跨任意学生写入的万能接口；新闭环工具仅在受信内部任务上下文调用。Schema 的 enum、边界和归属在 handler 二次校验；超预算/权限拒绝也审计，不记录完整 args。其余工具保持 G05 未关闭。

发现响应中的 proxyRoute 不作为请求地址：客户端使用固定相对端点，并拒绝跨源重定向。录音接口绑定课程所属学生；不存在/不归属课程统一拒绝且不创建房间。Hub 冷/热房间均复核归属。HTTP 返回 X-Trace-ID；课堂事件以 lesson/session/event 关联，禁止将每条随机 trace 当作链路贯通。

## 5. 定位日志规格

WebSocket 背压修订：普通帧的有限队列不能挤掉心跳响应。每个连接增加容量 1 的心跳控制队列，写泵优先发送，并允许普通帧前进；多个待发心跳响应允许合并（协议没有逐请求序号），不得扩成无界队列或阻塞房间锁。客户端持续读取、传输正常时，400 条过期事件洪泛后须在 5 秒内收到 heartbeat_ack；关闭连接后不得报告发送成功。心跳不能抢占已阻塞的 socket 写入，也不是业务完成屏障。每次通过校验的学生事件/语音处理后，在普通 FIFO 尾部发送 `event_processed`（event_id、context），供协议客户端关联处理回执；这不代表结算/持久化成功，仍须检查业务结果帧。语音反馈还须等待 `feedback_reply`，因为其处理在课堂路由之后。普通队列满的丢帧通知/自动快照恢复尚未实现，仍列 G07 待办，不能靠心跳推断业务帧完整性。

本机媒体等待预算：课堂计时器按实际 turn 重置（包括同为 tts_seg 的下一段、同为 wait_answer 的下一题），不能累计前一段耗时。本机 TTS 相位在原播放预算外预留 20 秒合成时间，录音相位预留 4 秒采集与 20 秒转写时间；仍采用有界超时，迟到结果必须被上下文校验拒绝。此预算仅用于启用对应本机能力的课堂，不能把超时延长当成音频质量达标。

G07 的 turn 同时带单调版本号：相位签名变化递增，暂停后恢复不得复用旧 token；签名覆盖重教段 ReteachSeg、回顾 InReview/ReviewIdx。WS 活跃连接验证也在同一房间锁内完成。

G07 外部事件协议：每个课堂帧携带 `context={epoch,turn}`。epoch 为房间实例随机标识，重启失效；turn 编码当前相位、教学词/朗读段、测验题目标识及暂停状态。REST event/voice 与 WS student_event/voice_text 必须携带原 context 和唯一 event_id（长度 1–128）；服务端在房间锁内同时校验、去重、执行，缺失/过期/重复均返回 event_rejected + 最新快照，不产生副作用。客户端异步 ASR/浏览器识别/TTS 回执使用任务开始时 context，禁止结果到达后换为新题 context。内部状态机测试入口保留兼容。事件去重缓存最多 2048 条；缓存淘汰后旧 turn 仍失效。用例覆盖缺字段、同事件跨 REST/WS 重放、前题迟到、房间重建旧 epoch、同相位换词/朗读段、ASR 处理中切题。

必需事件：`request_completed`、`provider_discovered`、`model_request_completed`、`model_request_failed`、`provider_fallback`、`audio_transcribed`、`audio_stale`、`phase_changed`、`quiz_judged`、`tool_called`、`feedback_handled`、`lesson_settled`、`snapshot_saved/restored/failed`。

字段：trace_id、module、event、lesson_id/student_id（适用时）、模型/任务、duration_ms、状态码/失败分类、工具名、相位/题目标识。日志不记 API key、Authorization、音频、完整 prompt/模型回复；原始学生文本改长度/摘要或测试专用取证。浏览器 E2E 保存 console/error、网络失败、截图和 Playwright trace，关联后端 trace。

自动化模型能力评估：判分准确率目标 ≥95%，反馈结构正确且边界遵从；记录每例模型原始分类、实际结果、耗时和 fallback 数。小样本仅作冒烟结论，正式结论需 100 题标注集；语音用固定 WAV 与异源语音评估，不能仅同模型回环自证。英文可懂度还需真人听测。结果不足时先定位任务/提示词/协议问题，再比较本机模型替换与互联网服务的延迟、质量和成本；本轮不自动购买或替换平台模型。

用例补充：C04 分别从 tts_seg/repeating/wait_answer/结算故障恢复，检查题目标识、尝试次数、冻结配置；C05 覆盖上述所有 REST/WS 越权入口；C08 覆盖同一事件跨通道重放、前题迟到、enter Promise 离页后返回及心跳超时。E2E 使用专属数据库/端口，不复用未知服务，默认 headless；确定性媒体桩与真实录音报告分开。Stats 尚未实现时路由业务覆盖门保持未通过。对无工具链的环境只可报告静态检查，不能替代 Go/浏览器测试。

## 7. 执行与评审门

1. 架构/后端与测试/前端分别评审本文，问题与处理写入 10 验收记录。
2. 设计问题关闭后按依赖实施：模型适配 → 数据闭环/调参 → 课堂接线/协议 → E2E。
3. 子代理执行 Go 回归/覆盖率、前端构建与无头 E2E；真实平台评估独立记录。
4. 代码再评审，修复发现必须补 Go + E2E 回归；记录仍未完成或环境阻塞的项目，禁止写“全通过”替代证据。
