# First-Audio Real-SQL Preflight Amendment

Date: 2026-10-28  
Status: draft for architecture, security, backend, and testability review. No implementation or acceptance is claimed.

This amendment controls the real-SQL preflight slice and supersedes only the conflicting provisions in `docs/74-first-audio-matrix-isolated-backend-sdd.md` §3 step 5 (probe statement/lesson column), §4 (phase-specific authorizer tuples and runtime PRAGMA policy), and `docs/76-first-audio-context-authority-and-probe-lifecycle-sdd.md` §3 (preflight receipt milestones). Unchanged containment, identity, phase, and process-reaping rules remain in force. Runtime PRAGMA SQL stays denied; journal configuration is verified from checked connection/driver state captured by the setup pool and included in the baseline.

## 1. Scope

Connect the reviewed startup, immutable-context, and probe-receipt designs (`docs/74`–`docs/76`) through one real CGO SQLite/GORM pool. Prove every pinned physical application connection can consume its own one-use challenge, execute only the exact synthetic lesson `OLD == NEW` update through the installed row trigger/UDF, explicitly roll back, and leave the complete database snapshot unchanged. This slice ends in `PREFLIGHT`: it opens no listener, returns no browser origin, performs no `JOURNEY` DML, and does not replace `unavailableFirstAudioBackend`.

## 2. Authority and connection identity

`firstAudioGuardController` and its immutable context are the sole phase authority. Add `DRIVER_PROBE` as the initial immutable context phase, with no row contracts. It permits only the exact `sqlite_version()` function needed by the SQLite dialector during synchronous `gorm.Open`; it grants no table read or DML. Its successful observation is bound to a registered physical connection and is required for a one-way `DRIVER_PROBE → STARTUP_PROBE` publication. The previous startup-policy `phase` atomic must be removed from the integrated path, rather than mirrored beside the controller. The next transitions are `STARTUP_PROBE` (entire `NewApp` initialization), then `PREFLIGHT` only after startup schema and row snapshots match. No transition can revert or skip a phase; `NewApp` SQL outside the checked-in callsite inventory rejects and terminalizes the child.

`ConnectHook` assigns each physical connection a monotonic private ID and registers the exact `*sqlite3.SQLiteConn` identity before returning it. A transparent driver-connection lifecycle wrapper records retirement in `driver.Conn.Close` and invalidates that exact registry entry before delegating physical close; it forwards every driver interface used by `database/sql`/GORM, so wrapping cannot silently change execution behavior. The preflight runner pins the pool's full configured capacity and verifies each `*sql.Conn` resolves to its registered driver connection using `Conn.Raw`; IDs are never accepted from SQL, the browser, environment, or test protocol. Connection replacement, missing registration, hook count mismatch, or close/reopen during the pinned probe terminalizes the candidate. Compile-time assertions and tests must prove the wrapper preserves the exact optional driver interfaces used by GORM and database/sql (including context prepare/exec/query, begin, ping, validation, reset, and named-value checking) while retirement invalidates the same registration. A failed-probe discard test must cause physical retirement, prove deregistration, and prove the old connection ID/receipt cannot be reused; `*sql.Conn.Close()` alone is not evidence of physical retirement because it normally returns the connection to the pool.

Each connection receives a CSPRNG challenge and preflight-only permit bound to run ID, lesson ID, generation, context version, connection ID, probe ID, and a private transaction nonce. ConnectHook stores the challenge on the connection registration; neither a caller-supplied connection ID nor a SQL argument can select another registration. The raw token is supplied only to that connection's exact `SELECT first_audio_probe(?)` inside its explicit transaction. The token is not stored in a context, response, or log; its digest is compared in constant time. Per-registration probe state is monotonic: `UNARMED → TOKEN_CONSUMED(tx nonce) → TRIGGER_CONSUMED(probe ID, exactly once) → ROLLED_BACK`. The row-guard UDF must verify that the token was consumed on this same registered physical connection, in the same live transaction nonce and current probe, then atomically consume the one-use trigger permit during the only accepted callback. An UPDATE before token consumption, a token consumed in another transaction, callback replay, or any extra/missing callback fails closed. ROLLBACK, cancellation, callback mismatch, or any error immediately invalidates the one-use token/row permit; it cannot be rearmed or retried. The separate one-use `TX_CLEANUP` authorization remains available solely to roll back that same active transaction. UDF callbacks only inspect immutable registration/context/permit data and never query SQLite, acquire a lifecycle lock, or call back into application services.

Preflight has a private admission gate separate from normal operation admission. The test coordinator alone can acquire a connection-bound preflight permit; App routes, REST/WS/timer handlers, tools, workers, and the listener factory remain unavailable. The pool capacity is fixed before pinning. The coordinator pins all configured physical connections simultaneously, verifies the registry contains exactly those connections, and freezes that set. Connection lifetime/idle recycling is disabled. Any physical connection replacement after freeze is terminal; an unverified connection never inherits another connection's completed receipt. Readback uses the same pinned, registered connections under read-only preflight permits. No helper calls `OpenJourney`.

## 3. SQL probe and receipt

The reviewed schema installs fixed lesson INSERT/UPDATE/DELETE triggers before the guarded pool opens. All three call `first_audio_row_guard` from their exact trigger source; only the exact UPDATE source can succeed in `PREFLIGHT`. The no-op statement is fixed as `UPDATE main.lessons SET id=id WHERE id=?`, with the parameter issued by the controller; it must match exactly one row and produce exactly one expected UDF callback. The callback projection is the ordered 18-column `store.Lesson` row: `id, student_id, book_id, seq, status, open_at, started_at, finished_at, batch_word_ids, phase, group_idx, word_idx, repeat_count, tts_seg_idx, quiz_state, cumulative_ids, result, state_upd_at`. For each of the 18 OLD values followed by each of the 18 NEW values, the trigger passes `typeof(value)` and `CASE WHEN typeof(value)='text' THEN CAST(value AS TEXT) ELSE value END` as a pair, for exactly 72 UDF arguments; it does not use `json_array`. The type tag distinguishes SQL NULL from an empty BLOB. The CASE expression preserves the SQLite value class while forcing TEXT through a declared-type-free expression, avoiding driver DATETIME parsing; INTEGER and REAL remain native numeric arguments, and BLOB remains bytes. The runner reads the same `(typeof(column), CASE WHEN typeof(column)='text' THEN CAST(column AS TEXT) ELSE column END)` projection inside the same transaction using a private projection-read permit. Normalize both callback and readback into a typed comparison value: SQL NULL as a dedicated null tag, INTEGER as int64, REAL as its IEEE-754 bit pattern, TEXT as its exact Go string bytes, and BLOB as exact bytes. No text, float, or blob is parsed or normalized. Integration tests must pin exact mattn callback argument types and conversion behavior before freezing the manifest; the build must reject a SQLite library whose maximum function-argument count is below 72. No-op updates to another row, changed fields, direct UDF calls, wrong trigger sources, or use in another phase fail closed.

The setup pool captures a canonical full snapshot after fixture seeding and exact trigger installation, then closes before the guarded pool is opened. `NewApp` must leave that snapshot unchanged. After `NewApp`, the private helper uses each existing pinned `*sql.Conn` for every operation: begin one transaction bound to that pinned connection; consume that connection's token; enable the one-use `PROJECTION_READ` permit and query exactly one lesson row using the 18-column typed projection; freeze its 18 type/value pairs (36 values) and close that permit; if the query errors or returns zero/multiple rows, do not execute UPDATE; invalidate the probe, roll back under `TX_CLEANUP`, terminalize the candidate, and issue no receipt; otherwise execute the fixed no-op UPDATE; require exactly one matched row and one row-guard observation; explicitly roll back and require rollback success; then read back the complete schema/row snapshot on that same pinned physical connection. Snapshot code must not reacquire through `*sql.DB` while the pool is fully pinned. A per-connection SQL/GORM `ConnPool` adapter may be used, but tests must prove it issues no pool reacquisition and cannot deadlock. The snapshot covers every manifested table and column, `sqlite_sequence`, schema objects, and verified journal/connection settings from driver state; no runtime PRAGMA SQL is issued. Compare with the setup-pool canonical snapshot after `NewApp`, after each connection probe, and once after all probes. A receipt becomes complete only after explicit rollback, transaction-handle cleanup, and unchanged snapshot are verified. Receipt construction is private to the coordinator and no public/test protocol caller can submit rollback-success evidence. Token consumption, callback observation, rollback, connection identity, and snapshot equality are separate mandatory milestones.

Failure cleanup has one owner: the prepared-backend coordinator. Any hook/registration failure, UPDATE/callback mismatch, cancellation, timeout, panic, readback error, or snapshot delta closes preflight admission and terminalizes the child. A rollback or cleanup error is `outcome_uncertain`: do not create a receipt, return the connection to the reusable pool, retry SQL, or continue snapshot acceptance. Discard the physical connection through the `database/sql` bad-connection path and verify its deregistration; if that cannot be proven, keep the child terminal and require the parent runner to reap the entire process tree. Shutdown closes App resources and the pool only after probe activity drains. The listener factory is injected as a counter and must remain uncalled on success and every failure path. No uncertainty permits a later phase publication.

## 4. Authorizer and schema contract

The authorizer is an explicit tuple allowlist `(phase, source, action, database, table/column-or-function, permit-kind)`; it never uses a broad “allow function” rule. `DRIVER_PROBE` permits exactly the observed `SQLITE_SELECT` with empty source/table/database and `SQLITE_FUNCTION(sqlite_version)` callback during synchronous dialector initialization; neighboring functions or table reads are denied. `STARTUP_PROBE` permits only the inventoried `NewApp` reads and the existing zero-row `SQLITE_UPDATE(main.users.id)` prepare reservation; its trigger rejects every actual user row effect. `PREFLIGHT` permits `SQLITE_SELECT` and manifested `SQLITE_READ` tuples only under coordinator-only `SNAPSHOT_READ`, plus `SQLITE_UPDATE(main.lessons.id)` and the exact `SQLITE_READ(main.lessons.id)` WHERE-column tuple for the fixed probe statement under `PROBE_SQL`.

The token statement is exactly `SELECT first_audio_probe(?)`: allow its empty-source, empty-database/table/column `SQLITE_SELECT` tuple and `SQLITE_FUNCTION(first_audio_probe)` tuple only under the one-use `TOKEN_CONSUMPTION` permit for that connection and active transaction. Tests assert one statement and one token callback, and denial of adjacent ordinary SELECTs and token replay. The OLD/NEW comparison query is a fixed `SELECT` of the manifested 18 `main.lessons` columns using `(typeof(column), CASE WHEN typeof(column)='text' THEN CAST(column AS TEXT) ELSE column END)` under a single-use `PROJECTION_READ` permit on the same pinned connection; its required empty-source `SQLITE_SELECT`, exact column `SQLITE_READ`, and `SQLITE_FUNCTION(typeof)` tuples are admitted only while that permit is active, and application code cannot acquire it. For the fixed `fa_lessons_guard_update` source, permit its trigger-internal `SQLITE_SELECT`, exact 18 `SQLITE_READ(main.lessons.<column>)` tuples, `SQLITE_FUNCTION(typeof)`, and `SQLITE_FUNCTION(first_audio_row_guard)` only under `PROBE_SQL`. The row-guard UDF must receive exactly 72 arguments. Keep these tuples denied for every other trigger source and permit kind; the INSERT/DELETE lesson triggers are not admitted by this preflight. Direct calls, wrong source, database, column, argument count, phase, permit, or function are denied. All other function/action tuples remain denied. Snapshot capture may read only fixed manifested schema objects and rows; journal settings are captured from verified setup/driver state, and no runtime PRAGMA action is authorized. Since SQLite authorizers cannot inspect the UPDATE predicate or bind values, the trigger/UDF checks exact OLD/NEW identity and all persisted fields.

The probe coordinator may issue `SQLITE_TRANSACTION(BEGIN)` under `PROBE_SQL` and one `SQLITE_TRANSACTION(ROLLBACK)` under a separate `TX_CLEANUP` permit bound to the same connection and transaction; During `PREFLIGHT`, `COMMIT` and savepoints are denied. `TX_CLEANUP` is independent of the invalidated token/row permit: cancellation or callback mismatch immediately closes business/probe admission and invalidates the challenge, preventing further SELECT/DML/COMMIT, but retains exactly one coordinator-only ROLLBACK authorization for the active transaction. If that rollback cannot be confirmed, connection disposal and child reaping apply.

### Exact authorizer tuple manifest for this slice

The initial implementation must check in this finite extension to the existing schema-derived read manifest. `source=""` means SQLite's empty trigger-source string; omitted table/column/function fields must be empty. `READ(table, columns)` means one tuple per named column, not a wildcard.

| Phase | Source | SQLite callback tuple | Permit and boundary |
|---|---|---|---|
| `DRIVER_PROBE` | empty | `SELECT`; `FUNCTION(sqlite_version)` | Driver initialization only, one observed dialector query |
| `STARTUP_PROBE` | empty | `SELECT`, manifested `READ(main.table,column)`, existing manifested `FUNCTION(count|max|coalesce)` | Synchronous `NewApp` startup reads only |
| `STARTUP_PROBE` | empty | `UPDATE(main.users,id)`, `READ(main.users,id)` | Existing zero-row `UPDATE users SET id=id WHERE 1=0` reservation during `APP_STARTUP_TX` |
| `STARTUP_PROBE` | `fa_users_no_update` | `SELECT`; `FUNCTION(first_audio_row_guard)` | Only compile/execute the fixed zero-row users reservation trigger; callback rejects actual row effects |
| `STARTUP_PROBE` | empty | `TRANSACTION(BEGIN|COMMIT|ROLLBACK)` | `APP_STARTUP_TX` held by synchronous `NewApp`; no savepoints |
| `PREFLIGHT` | empty | `SELECT`; manifested `READ(main.table,column)` | Coordinator-only `SNAPSHOT_READ`, including all schema tables and `sqlite_sequence`; no functions or PRAGMA |
| `PREFLIGHT` | empty | `READ(main.lessons,id)`; `UPDATE(main.lessons,id)` | Exact no-op statement only under `PROBE_SQL` |

| `PREFLIGHT` | empty | `TRANSACTION(BEGIN)` | `PROBE_SQL` for one active pinned connection transaction |
| `PREFLIGHT` | empty | `TRANSACTION(ROLLBACK)` | `TX_CLEANUP`, once for the same active probe connection/transaction; independent of invalidated row/token permit |

The existing full read manifest supplies the complete table and column list; this amendment supplies only phase/source/permit restrictions. `COMMIT` is denied in every phase except the single `STARTUP_PROBE/APP_STARTUP_TX` transaction shown above; it is always denied in `PREFLIGHT`. `SAVEPOINT`, runtime `PRAGMA`, DDL, ATTACH/DETACH, unlisted functions, lesson INSERT/DELETE, and every other tuple absent from this table remain denied. Before implementation, capture the actual authorizer callback tuples for `NewApp`, token consumption, the 18-column projection, and the lesson update trigger with `EXPLAIN`/prepare-only probes; compare them to this manifest and change the reviewed manifest before any runtime permission is added.
Add the fixed lesson triggers to the checked-in `sqlite_master` object inventory and digest; record their exact DDL/source names and verify the schema/read manifest before the guarded pool opens. Keep the no-op probe transaction separate from `NewApp` startup and do not grant config/user writes. Capture the exact `NewApp` SQL surface: the zero-row `users.id` update reservation, approved read statements, and empty `notifications`/legacy `feedbacks` restore queries. Unexpected startup DML or an unlisted query fails before preflight. The manifest must name each allowed function/action tuple, trigger-source tuple, transaction action, and connection setting before implementation; tests assert each required tuple is admitted only in its stated context and nearby variants are denied.

The driver bootstrap function permit is cleared before `NewApp`; the controller publishes `STARTUP_PROBE`, constructs `api.App`, then publishes `PREFLIGHT` only after startup snapshot equality succeeds. All physical connections must complete their own probe before any future `JOURNEY` context can be published. This amendment does not grant permission to publish `JOURNEY`.

## 5. Required SQL integration matrix and review boundary

Positive tests cover every pinned connection: each consumes only its unique token, triggers exactly one callback for the selected lesson row, rolls back successfully, and verifies the unchanged complete snapshot.

Fresh-candidate negative tests must individually cover: wrong token; connection A using connection B's token; wrong run/lesson/generation/context-version binding; token replay; UPDATE before token consumption; token consumed on a different transaction; direct or wrong-source UDF call; a second trigger callback; update of another lesson row; corrupted expected OLD/NEW projection (row guard must reject the mismatch); zero matched rows; missing/replaced UDF; missing/replaced/extra trigger; unregistered/replaced physical connection; extra/omitted callback; failed rollback; connection cleanup failure; projection read error or zero/multiple target rows (assert no UPDATE occurs); and cancellation or timeout racing an admitted callback and drain; after an ordinary callback rejection or cancellation, verify one rollback remains authorized only in PREFLIGHT while further reads/DML/COMMIT are denied; verify rollback is denied in DRIVER_PROBE and STARTUP_PROBE except for the startup transaction permit. Multiple matched rows are structurally impossible because `lessons.id` is the primary key, so assert the fixed UPDATE cannot match more than one and test zero-row behavior separately. For every failed case, assert no receipt, no later-phase publication, preflight admission closed, and listener factory call count zero. For cases with confirmed rollback, compare the full snapshot. For uncertain rollback/connection outcome, preserve terminal evidence and never report snapshot equality as proof of a clean transaction. Run terminalizing negative cases in isolated child candidates.

Also assert the setup pool is unusable before guarded pool creation, `NewApp` startup and each successful probe preserve the exact canonical schema/row/`sqlite_sequence` snapshot, all handles drain before shutdown, and test-only symbols remain absent from the production binary. Test the actual trigger 72-argument count, native callback types, and typed projection conversion on both Linux and Windows CGO runners before freezing the baseline manifest.

Architecture, security, backend, and testability review must approve this exact amendment before implementation and review the resulting code before acceptance. A pass may be reported only as **guarded App startup and real-SQL preflight integration**. Tool-audit DML, runtime snapshots, cross-table ordering, operation/SQL leases, reset, two-process Playwright journeys, performance, and classroom acceptance remain separate open gates.
