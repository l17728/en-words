# RunRoot WAL Retry Coverage Determinism SDD

## Status and scope

This is a narrowly scoped RunRoot WAL reliability correction plus package-coverage stabilization. Linux tagged package runs produced 80.4%, 80.2%, and 80.3% statement coverage against identical `runroot_ledger.go` and test-file hashes. `enableRunRootLedgerWAL` varied from 79.3% to 55.2%. The cancellation test sometimes exits through a different SQLite/context error path. A deterministic retry test exposed the cause: the pinned `mattn/go-sqlite3` driver reports its primary code in the exported `sqlite3.Error.Code` field, while `runRootLedgerSQLiteBusyOrLocked` currently recognizes only the `Code() int` interface. It therefore fails to classify a real `SQLITE_BUSY` from this driver, even though synthetic interface tests pass. After fixing that function, five independent package coverage runs still varied in `connectHostLoggerClientOnce` and `loggerWaitWithPoll`, because the real poll/socket environment only reaches some branches nondeterministically. This violates the repository's deterministic-coverage rule.

Do not change product readiness or expose routes. Correctly classify primary and extended BUSY/LOCKED codes from both the pinned CGO `mattn/go-sqlite3` error and the existing `Code() int` error contract used by other supported drivers. Mask extended codes to their primary byte and retry only primary codes 5/6. Keep non-SQLite/text-only lookalikes non-retryable. Preserve the cancellation contract: after WAL transition receives BUSY/LOCKED, it retries within a bounded context; cancellation during the retry wait returns `context.Canceled`, leaves journal mode unchanged, creates no ledger schema, and the constructor discards its pinned connection. After each SQL call, check the attempt context error and compare the monotonic current time with its effective deadline before classifying a driver error. If expired, return `context.DeadlineExceeded`; this remains deterministic even if Go's deadline timer callback has not run yet.

## Required test behavior

Extend `runRootLedgerSQLiteBusyOrLocked` to inspect actual pinned CGO driver errors through a small build-specific adapter (the CGO file uses `errors.As` with `sqlite3.Error`; the non-CGO stub reports no native driver code) while preserving the generic `Code() int` fallback. Add tests with actual `sqlite3.Error` values for BUSY, LOCKED, extended BUSY/LOCKED, a non-retryable SQLite code, and the existing text-only lookalike.

Keep `enableRunRootLedgerWAL(ctx, conn)` as the production entry point and delegate to a private per-call helper with the existing retry policy plus optional test-only timer factory and `beforeRetryWait` observer. Production supplies neither and continues to use `time.NewTimer` with the same delays and context select. In the test, inject a fake timer whose channel never produces a value and whose `Stop` records calls. After a real SQLite BUSY/LOCKED result is classified and timer created, the observer signals a named barrier and waits for release. The test cancels the context and releases the observer; the existing select returns `context.Canceled`, and the never-signaled timer ensures only the cancellation case is ready despite scheduling delays. Assert the observer was reached once, the timer was stopped, journal mode stayed DELETE, and no ledger schema was created. Release/join every goroutine on all paths.

Do not use `time.Sleep` as a barrier. Do not add mutable package-global hooks or alter retry timing. Keep the optional retry timer factory and observer per-call and private; production supplies neither and continues to use the real `sql.Conn` query. Add a private per-call WAL query function and monotonic clock hook only as needed to test deadline precedence. A deterministic test uses an actual typed `sqlite3.Error{Code: SQLITE_BUSY}` from the query seam and a clock value strictly after the effective deadline while the context's timer has not fired. Assert the classifier recognizes BUSY, the returned error is `context.DeadlineExceeded`, exactly one SQL attempt occurs, no retry wait is created, and no schema is written. Add a companion seam test that synchronously cancels the parent context during the query before returning BUSY; assert the post-query cancellation branch returns `context.Canceled` with one query and no retry timer. These seams are not package-global and do not change the production query path. Keep the actual SQLite busy-callback cancellation test separately: its named barrier proves BUSY reached the callback, then cancellation during retry wait returns `context.Canceled`, the fake timer is stopped, journal mode stays DELETE, and no ledger schema appears. Release and join every goroutine on all paths.

Stabilize the two additional poll-dependent coverage branches with deterministic tests. `loggerWaitWithPoll` already accepts a per-call poll function; cover an `EINTR` followed by readiness and a terminal poll error explicitly. Add a private per-call wait function seam for `connectHostLoggerClientOnce`; use a live abstract Unix seqpacket listener and inject a wait timeout to deterministically verify the descriptor-close/error path while existing readiness tests cover success. Production continues to pass `loggerWait` and actual `unix.Poll`; do not add global hooks or change retries.
