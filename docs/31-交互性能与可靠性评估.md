# 31 交互性能与可靠性评估

## 范围与验收原则

2026-10-15，基线 `cd3b410`。用户要求跨领域集体评审并提升功能完整性、易用性、性能、可靠性和可用性。本阶段针对已有学生/管理员实际路径；不更换共享模型，不改变教学判分政策。React19/AntD6沿已确认基线，AGENTS保持原样。

评审来源：`review/interaction-{architecture,backend,browser}-review-20261015.md`。静态发现不冒充性能测量；确定性浏览器/协议测试与真实模型质量分列。每项记录复现、设计评审、修复、单元/集成及E2E证据。模型质量既有缺口仍保留。

## 响应目标与测量

- 点击后显示忙状态/禁止重复操作目标250ms；浏览器回归容许1秒调度上限，在受控慢响应返回前必须观察到，不能用最终页面成功代替。
- 同一WebSocket判分被受控阻塞时，心跳应500ms内处理，断连应500ms内取消本连接请求；使用阻塞门而非随机sleep模拟上游，旧结果不得改变暂停/新会话状态。现有协议没有显式WS pause，本轮不新增该消息或冒称其旧实现缺陷；后台暂停与REST继续路径独立做兼容回归。
- 普通REST总期限30秒，覆盖连接和响应体读取；显式取消与超时区分。不得自动重放写操作；超时/断网/5xx可能已经提交，不能提示为“肯定未保存”。调用方可为明确长任务指定期限并留设计依据。
- 重复中文朗读：同账号同课堂同文本成功播完后，后续段复用媒体，N段仍有N次实际playing/ended和成功回执。固定慢合成夹具比较请求数和各段等待；记录冷/热延迟，不将mock毫秒数当真实模型速度。
- 词条读取比较少量批次在大词库中的查询量/扫描量及保序语义；单用户和多用户样本报告p50/p95/max、样本数、数据规模与机器/并发条件。未实测指标标未测。

## 规格与SDD

### IX01–02 摸底保存完整性

加载成功后才开放编辑/完成；保存期间同步互斥，冻结词条修改、翻页和返回。保存成功才导航，失败保留原选择并展示恢复操作，禁止先导航再后台保存。慢请求/500/重复点击用真实用户路径锁定，服务端保存内容与界面选择一致。

### IX03 课程表状态语义

词库、通知、课程分别维护加载/失败/成功空数据状态。尚未成功获取课程时不能显示“去摸底”，加载失败不能冒充无词库；提供可达的重试。切库/重试的请求代次隔离，迟到旧结果不得覆盖当前选择。

### IX04 反馈草稿与送达不确定性

普通反馈发送期间冻结正文及取消，立即显示处理中。提交ID和原稿绑定；成功只消费该次提交，不能清理新草稿。超时/断网等未知送达保留同ID供查询/恢复，不生成新ID重复执行；明确应用拒绝才能恢复修改。沿既有幂等与澄清设计，不降低授权校验。

### IX05 REST 有界等待

统一请求层接收调用方AbortSignal及总期限；finally释放定时器/监听器。区分取消、超时、网络、非JSON/结构异常及应用错误，保留会话代次保护（旧401不能清新token）。异常消息不输出HTML或原始服务正文。GET可显式重试，写请求不自动重试；错误提示保留“结果待确认”的语义。

同类覆盖ASR/TTS媒体请求：网络响应头和响应体共用30秒期限与外部取消，Promise.race保证调用方有界退出，真实fetch同步abort；不得据此声称不响应取消的上游也已停止。录音、WAV转换和实际播放不计入网络期限。ASR不自动重发，TTS明确失败沿已有语音降级，但不能伪造播放完成；超时/取消不缓存。单测锁头/体悬挂、迟到结果、finally清理，浏览器锁等待后可恢复/改用文字。

### IX06 中文音频复用

仅浏览器内存缓存，不使用localStorage/共享服务器缓存。作用域为当前token+lesson，变化或登出/卸载即清空并失效旧lease；token与正文不记日志。最多16项、总Blob.size不超过8MiB、TTL5分钟，LRU命中不延长TTL。超大单条不缓存。

仅成功HTTP、合法完整WAV且实际播放结束后入缓存；请求取消、身份改变、合成/播放失败不入缓存，坏缓存播放失败即淘汰。读取、异步完成及写入均核身份和lease。缓存只复用已授权音频，不复用Audio元素/字幕状态/成功ACK；仍由业务play_tts指令驱动。固定模型/voice前提下5分钟可复用旧音色，未来可配置模型/音色须扩展key/revision，不承诺热切立即生效。

### IX07 同连接控制不被慢模型阻塞

一个读泵加一个有界FIFO业务worker，不为每帧无限创建goroutine。心跳独立处理；普通业务和历史WS resume保持FIFO，执行时重新校验课堂/turn/client/账号与取消状态，不能越序复活旧结果。读泵收包时仍核当前连接/账号。队列满明确断开并记录原因，依现有重连恢复，不静默丢弃。读失败先取消在途ctx并关闭连接，随后清理worker；跨连接/账号隔离。初审“WS暂停”是假设，代码复核确认不存在该显式协议，现修正为真实heartbeat/close缺陷，不虚构暂停红例。

### IX08 课堂词条按需读取

将为了少量ID扫描整个词库的路径改为按book+ID批量查询，保留调用方ID顺序、重复/缺失语义及跨库过滤。空ID不查全表；不得改变课程题目或洗牌顺序。规模回归以实际查询和结果验证，禁止单凭耗时猜优化生效。

### IX09 下行静默故障检测

连接后立即发心跳，只允许一个在途心跳；收到当前连接ACK后10秒再发，10秒未ACK判离线，因此正常前台调度下静默故障检测不超过20秒。检测门不等于恢复成功门：重新获取ticket有30秒期限，重连沿既有退避。重复/非在途ACK不推迟检测，旧socket的open/error/close/ACK不得影响新连接。

超时或send抛错时先失效socket身份并清定时器、通知界面离线一次，再close旧socket及安排重连；不等待黑洞中的close握手。登出/主动close取消所有定时器，不自动重发任何业务事件。后台标签计时延迟可能触发安全重连，不承诺后台20秒检测。Node假钟验证状态机，浏览器仅丢ACK（不主动close）验证离线提示/恢复及无业务重放，和IX07慢判分心跳可达一起验收。

## 用例与质量门

IX01–05覆盖慢响应、失败、恢复、重复点击、会话切换及数据完整性；IX06覆盖重复朗读、取消、错误WAV、超限、过期、LRU、换课/换账号、迟到回调；IX07覆盖同socket慢判分/反馈、心跳、断线、满队列及多学生+管理员同时使用，既有SessionTimeout暂停与REST/历史WS续课另作兼容回归，不新增WS pause协议；IX08覆盖大库小批次、顺序、重复/缺失ID、跨库与真实进入课堂。

所有测试由后台测试代理执行。设计确认后先红例再实现；产品保存点执行完整Go/vet/race与覆盖率、Node、lint/build、全部无头Playwright，新增用例并入docs03索引。最终交叉审查实现与文档/日志：trace_id、module、event、耗时及固定原因，禁止记录token/音频/反馈正文。全局持久化锁、Timer串行、首包体积等静态候选先量化，不把未测风险写成已修复缺陷。

## 执行台账

## IX13 身份小报文入口保护（已实施及实际复核；新树总验收待收尾）

只限制 `POST /auth/login` 与尚未初始化的 `POST /bootstrap`：完整JSON正文最多16KiB，包含UTF-8字节与尾随空白；从handler开始接收正文至读完最多10秒，覆盖Content-Length及chunked。使用Gin1.12的Unwrap与ResponseController设置连接读期限，不使用额外读goroutine；先完整有界读取再JSON解码，拒绝尾随第二对象、畸形/空/null正文，不以空凭据继续认证。合法小正文及Unicode正常处理。

超限实际HTTP413、接收超时HTTP408、JSON格式错误HTTP400，保持code/msg包装；固定日志事件 `auth/identity_body_rejected` 含route/reason/limit_bytes，不含用户名、密码、正文、token或底层错误字符串。拒绝时关闭该连接，避免未读正文影响后续请求；成功读取后恢复读deadline以允许正常keepalive。ResponseRecorder等无连接测试transport允许ErrNotSupported，但真实HTTP/TCP集成必须证明期限有效，其他设置失败应failclosed。

bootstrap先判断已有管理员，保持既有初始化封禁响应（HTTP200包装code403）优先，不先读取或解析请求体；不得因超限覆盖该封禁结果。不更改登录凭据规则、全局server读期限、导入、音频和其他API限额。

红绿覆盖：两入口Content-Length和chunked超限、有效小JSON后超量空白、真实TCP慢body10秒408及同期间另一正常用户可登录；合法Unicode/小body、畸形/null不触发login_failed或创建管理员、已初始化bootstrap封禁优先、成功后keepalive正常、日志无凭据。浏览器登录413提示及随后合法登录恢复另行E2E。无真实模型调用。

当前：设计及源码交叉评审已完成，定向红绿和隔离性能基线已有证据。最终Go覆盖率/竞态、全部浏览器旅程及真实TTS复播验收仍在收尾；不以中间保存点通过代替总验收。

## IX10 隔离压力证据与最小收敛

架构代理的 opt-in `interaction_baseline_test.go` 只在临时 SQLite/httptest 中运行（`-tags interactionbaseline`），无真实模型或用户库。初测 20 次/锁模式：200ms 取消的快照保存仍等 1000ms 释放连接，保存 p50/p95/max=1001/1030/1048ms；第二连接占 SQLite 写锁为1046/1087/1119ms。1000个已完成房间每次 SessionTimeout 扫描仍调用1002次快照 upsert（含2个未结束房间），10次扫描p50/p95/max=286/351/351ms。初测其他通知调度无屏障、两个未结束房间未 Start，故不据此给生产活跃课堂 SLA；复测加入 Create 进入屏障、独立请求计时及已 Start 的 scheduled 房间，原始证据不覆盖。

主审及后端交叉设计确认：

- `saveRuntimeContextLocked` 使用 `DB.WithContext(ctx)`，保留失败日志 `snapshot_failed/persistence_failed`，失败不更新内存快照。只兑现传入 context 合同；现有 `traceContext()` 的 Background 调用不因此自动关联所有 HTTP 取消。
- `Room.SessionTimeout` 在 Room 锁内对 `retired` 或已成功结算的 `finished` 直接返回，不生成动作/快照。不能仅按 `PhaseLessonEnd` 跳过尚未成功结算的房间；既有 Tick 结算重试保留。未结束房间实际到期暂停和未到期行为不改。
- 红绿覆盖取消保存不落库/不更新内存及失败日志，结束/退休房间零快照写，真实未结束到期暂停正例。E2E 使用隔离故障夹具验证失败可恢复和结课后仍可查看课报，不增生产后门。
- 修复后重测同一 reviewed baseline，报告比较 SQL 次数和耗时；不修改其他全局锁或调度并发。后台完整回归后才宣称 IX10 关闭。

JSON 初测发生在IX13实施前：1KiB至8MiB登录体均完整解析后返回普通认证失败200（8MiB约103ms）；2秒慢body未返回，另一请求可服务。这证明当时入口缺少小报文上限，不证明2秒以外永不超时。IX13随后针对login/bootstrap设计并实施局部限额与接收期限，保留合法导入/媒体较大合同；此历史body表不是IX13后的行为描述。

IX10 实际定向结果：红例确认预取消保存落库、占池取消仍等待、完成/退休房间仍写快照；最小两处修复后含既有超时正例4.544s通过。同reviewed夹具复测48.523s通过；20次池等待保存p50/p95/max由1003/1021/1028ms变200/204/205ms；1000完成房间扫描快照1002→2次，10次扫描p50/p95由219/263ms变0/1ms。独立SQLite写锁busy等待仍约1秒，未被WithContext立即终止。详情/数据边界见 `review/interaction-baseline-20261015.json` 与架构评审末节；E2E及全量待收尾，不提前关闭阶段。

### IX11 页面与课堂操作反馈补齐（设计及实际代码交叉复核通过，待最终验收）

- 答题提交采用epoch/turn同步单飞：WS发送成功立即显示“正在判分”并禁止该turn的按钮/Enter/自动识别再次提交；发送false不走REST且释放本地待处理态。后续业务phase/新turn/判分结果、暂停或断线使旧pending失效；不自行补发或扣机会。重复同turn的show_quiz_item不能解除尚未确认的pending。后端权威状态仍决定判分，暂未返回明确结果只提示等待/连接恢复，不伪造答题成功。
- 课报选择携带lesson ID和LatestRead代次，立即显示所选课号/加载态，失败原位重试，关闭或新选使旧读取失效；迟到旧课报不能覆盖新标题或重新弹窗。通知标已读单飞并显示忙状态，失败显式提示，只有真实成功后刷新未读数。
- 摸底词芯片可Tab聚焦、Enter/Space切换aria-pressed，保存/加载期间不可键盘修改；只处理明确激活键，其他键不得选词。删除图标按钮提供包含词库名的可访问名称。
- 本机录音与识别区分展示：实际MediaRecorder开始才标录音，结束转WAV/上传前标识别；观察回调检查token/turn/capture仍有效，旧回调不能改新题。录音4秒、模型期限和实际判分政策不改。

验收：Node锁同步singleflight/失败发送释放/同turn重放不解锁、LatestRead迟到拒绝及键盘激活策略；真实UI缓冲服务业务返回帧后连续点击/Enter只发1答案，释放后依真实判分继续；多课报实际HTTP反序和关闭迟到、通知500重试、纯键盘摸底保存DB一致；受控MediaRecorder结束后慢ASR请求展示“正在识别”而非继续“正在听”，换题/断线零旧状态污染。多用户隔离沿现有fixture，真实模型另轨。

### IX12 词库和管理操作串行化（架构交叉设计通过）

词库列表区分加载、失败和真实空列表，失败原位重试并取消卸载后的请求。选库同步单飞覆盖POST和成功确认弹窗整个生命周期；卸载只销毁本页弹窗并解除等待，迟到结果不能导航或影响新页面。选库结果未知先查询学生已选词库确认，不自动重发；查询失败保留待确认提示并提供查询恢复。管理员操作按动作键显示对应按钮loading，但提交期间冻结所有相关表单、词库选择和导入内容，避免提交快照与画面不一致。同步锁拒绝同一渲染周期重复点击，失败后释放。

用例：ExclusiveAction网络/弹窗两阶段并发与失败释放单测；浏览器词库加载500→重试、两词库快速选择仅一POST、弹窗未关闭不能再提交、未知选库结果查询恢复；管理创建/导入延迟期间仅本动作忙且所有输入冻结，失败保留输入并恢复。业务变更不自动重试、不改变教学策略。

IX12代码复审扩展：删除词库同样纳入单飞、弹窗归属与卸载/账号代次守卫；提交过程中禁取消，结果未知先查询词库再操作，禁止自动重删。管理操作每次await后核对页面生命周期与账号，旧成功返回不得启动使用新账号的刷新或弹旧成功提示；只取消读取，不将中止界面等待声称为撤销已发出的写操作。

媒体超时可观测：`media_request_timeout`记录module=speech、lesson trace、operation、timeout_ms和duration_ms，仅固定元数据；网络期限覆盖响应头和body。取消不是服务故障，不输出错误正文、音频或token。

### IX14 大库导入与选库的原子批量写入（已实施及提交故障定向通过；总验收待收尾）

独占SQLite基线确认1000条导入4049ms、首次选库2163ms，分别1000个独立Create事务；重复选库103ms无写事务。100条为258/266ms各100事务。此数据与race竞争下浏览器99秒导入分开，不据后者认定死锁。

导入继续逐输入验证并保留Skipped原始顺序：非法、库内已有和同批重复跳过，首条合法同词胜出，跨库同词允许。有效输入在单一仓储事务内提交，按输入顺序分配全局词条ID；读取key/ID、写入或commit失败及context取消均返回错误并回滚本次全部有效写，不再把存储故障伪装Skipped。SQLite词数仍由实际行count计算；MemRepo单锁准备副本后一次发布并更新count。旧无context入口包装Background，HTTP传请求context。

### 普通HTTP环境的安全请求标识兼容

本地局域网普通HTTP环境可能缺少`crypto.randomUUID`。统一`clientId`先用该接口，不存在或抛错时使用`crypto.getRandomValues`生成带正确version/variant位的UUIDv4；禁止以时间、计数器或Math.random替代。两种安全能力都不可用时，提交/事件ID生成明确失败，不发送缺失幂等标识的业务请求。仅诊断请求ID允许标记`unavailable`，不能因此阻塞普通REST读取。

本地`request_id`与服务响应`server_trace_id`分开；后者仅接受`X-Trace-ID`中1–128字符的字母、数字、下划线和连字符。日志不得输出token、正文或查询参数，也不把本地诊断ID冒充服务端trace。

验收边界：Node覆盖原生接口、缺失/抛错后安全回退、UUID格式及无安全随机能力时拒绝；API诊断ID失败仍能读取。Playwright禁用randomUUID后走真实登录、课堂和反馈提交，验证界面不中断且业务ID仍有效。实际结果并入最终Node/E2E报告；安全随机UUID不等于认证凭据，不承担鉴权。

### IX16 课堂工具事务分阶段定位（实际独审通过，五分支定向绿）

真实 D 盘课堂 `tts_finished` 到 `tool_called(committed)` 出现 15.545 秒间隔；同一审计行记录工具执行仅 1 毫秒。现证据只能定位到工具体之后，不能直接断言 fsync、锁等待或 SQL 插入。保持同步审计、事务提交后发动作、Room/agentWriteMu 锁和 ACK 合同不变，不调低 SQLite synchronous。

`callAgentTool` 的既有 `tools/tool_called` 增加固定非负整数毫秒字段：

- `lock_wait_ms`：调用前到取得 `agentWriteMu`；不含此前 Room 锁等待。
- `transaction_ms`：GORM Transaction 调用到返回，包含开始等待、回调和提交/回滚。
- `begin_wait_ms`：Transaction 开始至进入回调；若回调未进入则等于 transaction_ms。
- `config_load_ms`：事务内配置加载调用的耗时。
- `audit_write_ms`：事务回调内 persistToolAudits 调用耗时，包含 SQL 写入但不冒称单独磁盘耗时。
- `finalize_ms`：回调退出至 Transaction 返回，可能包含提交或回滚，不能命名为仅 commit。
- `rollback_audit_write_ms`：事务失败后独立记录失败审计的耗时，与 audit_write_ms 分开。

使用 Go 单调时钟差并截断到整数毫秒；内存路径各数据库/锁字段为 0。拒绝非可信 task/不可序列化参数仍保持原行为。字段不包含 SQL、Args、回答、用户名、原始错误或凭据；既有 lesson trace/task/tool/outcome 保留。记录这些阶段不改变任何业务结果，也不是性能修复。
