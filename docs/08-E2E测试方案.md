## 1. 工具链与运行方式

| 项 | 决策 |
|---|---|
| 运行器 | Playwright Test（`@playwright/test`） |
| 浏览器 | **Chromium headless**（CI 与本地一致；NF-08 的 Edge/Chrome 双核抽检用 `--headed` 手动触发，不入 CI 门） |
| 被测系统 | 各专项配置启动隔离 Go 后端与 Vite/preview；数据库和端口由配置/fixture 指定，不接真实学生库 |
| 账号 | 用例在隔离库中创建管理员及独立学生；多用户用不同 Chromium context |
| 时钟 | Go FakeClock 验证服务端定时；浏览器 `page.clock` 验证 UI 定时，不能互相替代 |
| 语音 | 确定性媒体 mock 验时序；`two-student-real-media.spec.ts` 以冻结 WAV、真实 MediaRecorder 和本机模型验证媒体旅程 |
| 证据 | 每次记录 Playwright 退出码、用例数、trace/结果 JSON；真实媒体还断言 `playing→ended`、字幕和唯一 ACK |

当前 `playwright.config.ts` 继承 `playwright.closure.config.ts`，只匹配 `bugs-regression.spec.ts` 和 `smoke.spec.ts`；其他族需显式指定对应配置。服务进程、端口和数据库由各配置管理。`E2E_SERVER_BINARY` 可指向本轮构建的 Go 程序。

## 2. 工程结构

主要可执行文件：`firstuse-regression.spec.js`/`firstuse-journey.js` 覆盖首用，`fulljourney.spec.ts` 覆盖课堂教学→跟读→最终测试→课报，`feedback-regression.spec.js` 覆盖反馈，`interaction-*.spec.ts` 和 `recovery-regression.spec.ts` 覆盖交互边界与恢复，`two-student-real-media.spec.ts` 覆盖本机双学生语音。`isolated-fixtures.ts`、`recovery-server.ts` 等负责隔离服务和账号；不要按旧的 `01-*.spec.ts` 蓝图寻找文件。

## 4. 覆盖率要求（E2E 门）

E2E 覆盖率定义两层，均须达标：

**页面/路由覆盖目标 =100%**，按当前 `web/src/App.tsx` 注册路由核对，不再使用下面的旧路由蓝图：

```
/login /books /placement/:bookId /dashboard /classroom/:lessonId
/classroom/:lessonId/voice-preflight /stats
/admin /settings
```

**P2 关键用户旅程覆盖（每个 FR 域至少 1 条绿路径）**：

| FR 域 | 旅程 | spec |
|---|---|---|
| A 账号 | 登录/改密/被踢 | firstuse/interaction |
| B 词库 | 导入→预览修正→发布→下架 | firstuse/interaction-import |
| C 摸底 | 全流程+断点续做 | firstuse/firstuse-journey |
| D 课堂 | 顺序教学/跟读/最终测试/RETEACH/续课 | fulljourney/recovery |
| E 记录 | stats 页数字与课堂结果一致 | firstuse/fulljourney |
| F 排课 | 首课/改期/逾期/计划视图 | firstuse/overdue-live |
| G 反馈 | A~D 意图闭环+超界确认 | feedback-regression |
| I Agent | Mock 双 Agent 决策可见（话术气泡/通知） | fulljourney/feedback-regression |

**验收门**：相关配置的 Playwright 退出码为 0，且用例数、失败、跳过与产物记录齐全；`package.json` 目前没有通用 `e2e` 脚本。

## 5. 准入与频率

- 改动先跑对应 Go 单测/集成测试和 Playwright 专项；阶段收尾再跑全量回归，并保存退出码与报告。
- 本机模型评估、真实媒体旅程与真人试点分别验收；合成 WAV 通过不代表真人麦克风、回声或噪声门通过。

## 6. 与既有测试的边界

| 层 | 工具 | 范围 |
|---|---|---|
| 单元/集成 | Go test（httptest+WS 客户端池） | 服务内逻辑与多用户并发；相关包用 `go test -race` 验证数据竞争 |
| 浏览器 E2E | **Playwright headless（本方案）** | UI 渲染/交互/时序/多 context |
| 本机语音 | 冻结 WAV、真实 MediaRecorder、8090 ASR/TTS | 传输、播放、字幕、回执与合成样本转写；不替代真人声学 |
| 真人试点 | 34 试点规格 | 发音、回声、插话、噪声、多人长尾及人工听感 |

## 7. 2026-10-13闭环与朗读设置专项

在 `web/` 下依次运行（专用端口与隔离数据库，不能同时运行三个配置）：

```powershell
npx playwright test --config=playwright.closure.config.ts
npx playwright test --config=playwright.firstuse.config.ts
npx playwright test --config=playwright.playback.config.ts
```

closure覆盖双学生隔离、反馈、跨通道重放、统计故障恢复、个人设置及暂停恢复协议；firstuse覆盖首启到课报/统计/下一课的默认3＋1流程；playback复用完整旅程验证2＋2及不同间隔、当前课冻结和下一课1＋1。具体增量用例见03第8节，实际报告见14。

使用构建后的 Vite preview 和无头 Chromium。媒体 mock 记录开始/结束时间以检验串行播放及最小停顿；暂停浏览器测试明确注入 WS 协议，真实会话超时由 Go FakeClock 验证。以上专项不能替代真实音频质量或 race 验收。当前 `package.json` 没有通用 `e2e` script，使用上列配置命令。

## 8. 反馈任务与会话恢复专项

在 `web/` 运行 `npx playwright test --config=playwright.feedback.config.ts`。与第7节三组顺序执行，使用各自新建的隔离数据库。可通过 `E2E_SERVER_BINARY` 指定本次源码构建的服务程序，省略则使用 Go 启动；不得复用其他项目或真实学生数据库。

专项覆盖两个学生和管理员的反馈归属、逐项结果、投诉待办、响应丢失查询、显式重试、改期后课表刷新，以及换账号/换登录凭据后的旧响应隔离。详细矩阵及实测报告见12 §8.5、§9；最终测试数以报告为准，不将用例清单视作通过证据。

浏览器识别和朗读采用确定性 mock；课堂 WebSocket 和后端 API 真实运行。网络丢包/乱序用明确的协议夹具，事务写失败用隔离 SQLite trigger；禁止新增产品故障注入接口。每次修复仍需对应服务层单元/集成证据，媒体 mock 不能替代真人音频验收。

## 9. 模型评估与普通回归的边界

普通 Go 回归不访问云模型。旧智谱真实接口测试仅在显式设置 `ENWORDS_REAL_API_TESTS=1` 时启用；离线 HTTP 替身覆盖协议、错误和取消。没有启用真实接口的测试报告必须如实保留跳过数。

在仓库根目录运行本机文本诊断：

```powershell
python review/evaluate_local_models.py --text-only --extended-pairs review/model-eval-extended-pairs.json --output review/local-model-evaluation-100.json
```

该脚本使用生产判分提示词，经8090平台执行100条精选标注题，报告模型结果、延迟与失败；不切换模型、不使用规则兜底。精选集通过不等于反馈意图、真实语音或随机样本泛化能力通过；模型比较应使用相同数据及超时预算。回归及评估由测试子代理后台运行。

## 10. 本机语音失败与双学生旅程

用例编号与断言以 03 的 ASR-F1/F2、MEDIA-2 为准。`interaction-boundaries.spec.ts` 注入 ASR 失败，使用真实页面操作覆盖跟读/答题暂停、刷新、文字继续、唯一提交与新题重新录音；Go 测试单独锁定 `epoch/turn`、`input_failed` 快照和恢复计时。`two-student-real-media.spec.ts` 在两个独立 Chromium context 中使用冻结独立 WAV 和真实 MediaRecorder，经本机 ASR/TTS 走完整课堂；断言实际播放、字幕、ACK 与课报，不以合成接口的 HTTP 200 替代可见课堂结果。双学生通过证据见 `review/two-student-real-media-20261112.md`，真人拾音与 4–8 学生中文朗读容量仍需另行验收。

多词业务闭环采用 `web/playwright.local-journey.config.ts`，对应 `web/e2e/local-journey.spec.ts` 的 MJ01、MJ02a、MJ02b、MJ02c、MJ03 与 CONF-RAW。先由当前源码构建独立服务二进制，再设置 `E2E_SERVER_BINARY` 在 `web/` 执行 `npx playwright test -c playwright.local-journey.config.ts`；配置固定 `-providers local` 与隔离 SQLite、无头 Chromium。六个英文跟读 WAV 和中文整句 WAV 均核对 manifest 标签与 SHA；记录逐词 `/transcribe` 状态/语义、WS 序号、字幕和 ACK。测试启动前确认 8090 的 `asr`、`tts`、`tts-en` ready；本段是用例入口说明，实跑结论另见报告。
