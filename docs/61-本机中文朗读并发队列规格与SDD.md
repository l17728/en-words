# 本机中文朗读并发队列规格与 SDD

## 故障与目标

双学生真实课堂一侧中文朗读 `503`。公开合成短语“老师”复现：8090 代理 N=2 返回 200/429；8002 直连也返回 200/429。8090 的 `tts.maxConcurrent=1` 与中文 TTS 进程的 `active` 单请求锁叠加；产品 API 将上游错误呈现为 503。目标是在不并行调用 Sherpa 原生 worker 的前提下，让 2–4 名学生的短段请求有界排队完成。

## 契约与状态

8090 `tts.maxConcurrent=2`，8002 后端保留最多 1 个合成 + 3 个 FIFO 等待者的有界实现；产品入口只放行两名同时请求。请求先通过 JSON/模型/长度校验，再入队；满队返回 429，并带可重试语义。等待不超过 12 秒；单次 worker 执行硬超时 6 秒，队列加执行总预算不超过 18 秒，低于产品 Go 的 20 秒。客户端在等待中断开或超时立即从队列移除，不执行旧合成。执行中的断连请求终止子进程并丢弃结果，但原生 worker 是否及时响应取消不可假设；槽位保留到子进程退出回调后再交给下一等待者。超时强制结束 worker 并确认 close/exit 回调后释放槽位。所有路径必须最终释放队列占用，不能出现永久 `active`。响应仅为有效 WAV 或明确 4xx/5xx；不得把失败伪装成已播放。Go 与课堂前端沿既有 `tts_failed` 暂停当前段，学生可重试或显式改用文字。

中文 TTS 日志只记录安全 trace ID、事件、等待/执行耗时、HTTP 状态与取消原因，不记文本/密钥。8090 转发受限格式的 `X-Trace-ID`。端到端观察从课堂 `lesson/turn/segment` 关联到产品合成请求和本地服务。

## 验收与回滚

先保存现有 `models.json` 和中文 TTS 服务源码哈希。使用公开冻结短语验证 8002 直连与 8090 代理 N=1/2/4/8 各 10 轮：试点基线先按 N≤4 均 200，N=8 允许后四个 429；若 N=4 未达则收敛到 N=2，并以 N=2 全 200 为业务门，但无 5xx；容量门 p95 <15 秒、无进程崩溃。另记录交互门 p95 <2 秒是否达标，串行 worker 若超出须明确记为未达，不能以容量通过代替速度通过。故意取消排队请求后不得看到其合成事件；故障注入 worker sleep >6 秒或执行中断连，断言 6 秒硬超时、子进程退出、下一等待者被唤醒、健康检查与 active 计数归零；失败须暂停原段。再跑真实双学生 Playwright 课堂：两侧中文段均实际 `playing→ended`、字幕与 ACK 唯一。服务故障旅程须暂停当前段，不自动推进。

不达标时恢复原配置 `tts.maxConcurrent=1` 和原中文 TTS 服务源码，重启相关进程；ASR、英文 TTS、Picer 与文本模型均不变。容量通过仅说明合成样本与双学生浏览器场景，不替代真人课堂音质/噪声验收。

## 受控试点结果（2026-11-12）

中文代理 N=1×10 为 10/10 200、p95 3.917 秒；N=2×10 为 20/20 200、p95 5.699 秒；N=4×10 为 39/40 200、1 个等待超时 429、成功请求 p95 12.864 秒；N=8×10 为 40/80 200。8002 直连 N=2 为 6/6、N=4 为 12/12。故 N=4 原容量门未达，平台上限收敛为 2；N=2 业务成功门通过，但 p95 <2 秒交互门明确未达。单次 worker 每次重新加载 Sherpa 模型，无常驻复用；本轮只修业务并发，性能优化后续独立设计。隔离故障注入：10 秒挂起 worker 在约 6.0 秒收到 SIGTERM、exit/callback/close 后释放槽；排队取消请求未进入 worker，后续请求恢复。最终 maxConcurrent=2 配置下公开短语双并发再测 3 轮 6/6 HTTP 200，耗时 2.954–8.955 秒，8090 active=0、failures=0；最终双学生浏览器严格旅程 1/1 通过，详见 `review/two-student-real-media-20261112.md`。
