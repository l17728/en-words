## 四层架构：平台 + 开放能力 + 智能体 + 用户

本软件不是"带 AI 功能的 CRUD 应用"，而是**双智能体协作平台**：

```
┌──────────────────────────────────────────────────────────────┐
│ 用户层    学生（学习/反馈）          管理员（词库/账号）        │
├──────────────────────────────────────────────────────────────┤
│ 智能体层  老师 Agent（课堂实时授课：节奏/话术/TTS/判分/鼓励）   │
│          系统 Agent（教务：排课/评估/调参/反馈处理/预警）       │
├──────────────────────────────────────────────────────────────┤
│ 开放能力层  Tool Registry：平台全部能力注册为工具（skill）      │
│            统一 JSON Schema 定义 · 角色作用域授权 · 风险分级    │
│            Agent 通过 function calling 调用 → 校验 → 审计      │
├──────────────────────────────────────────────────────────────┤
│ 平台层    课堂运行时 · 调度器 · 配置中心 · 学习记录 · 词库      │
│          反馈中心 · 用户认证 · WebSocket 协同 · TTS/ASR 服务   │
└──────────────────────────────────────────────────────────────┘
```

- **平台**：纯能力提供者，不含决策逻辑的硬编码；所有业务行为都以 REST/WS API 提供。
- **开放能力**：每个 API 能力注册为带 JSON Schema 的工具，按 `student / teacher_agent / system_agent / admin` 作用域授权，带风险分级与审计——这是系统的"插头面板"。
- **智能体**：两个 LLM 驱动的 Agent（先 Mock，后接阿里 DashScope qwen）。感知→决策(工具调用)→执行→观察的事件循环。
- **用户**：学生按 UI 学习、提交反馈；管理员维护词库与账号。

### 核心设计理念：Agent 即人（2026-08-23 定案 D-15）

> **平台开放所有能力，Agent 像人一样使用开放能力，与学生交互完成"教学 → 分析 → 改进"循环。**

平台与 Agent 的职责分界以"学校"类比：

| 类比 | 平台（学校设施） | Agent（教职工） |
|---|---|---|
| 定位 | 教室/题库/成绩册/排课系统——**无意志的能力** | 老师/教务老师——**有教学法的决策者** |
| 提供什么 | 31 个已注册工具：展示/朗读/出题/判分/排课/调参/记录/通知等；管理 REST 能力另列，见16及工具目录 | 全部行为=工具组合的"教学行为" |
| 不做什么 | 不决定"下一步教什么/怎么鼓励/何时调整" | 不绕过平台直接改状态（只经工具，全程审计） |

由此派生四条铁律（评审/实施的裁判标准）：
1. **决策在 Agent**：任何"因学生表现而改变教学行为"的逻辑（节奏/鼓励/调参/排课审视）必须位于 Agent 决策表（04 文档），平台只提供数据与执行工具——发现平台侧硬编码教学决策即为设计缺陷。
2. **平台确定性**：状态机/调度器/判分 L1 等机械逻辑平台负责（快路径），保证断线可恢复、Agent 可替换——Agent 崩溃课堂不卡死。
3. **一切经工具**：Agent 的每个动作（含说话）都是工具调用，scope+schema+审计三重约束；没有"后门"。
4. **闭环可观察**：教学(课堂事件)→分析(课报数据)→改进(工具调用)→再教学，每环有 trace_id 串联，管理端可回放整循环。

### Agent 自维护记忆（2026-08-23 定案 D-16）

> **记忆是 Agent 的，不是平台的**：平台仅提供记忆读写工具（`memory.append/memory.recall` 等，同其他工具一样走 scope+schema+审计）；**写什么、何时写、如何归纳，全部是 Agent 的教学决策**——如同老师自己记备课笔记与学生档案，学校只发笔记本，不替老师写教案。

| 记忆类型 | 归属 | 生命周期 | 内容（由 Agent 决定写入） |
|---|---|---|---|
| **学生档案** | 每生一份 | 跨词库持久 | 称呼偏好/性格观察（爱鼓励还是爱激将）/整体弱项（发音弱？拼写弱？）/家长嘱托/历史课报要点摘要 |
| **教学任务记忆** | 每生×每词库 | 计划生命周期 | 教学笔记（哪几个词全班易错、哪个策略有效）/已尝试的调整及效果/学生承诺（"周三要请假"）/计划变更原因链 |

用途：老师 Agent 课堂话术与节奏的依据（如档案写"对激将法反应好"→OP-6 类话术权重上调）；系统 Agent 排课审视时 recall 任务记忆里"上次降量原因"。**课堂事件/判分明细等客观数据不是记忆**（已有 classroom_events/quiz_items 表），记忆只存 Agent 的主观归纳。

## 核心理念（贯穿全部文档）

1. **协作软件**：同一节课的 UI 同时服务学生和老师 Agent；Agent 通过 WS 下发 UI 指令（action 级模拟点击），学生照屏幕学习。
2. **科学记忆**：依据《别再被艾宾浩斯曲线"骗了"》的结论——**等间隔复习**优于"前密后疏"，间隔按目标可配置；连对毕业进入长周期维护。
3. **全配置 API 化**：一切参数可配置、带边界校验、有审计日志；Agent 与管理员共用同一套 API。
4. **反馈驱动自适应**：学生反馈 → 系统 Agent(LLM) 解析意图 → 边界内自动调整配置/推迟课程 → 回复确认，全程留痕。

## 技术栈（当前清单与历史基线）

- 前端：React 19 + Ant Design 6 + Vite 8 + TypeScript 6 + Zustand 5；用户于2026-10-14确认保留当前版本，替代历史React18/AntD5基线，ADR与锁定版本见01、16，最终兼容验证另记录
- 后端：Go 1.25+（以server/go.mod为准）/ Gin / GORM / SQLite（单文件，家用零运维）
- 实时：Gorilla WebSocket（课堂协同）
- AI：当前优先接入本机8090模型平台（文本/ASR/中文TTS），保留Mock回归及旧供应商兼容；真实音频质量仍待独立验收，详见09、10
- 部署：单机/局域网，1 管理员 + 1~5 学生
