# 流式语音影子模式设计评审记录（2026-11-13）

## 评审范围

评审 `docs/79-流式语音影子模式与确认提交-SDD.md`，对照现有 `web/src/audio/duplex/`、`web/src/ws/client.ts`、`server/internal/api/ws.go`、`server/internal/api/ingress.go` 和 `providers.go`。

## 结论

采用 v1 影子协议：UTF-8 JSON + base64 PCM16，禁止 binary opcode；解码后单块 2560 字节、单流 15 秒（最多 188 块，末块可短）/480000 解码字节，wire base64 单块不超过 6400 字节，单学生单活动流。start_ack 后服务端生成 session/stream generation 和 input_revision；旧 stream、旧 revision、缺序号、超限、跨账号/课堂请求都拒绝并降级文字。第一版在 end 后复用已有本机 `/transcribe`，不伪造 interim ASR；draft 只展示采集/VAD 状态。

确认提交使用独立 `voice_confirm`，沿用现有判分与幂等入口，不放宽 epoch/turn 校验。确认回执以学生/课次/utterance 唯一键持久化，确认重试返回原 receipt，文本 SHA-256 不一致返回错误。确认前不判分、不耗机会、不推进、不写成绩；手打优先和迟到 final 均有明确拒绝原因。

## 评审意见闭环

| 领域 | 结论 |
| --- | --- |
| 架构 | 先做影子传输和 end 后转写，避免把现有批量 provider 假装成流式 provider；自动教学不在本阶段。 |
| 后端/安全 | JSON schema、大小/时长/并发/序号限制、账号归属和原文不入日志已冻结。 |
| 前端 | 保留 4 秒录音和文字路径；特性关闭时不请求麦克风；旧 generation 回调只清理不复活。 |
| 测试 | 每个缺陷必须同时补 Go 和 Playwright；覆盖乱序、重复、取消、迟到、确认幂等、双学生隔离和降级。 |
| AI/模型 | v1 不要求 interim ASR；本机 provider 不可用时显式回文字，不切云端。 |
