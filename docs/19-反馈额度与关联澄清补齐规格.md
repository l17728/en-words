# 19 反馈额度与关联澄清补齐规格

状态：设计已获主代理交叉复核批准，后端和前端已实施，确定性Go/SQLite与浏览器回归通过；真实模型与媒体总验收另行保留。实施不修改既有 submission_id 幂等和逐意图事务语义。覆盖04 S-06/S-07/S-09，补齐16剩余策略。

## 月度主动请假额度

Agent 决策接口接收同学生同提交月已成功改期次数，阈值3返回确认回复；平台只查询事实和执行。月份固定为原任务 CreatedAt 的本地自然月，跨词库共享；数据库以已成功 applied 的 D_postpone 意图 receipt 计数，不另外维护易失步计数器。失败/need_confirm/cron不计数，重复恢复跳过完成意图。逐意图执行事务内再次读取额度事实并调用 Agent 决策；额度满时当前执行结果为 need_confirm，仅调用 feedback.reply，不能写课程/记忆。冻结计划保留原请求，结果记录月/已用次数/limit，不伪称应用。两个实例争最后额度由原有 SQLite 首写事务串行化。内存通过 withFeedbackWork 全局事务锁实现相同语义。

## 难词池 FIFO

补充验收约束：月额度 need_confirm 是本任务终态提示，现无允许绕过额度的确认写接口；多D意图每个实际成功 receipt 各计一次。父澄清只能据已完成 result=status clarify 验证，认领与安装计划同事务，失败回滚；父拒绝后的尚未安装计划子任务必须清理，不能留下不可恢复的幽灵任务。

Agent 定义容量20，工具调用把明确容量策略交调度服务。Card/持久 MemoryCard 新增 BoostSequence（默认为0兼容旧数据）；每学生+词库内新激活使用历史最大序号+1，已激活重复不刷新年龄。若池满，按 BoostSequence、WordID 淘汰最旧，设置新卡标记和序号；词库间完全独立。旧活跃标记且序号0按 WordID 确定性排在新激活前，不丢弃旧标记。跨多个词库命中的一次反馈全部在原意图事务内处理，任一失败全部回滚。结课消费 BoostFlag=false，保留历史序号使后续重新激活获得更大序号。返回实际加强词与淘汰词摘要，日志只记ID/数量。

## 显式关联澄清

加强结果 `actual` 保留 `resources/count`，新增 `boosted_word` 和 `evicted_words:[{book_id,word_id,word}]`；词面只来自当前学生获授权的词库，前端据此显示成功淘汰摘要。任何淘汰词读取错误回滚整个意图，不显示未提交成功。工具日志仍只记ID。

提交协议可选新增 `parent_submission_id`；不传时维持旧行为，语音新反馈仍默认独立提交。服务端从父任务派生 conversation_id（首个父 task_id），客户端不能提交学生ID或任意 conversation_id。父任务必须归属当前学生，已经完成且含 clarify 结果，未被另一个子任务占用；别人任务返回不可用，不泄漏正文。新提交ID搭配同正文但不同父ID视为幂等冲突。

安装子任务冻结计划的事务内原子认领父任务 `clarification_child_task_id`：空值→本子任务；相同值可恢复；其他值返回 clarification_already_answered。父ID不可引用自己或未完成任务，因此不会产生循环。父任务是明确提问上下文，本次模型仍只解析新正文，不把任意历史 G_other 自动累计。Agent 的反馈输入增加 ClarificationReply；该输入为真且当前意图仍需 clarify 时，改为 escalate+reply_escalated（仍保留原 G_other 类型），其他清晰意图正常处理。完成结果只一次管理员待办/通知。系统缺管理员或存储失败时按原可恢复/终止规则输出，不假称已转交。

前端在 clarify 结果显示“补充说明”，打开正文输入并携带父 submission_id。子提交前草稿保留；网络失败沿用同一子 submission_id 查询/恢复，不生成新ID覆盖旧任务。明确显示这是回复哪条反馈；换账号清态、父反馈已被其他标签回复时提示刷新，不自动改成独立提交。协议新增字段在列表/详情一致返回。
