# Pilot VFS EEXIST Evidence-Layer SDD

## Status and purpose

This design amendment resolves a circular acceptance dependency between docs/55's runtime-derived SQLite callback flags and its private VFS `openat2(O_CREAT|O_EXCL)` collision behavior. It does not approve a production VFS, A0, or product route. Until domain review passes, docs/55 and docs/56 remain normative.

## Evidence layers

The host `unix` VFS trace is an oracle for SQLite 3.45.1 callback inputs and outputs (`xOpen` flags, role, `pOutFlags`, callback ordering and SQLite result). It is not an oracle for Pilot VFS syscalls. If a host run does not issue an exact-WAL-path `O_CREAT|O_EXCL`, the host EEXIST candidate remains `NOT RUN`; do not inject EEXIST into a different syscall or relabel the observation.

The VFS-flags golden therefore contains only callback facts observed from the pinned SQLite amalgamation and host VFS, with the source ID, platform and trace scope. It may be generated without asserting private syscall behavior. The private adapter's exclusive-create race is a separate callback-manifest case and native acceptance requirement, not a prerequisite input to the SQLite callback-flags golden.

## Private adapter EEXIST case

The adapter cases start with an already registered sidecar generation and its retained identity FD. For the second `xOpen` carrying CREATE|EXCLUSIVE, acquire and hold docs/55 locks in order (generation registry, lifecycle OFD lock, process namespace mutex) **before** attempting `openat2(O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC)`. Keep all locks continuously held through the syscall, EEXIST inspection, reopen, validation, final name check, and handle publication; `xDelete` and other namespace operations use this same order. The fixture does not introduce an out-of-boundary namespace writer. Once kernel EEXIST is returned, first inspect root-relative using `openat2(O_PATH|O_NOFOLLOW|O_CLOEXEC, RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_MAGICLINKS|RESOLVE_NO_XDEV)`; require regular-file type, exact owner and group, mode 0600, `nlink=1`, and pinned mount. Obtain mount identity from each pinned FD with `statx(fd,"",AT_EMPTY_PATH,STATX_MNT_ID)` (or an equivalent kernel API that returns the mount ID for that exact FD); do not infer mount identity from device/inode. Only then open the usable FD with no-follow flags; read access/default ACL xattrs from this regular-file FD, accepting only `ENODATA` as absent. Compare its device/inode/mount identity with both the O_PATH FD and the already registered generation FD, then perform final `fstatat(rootFD,name,AT_SYMLINK_NOFOLLOW)` and require the same identity before publishing the handle. Retain the usable FD; never adopt a new generation on this path.

The fixture actor is the test process running under the same dedicated service UID and same test-owned directory; it seeds the registered FD/name state before the measured `xOpen`. The actor is not an untrusted concurrent writer and the test proves no such writer is relied upon. A separate name-replacement fault hook may swap the directory entry only at a named point to test fail-closed behavior; this is synthetic fault injection, not evidence that hostile same-UID writes are safe. Foreign inode, invalid metadata/group/ACL, ACL query error, FIFO/device, symlink, hardlink, wrong mount, final-name drift, or open failure must fence and return `SQLITE_CANTOPEN`, close temporary descriptors exactly once, leave namespace unchanged, retain the old generation identity, and keep application SQL dispatch at zero. No colliding object is unlinked or rewritten.

Each negative adapter subtest has an independent stable ID and asserts the same failure contract (the vector-specific rejected property is listed below):

| Subtest ID | Fixture mutation | Required rejection and common oracle |
| --- | --- | --- |
| `VFS-EEXIST-FOREIGN-INODE-01` | Existing regular inode B replaces registered inode A before measured xOpen | Device/inode/mount identity mismatch; fenced `SQLITE_CANTOPEN`; zero SQL dispatch; no adapter namespace mutation; A remains the registered generation. |
| `VFS-EEXIST-GROUP-01` | Reopened regular file has a group different from configured egid | Group check fails before handle publication; same common failure oracle. |
| `VFS-EEXIST-FIFO-01` | Existing name is a FIFO | O_PATH type check rejects before a potentially blocking usable open; same common failure oracle. |
| `VFS-EEXIST-DEVICE-01` | Existing name is a device node in a privileged fixture | Non-regular type rejects before usable open; same common failure oracle. |
| `VFS-EEXIST-SYMLINK-01` | Existing name is a symlink beneath the root | `O_NOFOLLOW`/RESOLVE checks reject; same common failure oracle. |
| `VFS-EEXIST-HARDLINK-01` | Regular candidate has `nlink != 1` | Link-count check rejects; same common failure oracle. |
| `VFS-EEXIST-WRONG-MOUNT-01` | Candidate resolves on a different mount | `RESOLVE_NO_XDEV` or mount-ID check rejects; same common failure oracle. |
| `VFS-EEXIST-NAME-DRIFT-01` | Synthetic hook replaces the final directory entry after usable open but before final `fstatat` | Final name/FD identity comparison rejects; same common failure oracle. The hook's namespace change is test setup and must be separately accounted for; the adapter itself performs no mutation. |
| `VFS-EEXIST-ACL-QUERY-01` | ACL query returns an error other than ENODATA | Fail closed before publication; same common failure oracle. |

For every subtest, assert the old generation remains registered, no adapter unlink/write/rename occurs, every temporary FD is closed once, and no application SQL statement is dispatched. ACL-presence and unsupported-query cases additionally reuse `VFS-ACL-SIDECAR-ACCESS-01` and `VFS-ACL-SIDECAR-QUERY-UNSUPPORTED-01` manifest rows; this stable subtest supplements rather than replaces those callback rows.

The reviewed existing manifest mapping is fixed as follows. The loader must reject a manifest missing or renaming any of `VFS-OPEN-SIDECAR-01`, `VFS-OPEN-SIDECAR-02`, and `VFS-OPEN-SIDECAR-07`, even when row count and uniqueness remain valid; it also validates each row's callback, object role/name, CREATE|EXCLUSIVE flags, EEXIST result, registered-generation relation, SQLite result, generation/fence oracle, success `out_flags`, exactly-one/zero application SQL dispatch, and the exact barrier list:

| Manifest row | Test case and barrier | Expected oracle |
| --- | --- | --- |
| `VFS-OPEN-SIDECAR-01` | WAL; first xOpen registers inode A and retains its FD; repeat CREATE|EXCLUSIVE under all three held locks; barriers `eexist.wal.same.after_eexist_before_inspect`, `eexist.wal.same.after_opath_before_open`, `eexist.wal.same.after_open_before_final_name`, `eexist.wal.same.before_publish` | At every barrier assert registry, lifecycle, and namespace locks remain held. Safe reopen of inode A succeeds; generation does not advance; `pOutFlags` match the host SQLite golden; manifest asserts exactly one post-ready read dispatch. |
| `VFS-OPEN-SIDECAR-02` | Journal; first xOpen registers inode A and retains its FD; fixture replaces the name with valid inode B before the measured call; repeat CREATE|EXCLUSIVE under all three held locks; barriers `eexist.journal.foreign.after_eexist_before_inspect`, `eexist.journal.foreign.after_opath_before_open`, `eexist.journal.foreign.after_open_before_final_name` | At every reached barrier assert all three locks remain held. The registered-identity mismatch is detected after the usable FD opens and before any publish barrier; return CANTOPEN/fenced, with no generation advance, no namespace mutation by the adapter, all temporary FDs closed once, and manifest asserts zero application SQL dispatch. |
| `VFS-OPEN-SIDECAR-07` | Journal; first xOpen registers inode A and retains its FD; repeat CREATE|EXCLUSIVE under all three held locks; barriers `eexist.journal.same.after_eexist_before_inspect`, `eexist.journal.same.after_opath_before_open`, `eexist.journal.same.after_open_before_final_name`, `eexist.journal.same.before_publish` | At every barrier assert registry, lifecycle, and namespace locks remain held. Safe reopen of inode A succeeds; generation does not advance; `pOutFlags` match the host SQLite golden; manifest asserts exactly one post-ready read dispatch. |

The fixture must separately prove the EEXIST syscall occurred and the retry used no CREATE/EXCLUSIVE flags; merely observing two `xOpen` callbacks is insufficient. In all rows the trusted test process owns the root and seeds registry/FD state; the foreign-inode row alters the name only in controlled setup before the measured `xOpen`, never concurrently as an untrusted actor. Reached-barrier timeout, malformed control, missing retry, or failed cleanup is FAIL; only failure to establish a required precondition before any EEXIST syscall is NOT RUN with a measured reason. Reuse existing callback rows `VFS-ACL-SIDECAR-ACCESS-01` and `VFS-ACL-SIDECAR-QUERY-UNSUPPORTED-01` for sidecar ACL presence/query failure; add group, FIFO/device, symlink/hardlink, mount and name-drift vectors to the relevant adapter subtests and assert zero SQL dispatch. Linux amd64/arm64 ext4/XFS acceptance remains mandatory.

## Required document and manifest synchronization

On approval, perform these edits in order: (1) revise docs/55 so the host-derived flags golden records only observed SQLite callback facts and private adapter EEXIST behavior is an independent acceptance case; (2) revise docs/56 so the host candidate can truthfully remain NOT RUN and the three manifest rows map to the adapter cases above; (3) add `design_amendment` path/hash to the 80-row manifest while retaining docs/55 as `source_sdd`, regenerate docs/55 source hash and manifest hash, and update the exact-hash loader/review binding; (4) review the synchronized documents, manifest, loader and test map before implementation. No test status changes from design-only until execution evidence is bound to the exact reviewed implementation hash.

## Review and acceptance

Architecture, backend, security and test-design review must approve this exact amendment and its manifest mapping before implementation changes. After approval: synchronize docs/55/56 and the manifest; implement the private adapter; add unit/integration regressions; then run the pinned SQLite callback, crash/reopen, race, coverage, and native privileged filesystem matrix. Candidate `unix` traces remain noncanonical evidence and cannot be promoted into production syscall claims.
