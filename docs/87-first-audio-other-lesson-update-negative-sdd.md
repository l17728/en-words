# First-Audio Other-Lesson UPDATE Negative SDD

Date: 2026-10-29
Status: design/security/test review approved; implementation not started.

## Goal and boundary

Prove that a valid token and active PREFLIGHT transaction bound to lesson A cannot authorize the approved UPDATE trigger to inspect or accept lesson B. The trigger source itself is allowed, so rejection must come from the typed row projection and challenge binding, not from an authorizer shortcut. This is one component negative only; it does not satisfy the guarded-App/listener-factory or full docs/78 matrix gates.

## Isolated real-SQL case

Use a fresh same-binary child process with a unique marker, restricted `-test.run`, 30-second deadline, capped output, and parent `cmd.Run()` reap. Use the existing synthetic 18-column, dynamic-typing lesson fixture and checked-in trigger manifest; do not describe it as the production database schema. Register the test harness row-guard UDF that implements the reviewed projection/challenge policy; runtime production UDF registration is not claimed. On one tracked, pinned SQLite connection, create the table, then seed A and B with unique IDs and distinct values, then install the approved manifest triggers. Before the candidate transaction, assert the trigger names and DDL inventory exactly match the manifest and capture a full typed snapshot containing both rows.

Under PREFLIGHT, consume A's one-use token exactly once on the same transaction and connection; assert consumption precedes the projection read, keep `defer zeroFirstAudioSecret(token)` as an early-failure safety wipe, and explicitly call `zeroFirstAudioSecret(token)` immediately after successful consumption. Read A's exact 18-column typed projection using the test harness projection-read permit and retain it as the expected OLD projection. Then, under `PROBE_SQL`, execute only `UPDATE main.lessons SET id=id WHERE id=?` with B's ID. Capture actual authorizer callback tuples in a test-only recorder and assert the exact `PREFLIGHT/PROBE_SQL/SQLITE_FUNCTION/db=""/source="fa_lessons_guard_update"/arg1=""/arg2="first_audio_row_guard"` tuple occurs once and is allowed, with no unexpected denials. The test harness row-guard callback runs once, observes B's differing OLD projection, records the mismatch category, returns false, and the approved trigger's `CASE WHEN first_audio_row_guard(...)=0 THEN RAISE(ABORT,'first_audio_guard') END` aborts the statement. Assert the observed SQLite trigger-abort error, one callback, zero successful row observations, and receipt state `firstAudioGuardProbeTokenConsumed` before cleanup (never complete). Diagnostics may record only callback result/state, never token bytes.

Use the real-SQL test harness lifecycle owner to roll back the active transaction under the one-use PREFLIGHT cleanup permit. These coordinator types currently live in `_test.go`; do not describe them as production runtime. Require confirmed rollback/autocommit; challenge invalidation must move the incomplete receipt to `firstAudioGuardProbeFailed`. Compare the post-rollback full snapshot with the pre-probe snapshot; this full readback proves both A and B rows are unchanged without adding a separate B read permit. To test missing-receipt rejection, acquire the lifecycle transition lease and submit a valid JOURNEY candidate with matching binding evidence and the failed receipt; require `Publish` to reject because the probe denial is already registered, and assert the controller is terminal. Do not claim the internal `matchesPreflight` matcher ran: `Publish` rejects earlier on `hasProbeDenialLocked`. Do not call the low-level publisher directly as evidence of receipt enforcement. Log trace ID, exact authorized trigger tuple, mismatch category, callback count, token result, rollback result, receipt state, snapshot result, and transition outcome; never log token material.

Register pool and pinned-handle cleanup before transaction setup and register candidate cleanup last, preserving LIFO rollback/terminalization before handle release on all assertion failures. Keep fixture setup outside the authorizer only before its installation. The test must fail if SQLite does not report the expected approved trigger source or if the row guard does not run exactly once.
