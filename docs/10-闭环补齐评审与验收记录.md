### 第二轮代码评审

独立静态评审发现并修订：复合快照 key 解码、REST 结课摘要缺失、卡片预留错误传播、完成时间并发访问、配置 Reload 竞态、内存模式重复调量、坏快照恢复时错误重置。对可解析但无合法相位的快照明确报错，不能重新 Start 覆盖已有进度。

内存模式部分写入失败时，用冻结的绝对结算目标重放，避免已保存卡片重复进阶；它不承诺进程崩溃后的恢复，持久化验收必须使用 SQLite。SQLite 实现把所有确定性完成副作用合并在同一事务，事务内无模型调用；这替代了初稿的多个 outbox 任务，而非宣称已有通用 outbox。

末轮静态复核确认新增事件上下文覆盖朗读段、重教/回顾段、题目、答题阶段与暂停状态；同一状态往返采用单调版本，旧录音不会因暂停后恢复而重新有效。WebSocket 活跃连接在执行锁内复核。课堂按 turn 重置计时，本机媒体另计有界服务预算；重复快照不续期。已补故障快照、结算部分失败、日志隐私、迟到/重复事件及计时回归。这里只确认静态修复，未确认编译与运行。

完整首启 E2E 现覆盖管理员初始化→学生/词库创建发布→学生摸底→反馈→两词教学→错答重教→终测→课报→下一课。浏览器语音明确使用 mock，每段延迟 1.6 秒并检查全部播放完成，以暴露旧的跨段累计超时；该用例不测试真实音质。新增测试分散于 `localmodel/client_test.go`、`api/*regression_test.go`、`api/ingress_test.go`、`scheduler/settlement_retry_test.go` 与前端两个专用套件。

### 本机模型结果与选择依据

平台报告文本模型 `Qwen/Qwen3-VL-8B-Instruct-GGUF:Q4_K_M`、ASR `qwen3-asr-1.7b`、TTS `sherpa-onnx-vits-zh-ll`。原始 20 题判分 19/20，指令注入题误判；使用与生产相同的修订提示词后 20/20，耗时约 187–2688ms。仅小样本，不能据此确认通用能力或正式准确率。

中文“苹果”合成生成 WAV，但转写成“听过。”；该回环总耗时约 27.7 秒。英文合成一次超时、复测 HTTP 错误。不能判断问题只在 TTS 或只在 ASR，需要固定异源录音和真人听测拆分定位。当前音频未达到产品验收要求。尚无证据要求更换文本模型；下一步先修/比较本机语音链路，再以相同标注集比较其他模型。没有修改平台模型、读取平台密钥或调用互联网模型。
