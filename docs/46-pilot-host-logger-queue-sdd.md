# Pilot Host Logger Bounded Writer Queue SDD

**Status:** Implemented and reviewed slice (2026-10-20); native Linux acceptance passed on ext4 and XFS. This design is constrained by `docs/45-pilot-run-root-bootstrap-sdd.md` and covers only the bounded host logger queue. Trusted launcher, listener registration, RunRoot outbox orchestration, and product integration remain separate acceptance gates.

## 1. Problem and goal

`hostLoggerStore.AcceptPacket` currently holds the store mutex while it writes and syncs JSONL. A slow `Sync` can block all runs and exceed the two-second ACK deadline. This slice moves durable I/O to one bounded writer while keeping ambiguous outcomes fail-closed.

## 2. Admission and resource contract

- Preserve canonical validation, peer/process binding, per-run/global token buckets, deduplication, and exact ACK correlation. Charge one rate token for every received frame from an authenticated, registered run context before parsing/deduplication/capacity fast paths, including malformed frames, identical pending retries, durable replays, and digest conflicts. A silent receive timeout consumes none; peer/context failures are rejected before token accounting. Refill and debit each bucket independently for every such received frame: decrement each bucket when it has a token, leave an empty bucket at zero, and allow the frame only when both buckets had a token. Thus a frame rejected by one exhausted bucket still consumes any available token in the other. A structurally valid rate-rejected frame receives its correlated `rejected` ACK without append when bounded ACK-waiter capacity is available; if waiter/byte capacity is itself exhausted, reject without allocating state or ACK, and the caller applies the phase-specific no-ACK rule. Malformed frames receive no ACK. The rejected ACK is never a durability receipt. The deadline begins when a handler claims a run context, before socket receive, and covers receive, validation, admission, queue wait, append, `Sync`, and ACK send.
- Use per-run FIFOs with round-robin selection across active contexts. Preserve order within each run. The single writer serializes append and `Sync`.
- Count the complete canonical SOCK_SEQPACKET frame bytes (envelope plus event) for queued and in-flight work against both limits: at most 4 MiB per run and 64 MiB globally. One durability job owns exactly one frame charge through writer completion, even if its original waiter cancels after dequeue; that job charge is released when append/`Sync` finishes. Each additional deduplicated waiter owns a separate frame charge until ACK/cancellation. ACK waiters remain capped at 16, bounding post-`Sync` handler state independently. Reject over-capacity before allocating a job or waiter. Also cap pending jobs at 4,096 and live ACK waiters at 16 (one active packet handler per each of at most 16 registered contexts). Each SOCK_SEQPACKET frame remains capped at 16 KiB.
- Identical pending retries may share one immutable durability job, but each waiter retains its own expected ACK tuple and delivery nonce and receives a separately encoded ACK only after the shared `Sync`. Conflicting bytes for the same dedup key are rejected. Cancellation before admission creates no job. Cancellation while queued removes only that waiter; if none remain and the job has not entered the writer, remove the job. If cancellation races with dequeue, an in-flight write is never canceled or rolled back; the canceled waiter receives no ACK while other live waiters may receive their own ACK. Explicit cancellation alone does not poison the store. The caller treats any request sent without an ACK as ambiguous under the event-phase table below.
- Queue-full, malformed, rate-limited, closing, and poisoned requests fail closed without append. When queue/waiter capacity is exhausted, no ACK is guaranteed because ACK state is itself bounded; callers treat that as an ambiguous no-ACK outcome under the phase table, while rate and store accounting still occurs before the capacity check. Do not log payloads, audio, secrets, or high-cardinality identifiers as metric labels.

## 3. Deadline, phase, and failure semantics

No accepted ACK is sent before successful `Sync`, and no ACK is sent after the shared store has become poisoned. A single state mutex linearizes admission, dequeue, poison, close, durable-result publication, and ACK send. The handler waits for POLLOUT outside the mutex; immediately before a nonblocking SOCK_SEQPACKET Sendmsg it acquires the mutex and rechecks store state, waiter state, context, and deadline. Sendmsg is attempted while holding the mutex so a concurrent poison either wins first (no ACK) or follows a completed atomic packet send. EINTR/EAGAIN releases the mutex and retries only after another readiness wait and full recheck. ACK-send failure after successful Sync does not poison the shared store: persistence is known, only that waiter channel is ambiguous; return without ACK and retire that channel through the trusted launcher. A fresh-channel replay is permitted only for the same canonical event bytes when both docs/45 phase rules and the host logger dedup contract allow it (`run_root_dispatch_intent` and the stored `bootstrap.finish` outbox event), and only by the same live original Reaper process identity under its still-active Logger registration after the previous socket handler reached EOF and drained. Logger restart/re-registration or Reaper exit invalidates this authority; recovery-only/replacement Reapers cannot replay a committed event. Never replay `run_root_dispatch_committed` or a non-deduplicated transition; apply its phase-specific fence/indeterminate outcome instead. If another waiter shares the durable job, its own ACK remains eligible. A write/short-write/Sync error poisons the store. Deadline handling depends on the state at the linearization point: before admission, return without poisoning shared state; while queued, remove the waiter and cancel the job if it has no waiters and is not dequeued; while append/Sync is in flight, return without ACK and poison the store because file effects are ambiguous; after successful Sync, return without ACK but keep the store healthy because the event is durable. Replay only the exact canonical bytes for an event explicitly covered by docs/45 and the host logger dedup index; non-deduplicated transitions are not replayed. A writer may finish an already in-flight write after its waiter times out, but its late result is evidence only and cannot produce an ACK. Once poisoned by ambiguous in-flight file I/O, the writer starts no queued jobs and queued jobs are failed without disk effects; all runs reject new work until restart. A receive timeout before any packet, queued-job cancellation, and post-Sync ACK-send failure are local to that run/waiter and do not poison unrelated runs.

The caller applies docs/45's event-phase rules to every sent request that receives no ACK (deadline, explicit cancellation, or ACK-send failure); no failure implies one generic ledger transition. A correlated `rejected` ACK confirms that this frame was not appended and did not poison the logger. Before executing CAS, keep the reservation prepared and retry only the same authenticated idempotency record after rate capacity returns; if the store is full, wait for audited recovery. After executing CAS, retain the indeterminate fence and never retry the filesystem effect. A malformed frame has no ACK and uses the no-ACK phase rule. A rejected ACK is never a positive durability receipt:

| Event and transaction phase | Required caller outcome |
| --- | --- |
| `run_root_dispatch_intent` before executing CAS | Keep reservation `prepared`; no filesystem effect. A correlated `rejected` ACK may be retried under the same authenticated idempotency record after rate capacity returns (or audited offline recovery if the store is full); timeout/no ACK or store poison requires logger restart and strict index validation before retry. |
| `run_root_dispatch_committed` after executing CAS, before `mkdirat` | Mark/retain indeterminate, fence epoch and lease, and do not call `mkdirat`. |
| Critical post-side-effect/pre-terminal event | Retain indeterminate/fenced state and withhold capability. |
| `bootstrap.finish` after atomic terminal commit | Return `verified_io_failed`, preserve terminal states and held lease, withhold capability, and replay only exact stored bytes through a fresh channel of the same live original Reaper/active Logger registration. If Logger restart or Reaper exit invalidates identity, keep recovery_required; replacement recovery cannot deliver without a separately reviewed protocol. |

A crash during a partial line may leave a torn JSONL tail. Startup remains fail-closed: if strict index rebuild rejects that tail, quarantine the log for reviewed/manual recovery. Do not claim automatic replay in that case. Exact replay is allowed only after startup validates the complete canonical log.

## 4. Lifecycle and observability

`Close()` stops admission and uses one two-second end-to-end caller deadline. Every accepted append already calls `Sync` before completing, so shutdown performs no extra `Sync`. When handlers and writer drain, exactly one cleanup owner performs unlock and close in a goroutine; the caller waits only until its deadline. If the writer/handler does not drain, return `errHostLoggerRestartRequired`, retain the FD and `flock`, and do not start cleanup. If unlock or close hangs, the caller still returns by deadline; the cleanup owner never retries either OS operation. Unlock failure leaves the descriptor open; close failure is terminally unknown. Any timeout/error returns restart-required and the trusted parent must terminate/restart the logger process; its watchdog must bound process exit. Repeated `Close()` waits on the same completion and never starts another cleanup owner, reopens admission, or repeats an ambiguous syscall.

The append-only JSONL file also has hard lifetime bounds of 256 MiB and 1,000,000 complete records. Startup rejects a file beyond either bound; each unique append reserves both limits under the state mutex before entering the writer, and cancellation/queue failure releases reservations that never reached disk. Once either limit is reached, reject further appends without truncation or automatic rotation, keep prior evidence intact, emit `logger_store_full`, and require audited offline recovery/rotation that preserves all deduplication evidence before service resumes. A terminal operation whose finish outbox event cannot be appended remains committed but withholds its capability until that exact outbox event is durably delivered after recovery.

Expose payload-free structured counters/callbacks for `logger_queue_admitted`, `logger_queue_rejected_full`, `logger_ack_deadline_exceeded`, `logger_append_failed`, `logger_sync_failed`, `logger_store_poisoned`, `logger_store_full`, `logger_restart_replay_loaded`, and `logger_shutdown_restart_required`. IDs may appear in bounded diagnostic logs, not metric labels. Assert one transition record per state change.

## 5. Acceptance cases

1. FIFO per-run ordering and round-robin progress across runs; accepted ACK always follows successful `Sync`.
2. Exact 4 MiB per-run and 64 MiB global boundaries using full encoded frames including the retained job frame and all waiter frames while in flight; reject next frame without append, state growth, or ACK. A saturated run must not consume another run's per-run budget; other runs progress while global capacity remains.
3. Pending identical retries share one append and durable result but receive independently correlated ACKs with their own nonces; conflicting payloads reject. Enforce 4,096 jobs and 16 waiters before allocation.
4. Slow sync below deadline succeeds. Delayed sync beyond deadline returns without ACK by two seconds, poisons all contexts, and later completion never emits an ACK. A silent receive timeout before a packet, queued cancellation, and post-Sync ACK-send failure leave unrelated run contexts usable. In-flight cancellation does not cancel append and emits no ACK to that waiter; an in-flight append/Sync deadline poisons the store. ACK-send error after durable sync leaves the store healthy and is recovered only through exact dedup replay where the event-phase table permits it.
5. Stuck sync: bounded handler return, no additional dequeue/admission, bounded queue, and restart-required `Close` with FD/lock retained. After releasing the test barrier, restart and strict index rebuild; exact replay must not append a duplicate. Retained-charge oracle: shrink test capacity, dequeue one job and block `Sync`, cancel its only waiter, then assert its complete-frame charge remains, an over-limit next frame is rejected with no ACK, and the append continues. Release `Sync`; assert the canceled waiter still gets no ACK and the charge is released only after writer completion.
6. Failure matrix: short write, write error, sync error, silent receive timeout, queued cancellation, in-flight cancellation, ACK-send failure, close with queued/in-flight work, blocked unlock, blocked close, repeated close, torn tail. For blocked unlock and blocked close separately, use a barrier plus fake clock: `Close` returns restart-required at the single two-second deadline; repeated `Close` observes the same cleanup and never invokes the OS operation twice; admission stays closed. For blocked close, assert the FD state is reported unknown until the barrier resolves. Assert no fabricated ACK, no concurrent writer, correct phase outcome, and torn-tail quarantine.
7. Deterministic hooks control clock, writer, sync, ACK-send, unlock, and close barriers. Capacity tests inject lower test-only limits so 4 MiB/64 MiB boundary behavior is exercised without weakening production limits; hold 16 production contexts with active packet handlers/waiters, reject the 17th before allocation, and assert waiter/job/byte counts remain bounded. Send repeated valid durable replays, pending duplicates, and conflicting dedup frames past each bucket's burst/rate budget and assert the same per-run/global limits apply before any ACK; over-budget valid frames receive a correlated `rejected` ACK if bounded ACK capacity permits, otherwise fail closed without ACK; both available rate buckets are independently debited even if the other bucket is exhausted. Malformed authenticated frames consume a token in each available bucket but receive no ACK, while no-packet timeouts do not consume tokens. Saturate waiter/byte capacity with an over-budget valid frame and assert bounded no-ACK rejection with no append or state growth. Exercise both persistent-store limits exactly at and one record/frame beyond the boundary; queued reservations cannot exceed either cap. Cancel a queued, not-yet-written unique job at the reduced test cap, assert its byte/record reservation is released, and admit a replacement without exceeding the file bound. Restart must reject an oversized/over-recorded log without truncation. Also fill the persistent store before a committed `bootstrap.finish`: prove terminal ledger and exact finish outbox remain committed/ready, withhold capability, and assert no replacement Reaper or Logger restart can replay it. If capacity is restored without invalidating the original Reaper registration, replay the exact bytes once and return cached success without repeating creation; otherwise keep recovery_required and require a separately reviewed offline-delivery protocol. Recovery may not discard any dedup key. No wall-clock sleeps determine pass or fail. Failures report case ID, stage, elapsed time, queue byte/job/waiter counts, and state transition without payload.

Run tagged Linux tests with and without `-race`, default `go test ./...`, tagged `go vet`, strict manifest validation, and native ext4/XFS. Private mount namespace and separate process credentials are additional host acceptance cases. The store-full `bootstrap.finish` outbox recovery case requires the integrated RunRoot caller and remains blocked until that API exists.
