## 1. 补齐前审计基线与验收口径

本节保留补齐前盘点；当前31项实施清单见上文。“22工具”不是有效分母。补齐前docs/02 §3.2 去重重复 `classroom.say`、排除已移除 `advance_phase` 后，有 **29 个能力条目**，其中 `wordbook.crud_*` 是能力族而非真实工具名。当时生产工厂共 **13 个唯一注册名**，且“已注册”“具备受信执行入口”“生产旅程实际调用”不同，不能通过注册空 handler 或凑够22来关闭缺口。

现有13项为：`classroom.say`；`config.set/config.get/config.set_student`；`memory.append/memory.recall`；`scheduler.plan_next_lesson/postpone_lesson/boost_word`；`feedback.reply/feedback.escalate`；`report.compose_reply/report.publish`。来源为 api/app.go、agenttools.go、teachertools.go、lessonagenttools.go、feedbacktools.go。

C 反馈及 B 结课已有受信任务、共享8调用预算和事务执行器。其余课堂动作仍由 Hub 从状态机直接生成帧；Teacher.Decide 目前主要承担话术选择。Agent HTTP `tools/call` 不建立受信 task，因此当前安全拒绝这些业务工具，并非可用的外部自主 Agent 控制面。`SystemAgent.Decide(cron_overdue)` 存在，但 Hub 定时器只推进课堂/会话，未调度该决策；Scheduler.HandleOverdue 内含直接改期策略，不能直接接上定时器便声称符合 D-15。

## 3. 执行边界与实现分批

### T1：可核验目录与只读/记忆能力

新增机器可读能力目录，分别记 canonical_name、legacy_alias、role、risk、受信trigger、执行模式（internal_task/admin_operation）、注册工厂、实际调用点、对应测试。目录从明确名单生成并与 `ToolsFor` 双向比较，缺定义、多定义、重复名称均失败；管理端点能力独立一列，不冒充Registry条目。`feedback.apply_adjustment` 文档映射到 canonical `config.set_student`，若保留兼容别名，必须复用同一handler且共享预算/审计，不能独立绕边界。

先接 scheduler/progress/scripts 只读工具及 memory.list/revise/delete。工具JSON不接受任意student_id/owner_role/source_lesson_id；兼容字段出现时必须与受信任务完全一致。memoryId必须再次校验学生、book范围及owner_role，防同角色跨学生修改。所有写操作在任务私有事务服务执行；记忆写成功而审计失败必须回滚。用户提供的任务ID不能直接当授权。

公开 Agent HTTP 调用继续拒绝缺少平台签发上下文的写请求；本次不新增任意自主Agent管理入口。目录需清楚呈现这些工具为平台内部任务执行，不把HTTP可见名称宣传为外部可调用。若后续开放远程Agent，应另设计平台签发任务凭证、role/agent账号绑定、到期与重放限制，不能凭客户端 studentId 临时构造受信task。

### T2：课堂效果全部进入工具与审计

保持状态机负责确定性相位不变量，Teacher Agent 根据状态机事件和冻结事实产出教学效果计划；Hub只分发执行结果。课堂展示/播放工具默认是**无状态帧构造器**：接收任务内已冻结的action事实，不在handler重新进入Room锁，也不私自推进相位、播放或广播。工具结果经Hub单一序号/事件流出口发送。

每个学生事件/超时事件共享同一8次预算及父trace，不能每个工具重建预算；纯快照GET不触发教学动作。判分工具与18在途请求协议一致，锁外网络→锁内代次核验→提交，不能为了Registry封装重新把网络放回锁内。工具参数中的 word/item/phase 必须与已冻结当前动作匹配；非法工具结果不发送。工具失败保持可定位状态，不能静默丢弃成功回执或用快照双重朗读兜底。

### T3：明确现有cron决策的生产触发

新增可取消后台巡检，扫描只读候选，不在扫描函数硬编码重排。固定时区日期锚和排序；每个逾期课建立稳定任务键（lesson_id+原OpenAt/版本+trigger），交 `SystemAgent.Decide` 后由事务工具执行。多个进程/重启重复扫描不得重复改期、通知或记忆；处置前重新检查课程状态、学生有效性、选库与版本。

拆分现有 `Scheduler.HandleOverdue` 的“发现候选”和“执行给定变更”，保留原课过期、卡片阶段不变、下次预约等数据不变量，是否改期/询问由Agent决策。一次处置的课程、预约卡、通知、完成凭证和审计原子提交。连续逾期计数来自持久历史而非内存，首次/连续第二次路径分别验证。cron_daily 未有明确现成决策时不得注册空任务声称已完成，应在04列出实际采用的维护决策后实施。

月度请假上限、Boost池FIFO、再次澄清后升级等04旧表承诺与当前已验收C合同需逐条标明“本轮策略/历史待决”，不可通过补工具名暗示已实现。仅在明确策略与可测数据定义齐备后扩动作；不得未经设计就把规则散落在Hub或handler。

## 4. 日志、Go与浏览器验收矩阵

工具调用保持父trace、task/attempt、trigger、actor role、student/book/lesson、tool、结果码、耗时与事务结果；原文、记忆内容、模板变量与token不入日志。增加目录不一致、计划拒绝、cron候选/跳过/提交/回滚事件。Registry调用成功与事务commit分开，目录查询不能制造执行成功审计。

| 分项 | Go/SQLite/协议 | Playwright真实用户路径 |
|---|---|---|
| 工具目录 | 明确清单与角色目录相等，副本不可改权限，alias共用预算 | 管理操作与学生操作不越权，真实审计列表显示对应执行摘要 |
| 只读工具 | 学生/课/词库绑定，取消、坏参数、存储失败，无副作用 | 学生课表/Stats与工具摘要同事实，另一学生保持隔离 |
| 记忆CRUD | 同role不同student、同student不同owner均拒绝；写/审计失败回滚、重启保留 | 完成一课/反馈后后续Agent消费正确本人记忆；管理审计不显示越权内容 |
| 课堂工具 | 每种已声明动作真实走Registry一次；错turn/item拒绝；共享预算 | 默认/自定义朗读、错答重教、终测与课报旅程不变，断线恢复不双播（18） |
| cron | FakeClock首次/连续逾期、两App竞争、重启重复、禁用学生、事务逐点故障 | 真实逾期→刷新课表/通知一致、重新登录不重复，另学生正常上课 |
| 管理能力 | 管理REST身份/参数/事务回归，明确未授Agent写权限 | 管理员创建/解析预览/导入/发布/归档，学生只读已发布内容 |

所有回归由测试子代理执行。新BUG必须Go与E2E双轨；不为工具本身创建无产品用途的按钮或测试后门。覆盖率沿03门槛，日志及目录一致性作为总验收一部分。T1、T2、T3各批先review后实现；可用能力清单全部有明确实现或经批准的非Agent管理映射后，才能修正“22工具未完成”台账，不隐瞒原设计裁剪。
