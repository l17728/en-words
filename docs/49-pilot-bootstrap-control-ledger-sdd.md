# Pilot BOOTSTRAP Control Ledger SDD

## Status and scope

This design proposal connects the authenticated `BOOTSTRAP/v1` handler to durable control-generation and Gateway identity binding. It does not implement launcher orchestration, `CreateRunRoot`, `RECOVERY_BOOTSTRAP`, containment evidence, logger outbox/CAS, or product classroom wiring. The feature remains pilot-only (`pilot_e2e`) and unavailable to production routes.

## Durable record

Advance the schema to v2 and add `pilot_bootstrap_handoffs` with strict DDL: every column is `NOT NULL`; `generation BLOB PRIMARY KEY CHECK(typeof(generation)='blob' AND length(generation)=8 AND generation<>zeroblob(8))`; `launch_nonce TEXT UNIQUE CHECK(typeof(launch_nonce)='text' AND length(launch_nonce)=32 AND length(CAST(launch_nonce AS BLOB))=32 AND launch_nonce NOT GLOB '*[^0-9a-f]*')`; `run_epoch TEXT UNIQUE CHECK(typeof(run_epoch)='text' AND length(run_epoch)=32 AND length(CAST(run_epoch AS BLOB))=32 AND run_epoch NOT GLOB '*[^0-9a-f]*')`; `pid INTEGER CHECK(typeof(pid)='integer' AND pid BETWEEN 1 AND 2147483647)`; `uid INTEGER CHECK(typeof(uid)='integer' AND uid BETWEEN 1 AND 4294967295)` (UID 0 is rejected because BOOTSTRAP requires the provisioned non-root service UID); and each other unsigned identity component is an eight-byte BLOB with type/length checks and `<>zeroblob(8)`. Enforce row immutability with `BEFORE UPDATE` and `BEFORE DELETE` abort triggers. Insert with plain `INSERT` only; never use `INSERT OR REPLACE` or UPSERT. Startup validates exact columns, normalized DDL, unique indexes, trigger definitions, exact object inventory, and every persisted row against wire-level ranges and nonce/epoch formats. This slice accepts no v1 schema: its known object inventory is only a rejection fixture and must remain unchanged after refusal. A fresh v2 ledger contains only documented base ledger objects, the handoff table/indexes and two immutability triggers. Ignore only literal names beginning `sqlite_`; reject every other unrecognized user object.

Encode all uint64 values as fixed-width eight-byte big-endian BLOBs. SQLite bytewise ordering of equal-length BLOBs preserves unsigned numeric order; query the high-water mark using `ORDER BY generation DESC LIMIT 1`, never decimal text or signed INTEGER. This preserves the wire range through `MaxUint64`.

Before schema initialization, switch to WAL with a 50 ms SQLite busy wait per attempt and retry only SQLite primary BUSY/LOCKED result codes within a shared five-second caller-context deadline. This is a setup-only exception for `PRAGMA journal_mode=WAL`; check cancellation between attempts and after success, then restore and verify the normal 5,000 ms writer busy timeout. Normal ledger operations never retry BUSY/LOCKED outcomes. Initialize inside a writer-reserving `BEGIN IMMEDIATE` transaction. Inspect `sqlite_master`, meta and `user_version` only after holding the writer reservation; only a completely empty user schema may be initialized. Create v2 tables, indexes, triggers and the v2 meta row atomically. A concurrent opener waits and validates the complete v2 schema. Reject any prior-version, partial, unknown, or non-empty schema before DDL, leaving schema objects, meta contents and `user_version` unchanged. No implicit migration is allowed.

## Transaction and outcomes

`RunRootLedger.ConsumeBootstrap(ctx, request)` validates the canonical request, converts uint64 fields to fixed-width BLOBs, reserves the SQLite writer before reading the high-water mark, checks generation and permanent nonce/run-epoch uniqueness, inserts the full tuple, then commits before transport sends `ok`. A process-local mutex is insufficient across ledger instances. Other writers wait only through the configured five-second busy timeout; BUSY/LOCKED is infrastructure uncertainty, never business rejection or automatic retry. Equal/lower generation, nonce reuse, or run-epoch reuse returns `(false, nil)` without writes. Transport maps false to correlated `rejected`, closes the control channel, and keeps the run fenced. Boundary tests assert bytes and ordering at `MaxInt64`, `MaxInt64+1`, and `MaxUint64`; after MaxUint64, no generation can wrap or be accepted. A dual-pool barrier commits N+1 before N acquires the writer lock, then proves N is rejected. A separate lock-owner test verifies BUSY/LOCKED returns an infrastructure error without inserting.

Fault injection distinguishes: (a) failure immediately before COMMIT followed by rollback, where reopen sees zero rows and the instance is fenced; (b) successful COMMIT followed by ACK loss, where reopen sees one row and same-generation replay is rejected; and (c) a driver that commits underneath then returns an error, where reopen must see exactly one complete row, while production still treats the outcome as uncertain. In (a) and (c), send no `ok`; send correlated `restart_required` if the channel/deadline permits, then close the channel and fence the ledger instance. A separate crash at an unknown commit point may leave zero or one complete row, never a partial row. Never map COMMIT uncertainty to `(false, nil)`. The same generation is never retried; launcher reaps the Reaper and allocates a higher generation.

This row proves only that the authenticated Reaper consumed the handoff. It does not prove RunRoot creation, logger registration or operation commit. This slice rejects `RECOVERY_BOOTSTRAP`; future normal and recovery sessions must share one persistent generation high-water and nonce replay-prevention domain while retaining separate authorization and target-binding rules. No endpoint may be exposed until a separately reviewed orchestration transaction atomically binds handoff, allocation and operation state.

## Required tests and diagnostics

Cover first acceptance, increasing generations, stale/equal replay, nonce/run-epoch uniqueness, exact tuple persistence, uint64 and identity boundaries, reopen persistence, v1/partial/tampered schema rejection without mutation, concurrent first-open initialization, and independent-pool stale ordering. Direct SQL negative cases reject NULL, BLOB, uppercase, invalid-character, wrong-length, and 32-hex-plus-embedded-NUL-suffix nonce/epoch values; startup refuses any tampered persisted row. Cancel context while waiting for the writer lock, before insertion: fence the instance and assert no row after reopen. Test the three fault-injection cases and unknown-commit crash separately; assert ACK mapping, instance fencing, channel closure and no replay. Errors must not log nonce, run epoch, PID, UID, or namespace/cgroup IDs. Events include trace ID, component, stage, elapsed time, generation, result and safe error class; cleanup/dispatch outcome only when available and without identity values. Recovery finalization remains unimplemented until `RunContainmentEvidence` and atomic lease release receive a separate schema/transaction review.

## Review and acceptance gate

Architecture, backend, security and test reviewers must approve this SDD before implementation. Accept this slice only after focused Windows-host tests, Linux amd64/arm64 compile/vet, and native Linux normal/race tests on disposable ext4. This does not clear RunRoot/logger integration, multi-user E2E or isolated-classroom acceptance.
