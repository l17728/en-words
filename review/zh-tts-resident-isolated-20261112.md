# 中文 TTS 常驻版隔离验收记录（2026-11-12）

## 实施与正确性

新原生 worker、Node 适配器和构建/测试脚本仅在仓库新增；隔离运行于 `127.0.0.1:18002`，生产 8002/8090 与 `tts.maxConcurrent=2` 均未修改。首次直接启动时，原生进程缺 WinLibs 运行时 PATH 而退出；隔离启动脚本现显式加入编译器运行时目录，服务随后达到 4/4 READY。隔离原生协议 P01/P03/P04 为 5/5，真实 HTTP 中文合成为 2/2，fake HTTP 故障/取消/重启用例为 6/6。真实 Sherpa 模型输出 16000 Hz；早期将另一套 22050 Hz 夹具当成该模型采样率导致 WAV 被错误拒绝，已在代码、测试和设计中修正。

公开短词/短句按 N=1/2/4 各 10 轮、N=8 共 100 轮，全部经隔离 HTTP 端口，不传真人音频。首字节与总时延在本次测量中相同到毫秒级。

## 资源、混合健康和回滚

容量期间每秒记录 251 个资源样本：4 个 worker 持续存活，合计 RSS 峰值 910.2 MiB，系统可用内存最低 5104.6 MiB，服务进程 CPU p95 约 80.0%、峰值 82.4%。容量结束后只读查询 8090 `/api/status`：ASR、中文 TTS、英文 TTS、Picer 模型均为 ready。由于 N4/N8 速度门失败且需给全量浏览器回归释放 CPU，本次未追加 ASR/英文 TTS 混合**负载**；混合健康检查不能替代混合容量验收。原始结果在 `.test-artifacts/zh-tts-resident/capacity.jsonl` 与 `resource.csv`。

已停止隔离 Node：18002 无监听，原生 worker 数 0。生产仍为已通过双学生旅程的 `tts.maxConcurrent=2` 旧版。后续若要推进常驻版，先改进 N4/N8 实际首音时延，再在隔离端口重跑全矩阵、混合负载和浏览器证据；所有门通过后才申请受控生产切换。
