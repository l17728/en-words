# Security Review: Pilot Start Sidecar Code and §108

Read-only review of `server/internal/store/pilot_start_sidecar.go` against the current `docs/41-试点课堂Start持久迁移内核SDD.md` §108 and the surrounding §3 file-integrity contract. No code or design was changed and no tests were run.

## Decision

**BLOCK before security sign-off/integration.** The create/reopen split and JSONL parsing limits are directionally correct, but an append rejected because it would exceed 1 MiB only sets an in-memory `degraded` flag. The existing sidecar remains valid and below the cap; if the supervisor exits before durably quarantining the case, recovery can reopen it as healthy and accept a new command. This contradicts §108's whole-case cleanup/no-new-command rule. Also, this helper reopens by pathname instead of consuming the verified handle required by §3, and the supervisor integrations that must supply ACL and Windows directory durability are not present in this source.

## Findings

- **PSK-SC-108-01 — P1, blocking: cap rejection is not restart-persistent.** `Append` sets only `s.degraded` when `Stat` fails or the next line would exceed the cap ([pilot_start_sidecar.go:176-179](/D:/en-words/server/internal/store/pilot_start_sidecar.go:176)). No bytes or durable case-state marker are written. `replay` only sets degraded when the existing file is already at least 1 MiB ([pilot_start_sidecar.go:262-267](/D:/en-words/server/internal/store/pilot_start_sidecar.go:262)); a rejected append from a smaller valid file therefore reopens healthy after process restart. §108 requires the supervisor to reject further commands and use whole-case cleanup ([SDD §108](/D:/en-words/docs/41-试点课堂Start持久迁移内核SDD.md:114)). Persist a case quarantine/degraded state in the catalog before releasing the case lifecycle lock, and fail closed if that write/Sync fails. Add a cap-boundary restart case that injects a would-exceed append, crashes before and after quarantine persistence, and proves there is no fresh command or chain recreation after restart.
- **PSK-SC-108-02 — P1 integration blocker: verified-open identity is not carried into this helper.** `loadPilotStartSidecar` performs `Lstat`, then separately opens `resolved` by path, then checks only the opened handle's regular-file type and mode ([pilot_start_sidecar.go:81-103](/D:/en-words/server/internal/store/pilot_start_sidecar.go:81)). There is no no-follow open flag, file-ID comparison with the pre-open object, hard-link-count check, or verified directory/file handle parameter. A path/symlink swap between `Lstat` and `OpenFile` is therefore not rejected by this helper itself. Protected parent ACLs and the stated exclusion of same-account attackers limit exploitability in the declared harness model, but this is not the §3 contract that sidecar/key use the verified handle and each target be opened with identity/link checks. Integrate through an OpenVerified handle (or an equivalent atomic supervisor-owned open) and preserve the case lock through it; otherwise explicitly narrow the guarantee and prove the protected parent is enforced before every call. Do not treat the current Lstat check as atomic authorization.
- **PSK-SC-108-03 — P1 integration gate: Windows file ACL is unchecked here.** `pilotSidecarModePrivate` returns true on Windows regardless of the file's DACL ([pilot_start_sidecar.go:123-127](/D:/en-words/server/internal/store/pilot_start_sidecar.go:123)). The comment correctly delegates ACL verification to the supervisor; §108 also makes Windows ACL verification a mandatory integration gate ([SDD §108](/D:/en-words/docs/41-试点课堂Start持久迁移内核SDD.md:114)). No supervisor/OpenVerified implementation is present in the reviewed file set, so do not claim Windows protection until every create/reopen call is preceded by owner-only DACL, inheritance, owner, link/reparse and file-ID verification on the same opened handle.
- **PSK-SC-108-04 — P1 integration gate: Windows directory-entry durability is a no-op in this helper.** `syncPilotSidecarParent` returns nil on Windows without flushing a verified parent-directory handle ([pilot_start_sidecar.go:130-143](/D:/en-words/server/internal/store/pilot_start_sidecar.go:130)). The source comment and §108 properly label this as an outstanding supervisor integration gate. It remains a blocker for a durable-create claim until the supervisor provides and tests the platform-specific parent-directory durability operation.
- **Create/recovery separation — conditionally sound, caller-gated.** Recovery uses `O_RDWR|O_APPEND` without `O_CREATE` and rejects zero-length files ([pilot_start_sidecar.go:67-69, 92-113](/D:/en-words/server/internal/store/pilot_start_sidecar.go:67)); first creation uses `O_CREATE|O_EXCL`, so it cannot overwrite an existing entry ([pilot_start_sidecar.go:71-75, 92-95](/D:/en-words/server/internal/store/pilot_start_sidecar.go:71)). This matches §108 for correct callers. But `createPilotStartSidecar(path,key)` has no unforgeable “new catalog case” capability and accepts a path/key pair; if misused for an existing case whose sidecar was deleted, it creates an empty chain and `replay()` accepts it. Keep this function reachable only from a supervisor operation that has durably established a brand-new case; preferably encode that authorization in an opaque creation handle/token. Recovery must never fall back from `open` failure to `create`.
- **JSONL cap and parser — core checks match the SDD.** The 1 MiB and 8 KiB limits match the documented constants ([pilot_start_sidecar.go:21, 173, 200-211](/D:/en-words/server/internal/store/pilot_start_sidecar.go:21)); append checks projected size before writing, marks current object degraded, and fails without a write if over limit ([pilot_start_sidecar.go:176-189](/D:/en-words/server/internal/store/pilot_start_sidecar.go:176)). Replay bounds total bytes and line length, rejects unterminated lines, unknown fields, noncanonical JSON, invalid HMAC/sequence/transition, and does not truncate or rotate ([pilot_start_sidecar.go:196-268](/D:/en-words/server/internal/store/pilot_start_sidecar.go:196)). Exact-cap replay is returned as degraded, which is fail-closed for append. The restart persistence gap in SC-108-01 remains.
- **POSIX permissions and parent Sync — local behavior is conservative but pathname-scoped.** Creation requests mode 0600 and checks that group/other permission bits are absent ([pilot_start_sidecar.go:96-103, 126-127](/D:/en-words/server/internal/store/pilot_start_sidecar.go:96)); POSIX creation opens and syncs the parent directory ([pilot_start_sidecar.go:130-143](/D:/en-words/server/internal/store/pilot_start_sidecar.go:130)). This does not itself verify owner, ACLs, directory identity, or protect the parent path while syncing; those remain supervisor/OpenVerified responsibilities under §3.

## Required disposition

Before integration approval, make cap-triggered degradation survive restart via durable catalog quarantine; bind sidecar open/create to supervisor-verified case/file identity and new-case authorization; and close the Windows ACL and parent-directory durability gates. The source is `pilot_e2e`-tagged and no production route is implied, but the helper alone does not establish those guarantees.

## Limits

No tests, filesystem race injection, ACL inspection, Windows durability check, process restart, or runtime file operation was performed. This is a source/design review, not execution verification.
