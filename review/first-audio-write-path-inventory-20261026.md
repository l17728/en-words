# First-Audio Generation Write-Path Inventory (Review Follow-up)

Scope: current `server/internal/api`, `server/internal/scheduler`, and `server/internal/store` code reachable during classroom entry, first audio, classroom feedback, completion, or overdue processing. This is an implementation prerequisite for `docs/70` §7f, not evidence that generation permits exist. Direct repository calls and in-memory publication are included because they can still mutate learning state or expose stale frames.

These registrations are composed by `registerStudentTools` and API setup; `config.set` is separately registered by `App.registerTools`. The route/cron trigger is part of the caller, not inferred from tool risk. `callAgentTool` success audits are in its transaction. Its failure audit and settlement rollback audit are post-rollback writes and each needs a fresh current-generation permit before DB insertion. Any future registration must fail inventory reconciliation until mapped.

Schema cross-check (`rg -n 'tools\.Tool\{' server --glob '!**/*test.go'`) found registration constructors only in the eight API files listed above. The current `InputSchema` contracts group as follows: `classroom.say` requires string `text` and `category`; teacher effects require integer `index`; scheduler/progress reads accept an empty object with extra keys rejected; scripts require string `category`; memory append/recall requires `scope` and accepts student/book/source-lesson IDs, kind/content/importance/query/limit; memory list/revise/delete requires `scope` and accepts id/content/importance/kind with extra keys rejected; config set/set_student require `key`, `value`, `reason`; config get requires `key`; lesson plan/report tools accept an object with empty `properties`; feedback actions require `reason` and reject extra keys; overdue actions require `reason` and reject extra keys. Runtime handlers additionally call `strictToolArgs`; include that decoder behavior in the implementation permit tests.

Scheduler mutation methods are also indexed: `CreateCard`, `SaveCard`, `Boost` and `BoostWordWithCapacity` reach `memory_cards`; `CreateLesson`, `SaveLesson`, `PostponeLesson`, `ReplanExpired` reach `lessons`; `DeleteStudentBook` affects lesson/book relations; `SavePlacementDraft` reaches `placement_drafts`; placement atomic methods update cards/drafts. Caller evidence includes settlement (`SettleLesson`), feedback tools (`PostponeLesson`, `BoostWordWithCapacity`), overdue (`ReplanExpired`), lesson planning (`PlanNextWithPolicy`, `ReserveCards`, `SaveLesson`), and admin/placement routes. This is a first-audio-only matrix: it must not settle a lesson, submit feedback, replan overdue work, or mutate any `memory_cards` row. The allowlist is only the one synthetic `lessons` row and the explicitly named runtime/audit keys below; every `memory_cards` row remains denied.

## Table coverage and fail-closed baseline

Candidate allowlisted sample tables/rows: only `runtime_records` key `snapshot/<sampleLessonID>`, the exact synthetic `lessons` row, and append-only `audit_logs` with exact synthetic `trace_id=lesson-<sampleLessonID>` for first-audio effects. `runtime_records` keys `report/<id>`, `settled/<id>`, and `agent_result/<id>` are explicitly denylisted and must be absent at every journey boundary; all `classroom_events` are denylisted. No settlement, report publication, feedback submission, overdue replan, or `memory_cards` mutation is part of this first-audio-only matrix. Denylist includes every model in `startupModels()` not explicitly allowlisted (including `ws_tickets`), all nine manually created pilot tables, all three duplex tables, `users`, `word_books`, `word_entries`, `config_globals`, `config_overrides`, `config_revisions`, every `memory_cards` row, `agent_memories`, `durable_memories`, `overdue_tasks`, legacy `feedbacks`, `feedback_tasks`, `feedback_intents`, `feedback_todos`, `feedback_notices`, `notifications`, `placement_drafts`, and all non-sample `lessons`/`runtime_records`/`audit_logs`. Compare full canonical row/object snapshots before and after every first-entry journey as well as every reset.

Guard strategy: finish fixture/schema setup, close that pool, and create a fresh dedicated matrix pool with `mattn/go-sqlite3` `SQLiteDriver.ConnectHook` authorizer installed before the first SQL prepare on every physical connection. The authorizer is immutable for the process lifetime: deny DML on all denylist tables and all schema DDL/ATTACH/DETACH/unsafe PRAGMA. Install fixed BEFORE triggers for the mixed-allowlist `lessons`, `runtime_records`, and `audit_logs` tables; triggers call a test-only UDF registered by the same connection hook. The UDF validates operation, OLD/NEW row identity and current phase, allows only the synthetic lesson reset transition whose canonical OLD/NEW values match controller-held expected rows, `snapshot/<sampleLessonID>`, and append-only exact sample `trace_id` audit inserts. For audit insertion, the trigger also rejects a `NEW.id` already present regardless of SQL conflict algorithm; `recursive_triggers=ON` is defense in depth, not the only REPLACE defense. The UDF increments a process-memory attempt counter and rejects every disallowed operation. Phase changes may tighten but never loosen the policy. This execution-time row-aware guard covers SQL prepared before the journey; a required negative test prepares a forbidden row write before sample start, executes it during the sample, and asserts rejection plus a counter increment. Also test insert-then-rollback, `INSERT OR REPLACE` colliding with an existing non-sample audit ID followed by rollback (reject and retain the old row), audit update/delete, non-sample keys/trace, raw SQL, schema/attachment attempts, and every pool connection. Counters survive transaction rollback. Any non-allowlisted row/object delta, nonzero forbidden-attempt count, or inability to prove hook/UDF coverage fails the run; unknown tables/triggers/views/indexes fail closed. Do not infer the snapshot universe from `startupModels()` alone.

## Acceptance before implementation

Current registry constructor/name/schema cross-check is complete for the `server/**` production search; the mapping above records all constructor-generated names and schema variants. The production write-call search also covers direct GORM/SQL mutation sites in API/store/scheduler. Reviewers must validate permit boundaries, SQLite authorizer prepare-time policy, row-aware trigger/UDF execution checks, and per-connection coverage before implementation acceptance. The matrix stays `NOT RUN` until design reviews pass and implementation tests prove journey-boundary snapshots, preprepared-statement denial, rollback-surviving row violation counts, and the centralized permit all fail closed.
