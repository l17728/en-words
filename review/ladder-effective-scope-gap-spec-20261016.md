# 有效复习梯度变更：独立缺口与修复规格草案

状态：只读代码审查确认，未实施、未运行新测试。当前 startup 候选及浏览器 127 回归源码保持冻结。本文件不宣称以下回归已通过。

## 已确认的缺口

- `server/internal/scheduler/scheduler.go` 的 `TruncateLadderSteps` 仅处理 `*MemRepo`，持久仓储直接返回成功；注释所称 GORM UPDATE 没有实际实现。
- `server/internal/api/app.go` 将 `OnLadderChanged` 接到上述方法，仅传梯度长度。
- `server/internal/config/config.go` 的 `set` 在持久保存前调用 `OnLadderChanged([]int)`；回调没有 global/student 或学生 ID 信息。因此内存仓储中设置一个学生的覆盖，也可能截断其他学生的卡。
- 配置保存失败时，已执行的内存卡副作用无法由当前回调恢复。`DeleteOverride`（config.go:455）直接持久删除、清缓存并 bump revision，没有梯度回调；覆盖不存在时直接幂等返回。删除学生覆盖的回落也必须纳入同一有效配置变更合同，不能只修 set。

这是一组配置与学习进度一致性缺口。给 SQLite 增加无条件全库 UPDATE 或只加 pilot scope 拒绝门，均不等于完成功能。

## 拟定行为合同（待主审与架构确认后实施）

1. 全局梯度变化只影响没有独立梯度覆盖的学生；有覆盖的学生保持其有效梯度及卡进度。
2. 设置学生梯度只影响该学生。删除覆盖时，以删除后实际生效的全局值计算截断。
3. 对受影响的卡仅将超过新最大下标的 `LadderStep` 降至 `len(ladder)-1`。扩大梯度不提升步骤；其余学习字段、状态和其他配置不变。长度合法性继续由配置 schema 校验。
4. 配置值、受影响卡步骤及已有配置 revision 机制在同一事务提交；存储、取消、COMMIT 失败均不得发布部分结果或更新应用缓存。使用现有每键 Global/Student revision 与触发器，不另造单一 revision 计数。
5. 删除覆盖必须保留现有 revision 墓碑/ABA 检测语义；删除不存在覆盖继续幂等返回，不制造卡变更。重复相同设置的 revision/审计行为需独立锁定既有合同，不凭本草案猜测。
6. 持久仓储事务内读取受影响学生的有效覆盖并取得写入序列，避免与并发设置/删除覆盖交错。内存实现使用同等原子准备与发布语义。
7. 未来 pilot scope 门必须在任何配置或卡副作用之前核验全部受影响范围；遇到禁止范围整次拒绝。不能先写全局配置再发现 pilot 卡。
8. 提交成功后才发固定摘要日志，包含 trace、配置 scope、目标学生（适用时）、受影响/改变卡数和结果；失败不输出 SQL、配置原文或用户正文。

### goalMode 的隐式梯度依赖

实际 `config.effective`（config.go:306）优先学生 ladder 覆盖，其次全局显式 ladder；两者都没有时，才根据学生的有效 goalMode 选择默认梯度。因此协调入口不能只覆盖 `ladder` 键：global/student 的 `goalMode` 设置、学生 goalMode 覆盖删除，也必须计算事务前后真正生效的梯度、revision 和受影响 scope。

当前源码的 DefaultLadder 为 `[1,1,2,2,4,7,14,30]`，SprintLadder 为 `[1,1,1,1,2,2,3,3]`，**两者长度均为 8**。仅切换两种默认模式不会造成新的步骤上界缩短，不可把间隔变化冒称截断 BUG；但有效复习间隔发生变化，必须遵循配置事务与 scope 保护合同。没有批准重排现有 due 时间，本规格不顺带改变该教学策略。

存在显式 global/student ladder 时，goalMode 不改变该学生的有效 ladder；无显式 ladder 时，global goalMode 仅影响没有学生 goalMode 覆盖的学生。删除学生 ladder 覆盖还须区分回落到全局显式 ladder 或按有效 goalMode 推导的默认梯度。

需要用明确的事务协调接口替代具有提前副作用的无 scope 回调；具体归属与接口、锁顺序先经设计评审，不在本草案指定大范围重构。不能在持有 config.mu 的回调中重新进入 Store，形成自锁。

## 必须新增的逻辑/SQLite 回归

- 真实 SQLite 卡步骤超新界：全局缩短后正确截断，覆盖旧实现的静态已确认缺口；先旧行为红，再新行为绿。
- 两学生：A 无覆盖、B 有覆盖，全局缩短仅 A 改变；学生 B 设置只改 B，A 卡与配置不变。
- 删除 B 覆盖后按当时全局梯度截断；删除时全局更长则不提升步骤。
- 梯度扩长、相同值、空/非法梯度；学习状态、掌握度及其他非步骤字段保护。
- goalMode 的 global/student set/delete 矩阵：无显式 ladder 时正确选择两套长度均为 8 的默认值；学生 goalMode 覆盖隔离；显式 global/student ladder 的优先级不被模式切换覆盖；默认模式互换不提升或额外截断步骤，不擅自重排 due 时间。模式事务失败时配置、revision、缓存和卡保持原值。
- 删除学生 ladder 的两种回落（全局显式值、无显式值时按有效 goalMode 默认值），以及设置同长度不同间隔的配置：保持既有 revision/审计合同，不把“步骤无变化”写成“配置零变更”。
- 配置写失败、卡写失败和真实延期约束 COMMIT 失败：配置、卡、revision、缓存全部保持原值；新连接及原连接读取一致，后续正常重试成功。
- 两独立连接池并发 global/student/delete：最终步骤不得超出最终有效梯度，且等于可成立的串行截断历史；先缩短再扩大不能恢复已经截断的进度，因此不要求等于最终最大下标。不能依赖某一赢家时序；错误不伪成功。
- 内存仓储加失败持久适配器：重现回调先改卡后保存失败的旧缺口，修复后零部分副作用。
- 未来 pilot/legacy 混合范围：全范围预检拒绝后配置、卡、revision 均零变化；既有 scope 墓碑不可被删除绕过。

## 必须新增的真实 UI 旅程

管理员经真实配置界面缩短全局梯度；学生 A 无覆盖、学生 B 有覆盖并分别具有可核对学习进度。刷新、重新登录及受控后端重启后，断言有效配置和持久卡步骤对应上述作用域，B 不受 A/global 操作误伤。随后设置、删除 B 的覆盖验证回落。

同旅程补充 goalMode 全局/学生切换与删除覆盖的实际有效间隔变化，分别验证显式 ladder 保护及无显式 ladder 的默认回落；不能因两个默认长度相同而只断言步骤、不核有效配置。

另用隔离 SQLite 故障触发器使真实配置提交失败，界面显示失败且重新读取配置/进度保持原值；解除故障后用户主动重试成功。数据库断言仅补充真实界面操作，不用直接 seed 更新冒充配置行为。若现界面缺少删除覆盖入口，应单列接口与 UI 能力边界，先补规格，不能伪造已有按钮。
