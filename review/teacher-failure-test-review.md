# 跟读失败诊断与人工授权修复：测试领域评审

## 结论

当前规格方向正确，但还不能作为实施验收基线。需要补齐任务生命周期、权限负向用例、重复提交竞态和完整 Playwright 旅程后再开发。

## 必须补充的单元与集成用例

1. 同一 `analysis_key` 并发写入只产生一条分析记录。
2. 同一评价重复提交只执行一次工具调用，变体唯一约束生效。
3. 管理员评价与教师 Agent 迟到返回交错时，旧结果不能覆盖新状态。
4. 已成功重试后，旧分析变为 `superseded`，不能再次实施。
5. 学生只能读取自己的课程分析；学生、教师 Agent、系统 Agent 不能调用管理员评价接口。
6. Agent 输出缺字段、非法 JSON、未知工具、跨词条参数时，任务失败且原词条不变。
7. 删除变体、修改原词、批量写入均被工具作用域拒绝。
8. Agent 超时、模型断开、SQLite 重启后任务可恢复，且不会重复应用变体。
9. `etc`、`e t c`、`et cetera`、`ASAP`、`a s a p`、`as soon as possible`、`sth` 等规则的正向和负向判分。
10. 日志不得在关闭诊断开关时写入 transcript；开启时必须带 trace、analysis_id 和脱敏摘要。

## 必须补充的 Playwright E2E

- 管理员登录 → 查看待处理报告 → 认可建议 → Agent 工具执行 → 页面显示成功 → 学生重新跟读通过。
- 管理员编辑建议后实施，刷新页面后状态仍为已实施。
- 管理员拒绝建议，学生重试仍按原规则判分。
- 学生访问管理员接口返回 401/403，且页面不显示管理按钮。
- 两个浏览器同时点击实施，只有一次变体生效，另一端显示已处理。
- 分析接口延迟或 500 时课堂继续，页面显示可重试诊断，不改变课堂阶段。
- 课堂失败、成功重试、旧报告 superseded 的完整旅程。
- 词库扫描启动、进度、完成和重复触发的幂等旅程。

## 验收门

发布前需证明：核心状态和工具调用覆盖率达到项目门槛；上述 E2E 全绿；审计日志可通过 `analysis_id` 回放；失败任务重启后可恢复；所有 Agent 建议均需要人类授权才能改变词库。
