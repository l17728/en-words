# 跟读失败诊断与人工授权修复：最终测试评审

## 结论

设计文档和评审记录已经形成闭环，但**测试发布门尚未关闭**。当前仓库还没有发现 `teacher_failure_analyses`、`word_pronunciation_variants`、分析 API 或对应前端实现，因此不能宣称该特性已开发、验证或上线。

## 当前已闭环

- 失败分析与人工授权的角色边界已明确。
- `analysis_key` 幂等、任务状态、CAS 授权、变体冲突、批量扫描 job_id、隐私开关和审计要求已写入定稿记录。
- 单测、集成测试和 Playwright 必须覆盖的关键旅程已在测试评审中列出。

## 发布前阻塞项

1. 建立 SQLite 持久化模型、迁移和唯一约束。
2. 实现失败事件入队、任务恢复、Agent 超时降级和成功重试 superseded。
3. 实现学生查询、管理员列表、评价/实施、词库扫描 API，并完成权限负向检查。
4. 注册受控工具，保证 Agent 不能修改原词、发布词库或越权批量写入。
5. 实现管理员报告 UI、评价按钮、执行状态和失败重试。
6. 增加单测、集成测试及双浏览器 Playwright E2E：评价实施、拒绝、重复点击、迟到结果、越权、重启恢复和扫描幂等。
7. 进行全量回归、审计日志核验和一次人工验收。

## 通过标准

只有在上述实现存在、测试全绿、审计可按 `analysis_id` 回放、重复操作无副作用、Agent 不可用时课堂仍可继续，并完成管理员人工验收后，才可将该特性标记为上线。
