# 跟读失败诊断与人工授权修复：架构评审

## 结论

方向正确：课堂快路径与异步诊断分离，教师 Agent 只提出建议，管理员授权后才允许写入朗读变体。进入开发前需要补齐以下约束。

## 必须修改

1. **幂等键必须落库唯一**：`analysis_key` 不能只写在文档中。应由 `lesson_id + entry_id + normalized_transcript + failure_type + matcher_version` 组成，并建立唯一索引；同一失败并发入队只能产生一条记录。
2. **人工授权必须绑定**：管理员评价后生成一次性授权收据，包含 `analysis_id`、`operator_id`、允许的工具名、参数摘要、过期时间和 nonce。教师 Agent 只能使用该收据调用工具，不能凭普通 Agent 身份写库。
3. **工具执行要原子化**：评价、工具调用、变体写入和审计应有明确状态机：`pending → approved → applying → applied/failed`。重复点击返回原结果，禁止重复写入。
4. **失败任务需要持久化队列语义**：补充 `attempt_count`、`next_retry_at`、`last_error`、`locked_until`。模型超时、进程重启、重复消费都必须可恢复；课堂请求线程不能等待队列完成。
5. **隐私和留存缺失**：`transcript` 属于用户语音内容。报告接口必须按学生本人/管理员隔离，日志不得默认重复打印全文；明确保留期限、删除策略和 `ENWORDS_LOG_ASR_TEXT` 的诊断开关关系。
6. **变体冲突规则缺失**：增加变体前要检查同词条重复、与原词相同、与已禁用变体冲突及跨词条误归属；`remove` 只能禁用，不物理删除审计记录。
7. **学生报告权限未定义**：学生只能看到自己的报告；管理员可按学生、词库、状态分页查询；老师 Agent 只能读取必要字段。API 必须明确 401/403/404/409/422 语义。
8. **扫描任务接口不完整**：`pronunciation-scan` 需要返回 `job_id`，并提供状态、取消、重试和进度查询；大词库不能同步执行，也不能重复启动同一词库的活动任务。

## 建议修改

- 记录 `agent_model`、`prompt_version`、`matcher_version`，保证报告可复现。
- 为确定性规则和 Agent 建议区分 `source`，规则命中不必调用模型。
- UI 在 `applying` 状态禁用按钮，并显示最终工具调用结果和审计编号。
- “批量实施”暂不开放；若后续开放，必须先生成变更清单并二次确认。
- 增加负向用例：Agent 无授权写入被拒、跨学生查询被拒、迟到分析不能改变已完成课堂、失败重试不生成重复变体。

## 评审结论

补齐上述 8 项必须修改后可进入实现；当前文档可作为方向性规格，尚不能作为上线 SDD。
